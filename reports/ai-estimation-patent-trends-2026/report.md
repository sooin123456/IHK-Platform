# AI 적산의 미래 데이터와 특허 방향

기준일: 2026-08-14  
대상: Lukas QTO / 한길시스템의 제품·데이터·특허 전략  
주의: 아래 특허 분석은 공개 공보 기반 기술·사업 리서치이며 법률 의견이나 FTO(Freedom to Operate) 결과가 아니다.

## Executive Summary

1. **해외 선두 제품의 경쟁력은 AI 모델 하나가 아니라 데이터 루프에 있다.** 도면·BIM 추출, 사람 검토, 품목·조립식, 단가, 개정, 탄소, 실제 결과를 같은 프로젝트 식별자로 연결한다.
2. **건설 AI 시장은 기대보다 운영 성숙도가 낮다.** RICS 2025 조사에서 45%는 AI 미사용, 전 프로젝트 규모로 확장한 조직은 1%였다. 인력·역량 46%, 시스템 통합 37%, 데이터 품질 30%가 주요 장벽이다.
3. **2D 도면 자동 인식→물량→비용·내역서의 직선형 자동화는 특허가 밀집했다.** Autodesk, BuildingEstimates.com, Togal, Matrak 계열의 등록 특허와 Fobecon의 2026 PCT 공개가 겹친다.
4. **Lukas가 먼저 가져야 할 자산은 ‘정답 숫자’보다 정답이 확정되는 과정이다.** 원본 SHA, 요소 ID, 개정, 계산 규칙, AI 제안, 사람 수정·승인, 계약·정산 결과를 함께 저장해야 한다.
5. **권장 제품 경로는 검증 가능한 AI다.** 공식 API의 결정론적 추출을 기반으로 AI는 분류·매핑·누락·이상치·유사 항목을 제안하고, 최종 물량과 비용은 버전 고정 규칙과 사람 승인을 거친다.

## 1. 해외 시장 신호

[RICS AI in Construction Report 2025](https://www.rics.org/news-insights/artificial-intelligence-in-construction-report)는 2,200명 이상의 글로벌 응답을 바탕으로 다음 간극을 보여준다.

| 지표 | 비율 | Lukas 제품 의미 |
|---|---:|---|
| AI가 더 큰 가치를 제공할 것이라 본 QS·건설 전문가 | 약 67% | 수요 기대는 높다 |
| AI 미사용 조직 | 45% | 다수는 도입 전·실험 단계다 |
| 인력·역량 부족 | 46% | 전문가 승인 UX와 교육이 제품 일부여야 한다 |
| 시스템 통합 | 37% | Revit·Excel·원가 DB 연결이 핵심이다 |
| 데이터 품질 | 30% | 원본·수정·정답 provenance가 경쟁력이다 |
| 전 프로젝트에 AI를 확장한 조직 | 1% | 완전 자동 주장보다 좁고 검증된 성공이 중요하다 |

판단: 현재 구매자가 원하는 것은 ‘사람을 없애는 AI’보다 **반복 검토 시간을 줄이면서 오류 책임과 근거를 남기는 도구**에 가깝다.

### 2.1 산군 같은 국내 건설 데이터 스타트업과의 비교

산군은 현재 Lukas의 직접적인 적산 경쟁사라기보다 **건설 시장·조달 인텔리전스 플랫폼**에 가깝다. 기업·현장·공사·입찰·수주·평판·뉴스·스마트건설 DB와 API를 제공하고, 영업 타기팅·협력사 탐색·위험관리·입찰 분석을 해결한다. 반면 Lukas는 Revit·IFC·QTO·내역을 연결해 프로젝트 내부의 물량과 계산 근거를 확정하는 방향이다.

| 구분 | 산군 | Lukas QTO |
|---|---|---|
| 핵심 질문 | 어디에 공사가 있고 누구와 거래할 것인가 | 이 프로젝트에 무엇이 얼마나 들어가며 근거는 무엇인가 |
| 데이터 방향 | 시장 외부→기업 사용자 | 모델·도면 내부→프로젝트 사용자 |
| 핵심 데이터 | 기업, 현장, 공사, 입찰, 수주, 신용·평판, 뉴스 | RVT/IFC, 요소 ID, 속성, 물량, 규칙, 내역, 개정, 승인 |
| 주요 고객 | 영업, 구매·외주, 자재·장비사, 공공기관, 사업주 | 적산사, QS, BIM 담당자, 설계사, 견적·원가팀 |
| 제품 형태 | 웹 구독, 데이터 다운로드, B2B SaaS, API | Revit 추출기 + 웹 검토·검산·공유 플랫폼 |
| 데이터 해자 | 광범위한 외부 DB와 갱신 빈도, 검색·필터, 사용자 네트워크 | 프로젝트 원본과 물량의 요소단위 연결, 계산·승인·개정 이력 |
| 현재 우위 | 접근성, 유통, 시장 범위, 무료 진입, API | 깊은 물량 근거와 재현성, 모델-내역 연결 가능성 |
| 현재 약점 | 모델 내부 물량의 직접 산출·검증이 핵심은 아님 | 설치·추출 진입장벽, 적은 누적 프로젝트, 웹 협업·유통 미성숙 |

가장 큰 사업 기회는 산군을 복제하는 것이 아니라 두 층을 연결하는 것이다. Lukas가 ‘어떤 자재·공종이 얼마나 필요한지’를 증명하고, 산군형 데이터가 ‘누가 공급·시공할 수 있고 시장·신용·입찰 상황이 어떤지’를 제공하면 **물량→내역→조달·협력사→실적·정산**의 흐름이 완성된다.

따라서 Lukas의 초기 전략은 무료 Properties/QTO 추출과 웹 결과 공유로 진입장벽을 낮추고, 유료 기능을 프로젝트 개정관리·내역 매핑·승인·검산·감사보고서에 두는 것이 적절하다. 장기적으로는 고객 동의가 있는 비식별 집계만 사용해 공종별 단위물량·오차·변경 패턴 벤치마크를 구축하고, 외부 기업·입찰·가격 데이터는 직접 대규모 수집하기보다 API·제휴로 연결하는 편이 효율적이다.

### 특허가 밀집한 기능

- 2D 도면의 벽·방·문·기호·영역 자동 분할
- 스케일 인식 후 길이·면적·개수 자동 계산
- 도면 객체에서 자재·노무·BOM·bid까지 한 번에 생성
- 자동 폴리곤과 사용자의 대화형 수정
- BIM/CAD 객체 ID와 takeoff 객체·원가 분류의 지속 연결
- 확률맵에서 특징 좌표와 고유 ID를 생성하는 방식
- 국내 도면·시방 예외·근거선·산출내역서를 함께 처리하는 방식

### 상대적으로 차별화 가능성이 있는 방향

‘특허가 없다’는 뜻은 아니며 별도 선행기술 조사가 필요하다.

- Revit 공식 API 추출과 요소 ID·파일 SHA를 결합한 감사 가능한 원장
- RVT·IFC·QTO·내역·정산의 교차 검산 및 동일 개정 증명
- 계산 규칙의 불변 버전과 사람 승인 체인
- AI 제안과 최종 결정론적 계산을 분리한 구조
- 설계 개정 전후의 증거 기반 재검증 그래프
- 실제 정산·소비량·생산성까지 되돌아오는 학습 데이터 구조

## 4. 향후 3~5년 기술 동향

### 4.1 단일 도면 인식에서 프로젝트 지식 그래프로

미래 적산 AI는 객체 하나를 인식하는 수준에서 벗어나 설계 개정, WBS, 일정, 계약 변경, 실제 정산을 그래프로 연결한다. [CN120409855A](https://patents.google.com/patent/CN120409855A/en)는 다중 버전 BIM 구성요소 그래프와 원가 예측을, [CN121391329A](https://patents.google.com/patent/CN121391329A/en)는 BIM 개정 차이와 유사 항목·생산성·변경비용을 다룬다.

### 4.2 견적값에서 실제 결과 학습으로

[CN121660372A](https://patents.google.com/patent/CN121660372A/en)는 이론 물량과 실제 정산 물량의 편차를 학습하는 방향을 보여준다. 앞으로의 데이터 우위는 ‘몇 m³로 계산했는가’뿐 아니라 ‘왜 정산에서 달라졌는가’를 보유하는 데서 생긴다.

### 4.3 원가와 탄소의 통합

[ICMS 3](https://icms-coalition.org/the-standard/)는 생애주기 비용과 탄소를 공통 분류 체계로 연결한다. Autodesk Takeoff도 분류·단가·embodied carbon을 데이터 출력 범위로 확장하고 있다. 물량 데이터 모델에 원가와 탄소의 버전·지역·시점을 포함해야 한다.

### 4.4 완전 자동보다 불확실성 표시와 사람 승인

AI가 낸 숫자에는 신뢰도, 누락 사유, 적용 규칙, 근거 위치가 함께 있어야 한다. Autodesk의 심벌 검출도 사용자가 인스턴스를 확인한 뒤 저장한다. 적산은 금액 책임이 크므로 human-in-the-loop가 임시 단계가 아니라 제품 구조로 남을 가능성이 높다.

## 6. 권장 로드맵

### 0~6개월 — 데이터 기반

- Revit 추출값과 element ID, 파일 SHA, Revit build, scope를 고정한다.
- QTO·IFC·내역·개정·승인·보고서를 한 project/run ID로 묶는다.
- 수량의 `원본값 / 보정값 / 최종값 / 근거 / 규칙버전`을 분리한다.
- 사람 수정 사유를 구조화된 선택값과 메모로 저장한다.
- ICMS/자체 공종·품목 코드의 버전 계약을 만든다.

### 6~12개월 — 검토형 AI

- 요소→공종·품목 매핑 추천
- 누락·중복·단위 오류·비정상 수량 탐지
- 과거 승인 결과 기반 유사 항목·공식 추천
- 개정 전후 물량·금액 차이 요약
- 모든 AI 결과에 confidence, model version, evidence, 승인 결과 저장

### 12~24개월 — 예측형 AI

- 정산 대비 견적 오차 범위
- 지역·시점·유형별 단가·생산성 보정
- 설계 변경의 비용·공기 영향 예측
- 비용·탄소 대안 비교

조건: 대표성이 있는 승인 데이터와 프로젝트 단위 holdout 검증셋을 먼저 확보해야 한다. 학습 데이터와 평가 데이터가 같은 프로젝트의 개정본을 공유하면 성능이 과대평가된다.

## 7. 제품·특허 실행 제안

1. **2D 도면 완전 자동 적산을 첫 AI 목표로 두지 않는다.** 특허와 학습데이터 부담이 가장 크다.
2. **Lukas QTO의 강점은 증거 기반 추출·검산 플랫폼으로 고정한다.** ‘AI가 계산했다’가 아니라 ‘어떤 원본·규칙·승인으로 이 숫자가 확정됐는가’를 판다.
3. **첫 AI는 추천형으로 제한한다.** 분류, 매핑, 이상치, 개정 차이 설명부터 시작한다.
4. **특허 출원 후보는 좁고 구체적으로 설계한다.** 증거 바인딩, 개정 그래프, 승인 이벤트, 다중 원본 교차검산, 결정론적 계산과 AI 제안 분리 구조를 청구항 후보로 검토한다.
5. **FTO는 기능 단위로 한다.** 2D segmentation, 폴리곤 수정, 객체-ID 매핑, BOM/견적 생성, 시방 예외 처리를 각각 청구항 차트로 비교한다.

## 결론

Lukas의 최선의 방향은 해외 2D 자동 takeoff를 그대로 복제하는 것이 아니다. **Revit에서 제대로 추출하고, 원본·규칙·사람·개정·정산을 연결해 검증 가능한 학습 데이터를 독점하는 것**이 먼저다. 이 기반 위에서 AI를 분류·매핑·검토 보조로 붙이면 실무 도입 장벽을 낮추면서 장기적으로 예측 적산까지 확장할 수 있다.
