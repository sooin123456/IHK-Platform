# Lukas QTO 추출 우선 제품 기획

기준일: 2026-08-13  
제품 책임자: Lukas  
현재 단계: 기획 확정 전 — 추가 기능 구현 금지

## 1. 이번 제품의 한 문장 목표

현장 사용자가 웹에서 파일을 받아 Revit 2025에 설치하고, 버튼 한 번으로
**요소별 이름·부피·길이·높이와 그 값의 Revit 출처를 CSV로 추출**한다.

첫 제품은 적산 판단기가 아니다. 추출값을 먼저 신뢰할 수 있어야 이후의
공제·할증·내역 매핑·검산이 의미가 있다.

## 2. 해결할 현장 문제

현재 실무자는 모델이 커질수록 다음 작업을 반복한다.

- 요소를 하나씩 선택해 Properties를 확인한다.
- 같은 종류의 요소라도 어떤 파라미터에서 값이 나왔는지 다시 확인한다.
- 값이 없는 것과 실제 0인 것을 구분하기 어렵다.
- 추출 프로그램의 합계가 맞지 않으면 원래 Revit 요소로 돌아가기 어렵다.
- 프로그램 설치가 실패하면 무엇이 잘못됐는지 설명할 증거가 없다.

Lukas QTO의 1차 가치는 계산식을 많이 넣는 것이 아니라, 이 반복 확인을
짧고 역추적 가능하게 만드는 것이다.

## 3. 1차 사용자와 사용 상황

### 주 사용자

- Revit 모델에서 물량과 Properties를 확인하는 BIM·설계·견적 실무자
- 설치와 첫 검증을 도와줄 사내 BIM 담당자

### 첫 검증 상황

- Windows 11
- Revit 2025
- 실제 프로젝트 또는 민감정보가 제거된 작은 검증 모델
- 인터넷은 다운로드에만 사용하고 RVT는 외부로 전송하지 않음

## 4. 1차 제품 범위

### 반드시 제공

Revit 요소 하나당 CSV 한 행을 생성한다.

```text
element_id,category,family,type,element_name,level,
volume_state,volume_m3,volume_source_parameter,
length_state,length_m,length_source_parameter,
height_state,height_m,height_source_parameter
```

각 수량은 다음 상태 중 하나다.

- `COMPUTED`: Revit 내장 파라미터에서 유효한 양수값을 읽음
- `ZERO`: 실제 첫 유효값이 0임
- `MISSING`: 사용할 수 있는 원본값이 없음

모든 수치는 Revit 공식 API에서 읽고 m³ 또는 m로 변환한다. 요소 ID와 실제로
선택된 내장 파라미터명을 함께 남긴다.

### 이번에 제공하지 않음

- 모든 사용자 정의 Properties 덤프
- 재료·규격 자동 판단
- 공제·할증·손율·단위중량 계산
- 콘크리트·거푸집·철근 내역 자동 생성
- IFC 파일만 업로드해서 동일 결과를 계산하는 웹 기능
- AI 자동 매핑과 누락값 보정
- 계정·프로젝트 DB·협업 기능

기존 구조수량·검산 코드는 연구 자산으로 유지하되 1차 현장 리본과 설치 성공을
막지 않게 분리한다.

## 5. 목표 사용자 흐름

1. 사용자가 공개 웹페이지에서 지원 버전, 출력 열, 샘플 CSV를 확인한다.
2. Revit 2025용 검증 파일을 다운로드한다.
3. 설치 전 검사에서 Revit·필수 런타임·권한·실행 중인 Revit을 확인한다.
4. 설치 후 진단이 `.addin`, DLL, SHA-256, Assembly 경로를 자동 확인한다.
5. 사용자가 Revit을 열고 `Lukas QTO > Properties 추출`을 누른다.
6. 저장 위치를 고르면 `element-ledger.csv`와 검증 JSON이 생성된다.
7. 사용자가 임의 요소를 Revit에서 선택해 CSV의 Element ID와 값을 비교한다.
8. 문제가 있으면 로그·진단 JSON·CSV만 전달한다. RVT 원본 제출은 필수가 아니다.

### 성공 화면

실무자에게 필요한 마지막 메시지는 다음 네 항목뿐이다.

- 추출한 요소 수
- `COMPUTED / ZERO / MISSING` 수
- 저장된 CSV 경로
- 검증 JSON 경로

## 6. 제품 단계와 통과 기준

### G0 — 계약 고정

목표: 무엇을 추출하는지 더 이상 흔들리지 않게 한다.

완료 조건:

- 15열 CSV와 세 상태의 의미가 문서·코드·검증 스크립트에서 동일함
- Revit 2025 초기 릴리스에 없는 API를 제품 코드에서 사용하지 않음
- 음수·NaN·Infinity·중복 Element ID는 명시적 실패
- 누락을 0이나 다른 파라미터 값으로 조용히 대체하지 않음

### G1 — 비-Windows 자동 검증

목표: Windows를 켜기 전에 잡을 수 있는 오류를 모두 잡는다.

완료 조건:

- Core self-test 통과
- Revit 2017·2022~2026 조건부 소스 컴파일 통과
- `COMPUTED / ZERO / MISSING` 조합 테스트 통과
- 단위 변환, CSV 왕복, 위험 문자열, 중복 ID 테스트 통과
- 배치파일의 SDK 감지·애드인 단독 빌드·설치 경로 정적 검사 통과
- 공개 ZIP 내용·SHA-256·웹 표시값 일치

이 단계는 실제 Autodesk DLL이나 Revit 리본 로드를 증명하지 않는다.

### G2 — Windows 빌드 검증

목표: 실제 설치된 Autodesk DLL로 제품 DLL을 생성한다.

완료 조건:

- 실제 `RevitAPI.dll`, `RevitAPIUI.dll` 기준 오류 0
- production marker의 Revit 버전·TFM·API 경로·DLL SHA 일치
- Desktop/검산기와 무관하게 애드인 단독 빌드 가능
- 실패 시 설치 폴더를 변경하지 않음

### G3 — Revit 설치·리본 검증

목표: 깨끗한 환경에서 사용자가 버튼을 볼 수 있다.

완료 조건:

- `.addin`과 DLL 설치 성공
- Revit 재시작 후 `Lukas QTO` 탭 표시
- 애드인 관리자에서 활성 상태 확인
- 기존 THEKIE manifest 충돌 없음
- 재설치·제거·롤백 시험 성공

### G4 — 실제 모델 추출 검증

목표: 현장 사용자가 원하는 결과가 정확히 나온다.

완료 조건:

- CSV 행 수가 추출 대상 요소 수와 일치
- 서로 다른 카테고리의 표본 20개를 Revit Properties와 대조
- Element ID, 이름, 레벨, 부피, 길이, 높이, source parameter 일치
- `ZERO`와 `MISSING` 표본을 각각 확인
- 설명되지 않은 수치 차이 0건
- Revit 중단·CSV 부분 파일·기존 파일 덮어쓰기 0건

### G5 — 업데이트 호환 검증

목표: `Revit 2025`라는 큰 버전명만 보고 호환을 주장하지 않는다.

완료 조건:

- 검증 증거에 `VersionNumber`, `SubVersionNumber`, `VersionBuild` 기록
- 가능한 경우 Revit 2025 초기 계열과 최신 누적 업데이트 계열에서 각각 실행
- 업데이트별 요소 수·상태 수·표본 결과 비교
- 차이가 있으면 지원 범위 또는 알려진 제한으로 공개

### G6 — 공개 설치본 후보

목표: 소스 키트가 아니라 일반 실무자가 받을 설치 파일을 만든다.

완료 조건:

- G0~G5 증거가 동일 빌드 SHA와 연결됨
- 새 Windows PC에서 다운로드→설치→리본→추출 성공
- 악성코드 검사와 파일 무결성 확인
- 웹에 버전·지원 Revit 빌드·게시일·SHA-256·제거 방법 표시

G6 전까지 웹 파일은 반드시 `현장 검증용 소스 키트`로 표시한다.

## 7. Windows 없이 지금 할 수 있는 작업

다음 작업은 실제 Windows/Revit 승인과 분리해 먼저 완료할 수 있다.

1. **API 허용목록 검사**  
   1차 추출기가 사용하는 BuiltInParameter 목록을 고정하고 스텁이 실제 API보다
   더 많은 가짜 멤버를 제공하지 못하게 검사한다.

2. **상태 조합 테스트**  
   양수, 실제 0, 누락, 잘못된 수치, 길이만 존재, 높이만 존재를 각각 고정한다.

3. **단위·CSV 계약 테스트**  
   내부 feet 값을 m/m³로 변환하고 소수 정밀도·한글·쉼표·줄바꿈·Excel 위험
   문자열을 보존한다.

4. **설치 전후 진단 설계**  
   SDK 부재, Autodesk DLL 부재, 빌드 오류, `.addin` 부재, DLL 부재, 해시 불일치,
   Revit 실행 중을 서로 다른 오류코드와 쉬운 문장으로 구분한다.

5. **릴리스 ZIP 계약 검사**  
   필요한 파일만 포함하고 `bin/obj`, macOS 메타데이터, 오래된 DLL을 제외한다.

6. **웹 다운로드 종단간 검사**  
   사이트 표시 SHA, 실제 다운로드 SHA, ZIP 내부 실행 파일의 버전이 일치하는지
   자동 확인한다.

7. **현장 대조표 준비**  
   20개 표본의 Revit 화면값과 CSV 값을 기록할 빈 검증 양식을 미리 만든다.

## 8. Windows에서만 가능한 작업

- 실제 Autodesk Revit 2025 DLL을 참조한 production build
- `.addin` 로드와 리본 생성
- Revit 업데이트별 API·내장 파라미터 동작 확인
- 실제 RVT 요소의 Properties와 CSV 대조
- IFC 내보내기 모듈과 실제 파일 재개방
- 관리자 설치·제거·백신·권한·다른 애드인 충돌 확인

이 항목은 스텁이나 macOS 테스트로 PASS라고 표시할 수 없다.

## 10. 후속 제품 로드맵

### 2차 — 사용자가 요구한 Properties 확장

동일한 작은 RVT를 Lukas QTO와 기존 UCF 프로그램으로 각각 추출한다. 실제 출력
차이에서 현장 사용자가 요구한 필드만 추가한다. 모든 Properties 자동 덤프는 하지
않는다.

### 3차 — IFC·QTO 전달 패키지

원시 추출이 통과한 뒤 같은 Revit 문서 상태의 IFC, QTO, element ledger를 하나의
SHA-256 manifest로 묶는다.

### 4차 — 공종별 적산

콘크리트 → 거푸집 → 철근 순으로 승인된 계산 규칙을 별도 기능으로 연결한다.
원시 추출과 실제 내역 대조가 없는 공종은 PASS하지 않는다.

### 5차 — 검산과 개정 비교

추출 결과와 내역의 사람이 승인한 매핑, 수정 전후 리비전, 근거 보고서를 연결한다.

## 11. 에이전트 운영 계획

기획 승인 전에는 에이전트가 코드를 수정하지 않는다. 승인 뒤에도 동시에 최대
세 역할만 운용한다.

### 총괄

- 계약과 파일 경계 관리
- 작업 순서 승인
- 통합 테스트와 최종 GO/NO-GO 결정

### extraction-contract

- 허용 API 목록, 상태·단위·CSV 계약 테스트
- 편집 범위: extractor, compat, Revit stub/test

### release-field

- 설치·진단·ZIP·웹 다운로드 계약
- 편집 범위: deploy, field launcher, field guide, release tests

한 파일을 둘 이상의 역할이 동시에 수정하지 않는다. G1이 끝나기 전에 G2 이후를
완료라고 보고하지 않는다.

## 12. 지금의 결정 게이트

다음 구현 목표는 **G0와 G1만**이다. G0·G1을 완료한 뒤 Windows 담당자에게
하나의 새 키트를 전달한다. 현장 결과를 받기 전에는 Properties 종류, IFC,
공종별 계산식을 추가하지 않는다.
