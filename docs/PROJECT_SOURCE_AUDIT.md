# 꿈푸른유치원 제공 폴더 감사와 제품 방향

기준일: 2026-08-12. `/Users/h/Downloads`의 제공 폴더는 읽기 전용으로 검사했다. 이 문서는 파일 이름만 보고 정답본을 임의 선택하지 않기 위한 작업 기록이다.

## 1. 확인한 자료 구조

압축 내부를 제외한 바깥 폴더에는 의미 있는 파일 58개와 `.DS_Store` 1개가 있다. 주요 형식은 XLSX 11, XLS 6, PDF 9, MDB 6, RVT 5, DWG 4, BAK·ACCDB 각 3, EMS7 2개이며 IFC는 없다.

자료는 하나의 단순 BIM 납품본이 아니라 다음 계통이 섞인 프로젝트 묶음이다.

- EMS 내역: 0910, 0614, 0614_1, EMS7 XLSX와 EMS7 전용 프로젝트 파일 2개
- 건축·구조 수량: ZF, ZG, ZJ 계열의 Excel·전용 포맷·MDB. PDF 3개는 MDB 스키마 참고자료
- BIM: 본파일 후보 `240503.rvt`와 `.0001`, `.0004`, `.0005`, `.0006` 백업
- 도면·견적: DWG/DXF/BAK, 공급사 견적 PDF/XLSX
- 토목: `토목최종.zip` 안의 중첩 ESTX/EBKX 자료

## 3. 아직 자동으로 정답을 고를 수 없는 충돌

구조 수량 ZG와 ZJ는 핵심 합계가 다르다.

| 항목 | ZG | ZJ | 차이 |
|---|---:|---:|---:|
| 콘크리트 계열(막자갈 포함) | 409.221 m³ | 450.781 m³ | 41.560 m³ |
| 형틀 계열(필름·단열재·거푸집 포함) | 2,781.316 m² | 2,717.205 m² | -64.111 m² |
| 철근 | 30,886.375 kg | 31,908.817 kg | 1,022.442 kg |

이 수치는 각 워크북이 보고한 복합 버킷 합계이며 아직 같은 항목끼리 정규화한 값이 아니다. 차이는 어느 쪽이 틀렸다는 뜻이 아니다. 범위, 공제, 이음·정착, 부재 포함 기준, 개정 시점이 다를 수 있다. 플랫폼은 먼저 두 근거를 같은 스키마로 가져와 부재·층·재료별 차이를 보여주고, 사람의 승인 전에는 어느 값을 정답으로 승격하지 않아야 한다.

토목 ZIP도 단일 파일이 아니다. 바깥 컨테이너의 22개 항목 안에 ESTX/EBKX 계열이 각각 64개 항목을 가지며, 같은 이름 42개가 서로 다르다. 전용 어댑터 없이 최신 이름 하나만 꺼내는 방식은 위험하다.

RVT는 Revit 2017 계열 후보라 현재 macOS에서 실제 요소를 열어 검증할 수 없다. 본파일과 백업 선택, CAD 링크 누락, 내보낸 QTO와 ZG/ZJ 대조는 [Windows/Revit 검증 절차](WINDOWS_REVIT_VERIFICATION.md)가 끝나야 확정된다.

## 4. 이 자료에서 도출되는 서비스

이 자료에서 세울 수 있는 `[제품 가설]`은 단순 “BIM 물량 뽑기”보다 **공사 원가 근거 사전검토 플랫폼**에 집중하는 것이다.

1. `Source Registry`: 파일 SHA, 범위, 개정, 원본·파생 관계를 고정하고 잘못된 조합을 실행 전에 차단
2. `Adapters`: Revit, EMS XLSX, ZF/ZG/ZJ, 토목 컨테이너를 원본 행·셀·요소ID를 잃지 않고 공통 스키마로 변환
3. `Deterministic Rules`: 복합 버킷을 세부항목·할증 기준으로 먼저 분해하고 승인된 계산식·규칙 묶음을 버전 관리하며 누락값을 추정하지 않음
4. `Reconciliation`: BIM↔내역, ZG↔ZJ, 산출근거↔집계표의 차이를 부재·층·단위별로 설명
5. `Evidence Report`: PASS/FAIL/REVIEW와 함께 파일 SHA, 원본 셀, Revit 요소ID를 역추적. 승인자·시각·서명은 향후 계약에 추가

`[시장 가설]` 가장 큰 문제는 계산식 수보다 **어떤 범위·개정·근거로 계산했는지 증명하지 못하는 것**이며, 혼합 방지와 역추적 가능한 검산 체인이 설계사·원가계산용역사·감리의 구매 이유가 될 수 있다. 이 가설은 인터뷰와 유료 파일럿으로 검증해야 한다.

## 5. 구현 순서

| 단계 | 기능 | 완료 조건 |
|---|---|---|
| P0 | SHA·범위·개정·수식 원본성 게이트 | 엔진·self-test·샘플 CLI 완료. 실제 현장 QTO·매핑·매니페스트 적용은 P1에서 검증 |
| P1 | 실제 Revit 2017 QTO | Windows에서 본파일 승인, CSV 내보내기, 요소ID 역추적 |
| P2 | ZG/ZJ 구조수량 어댑터 | 콘크리트 계열·형틀 계열·철근 버킷을 세부항목·할증 기준으로 분해·정규화하고 버전된 규칙 묶음과 원본 셀 증거로 충돌 보고 |
| P3 | 현장 파일 파일럿 | 적산 전문가가 차이 10건 이상을 검토하고 오판 기록 |
| P4 | L2 단가·품셈 | 데이터 저장·가공·SaaS·재배포 권리의 서면 승인 후에만 착수 |

다음 구현 단위는 세 버킷을 한 번에 일반화하는 엔진이 아니다. 먼저 ZG와 ZJ의 공통 집계 키를 정의하고 세부항목과 할증·공제 기준을 분해한 뒤, 항목별 명시적 식·단위·근거 셀을 가진 버전된 규칙 묶음으로 구현해야 한다.
