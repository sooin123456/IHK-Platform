# 1HK Drawing Workspace 제품·개발 계획

## 1. 제품 결정

1HK Platform의 도면 기능을 단순 뷰어·검토 화면에서 **브라우저 기반 도면 작업실**로 확장한다.

목표 경험은 다음과 같다.

> PDF·IFC·향후 CAD 도면을 한 프로젝트에 모으고, 브라우저에서 직접 작성·측정·주석·분류하며, 여러 참여자가 같은 도면을 검토·승인하고, 그 결과를 물량·내역·자재 데이터와 연결한다.

Rayon의 제품 범위와 작업 방식을 참고하되 이름, 화면, 아이콘, 샘플, 문구를 복제하지 않는다. 1HK의 차별점은 도면 편집 자체가 아니라 **도면 객체 → 원본 근거 → 물량 → 금액 → 검토 → 승인**을 한 계보로 연결하는 것이다.

## 2. 현재 구현과 목표의 차이

| 영역 | 현재 1HK | 목표 |
|---|---|---|
| PDF | 보기, 확대·이동, 영역 근거, 이슈 연결 | 페이지 편집, 벡터 오버레이, 측정, 주석, 레이어, 템플릿 |
| IFC | 3D 보기, 요소 선택, 속성, GlobalId 근거 | 2D·3D 분할 보기, 객체 연결, 개정 비교, 도면 객체와 상호 선택 |
| 협업 | 이슈, 댓글, 담당자, 상태, 승인, 알림 | 실시간 커서·선택, 공동 편집, 소프트 잠금, 변경 이력, 멘션 |
| 도면 작성 | 없음 | 선·폴리라인·사각형·원·호·텍스트·치수·벽·개구부·블록 |
| 구조화 | 파일·이슈 중심 | 페이지·캔버스·레이어·스타일·블록·표·사용자 속성 |
| 적산 연결 | 별도 수량·검산 흐름 | 도면 객체와 수량·단가·내역 행을 양방향 연결 |

## 4. 핵심 제품 원칙

1. IFC·PDF 원본 바이트는 수정하지 않는다. 모든 편집은 별도 벡터 계층과 개정으로 남긴다.
2. 저장된 객체는 프로젝트, 원본 파일, 페이지 또는 IFC 요소에 역추적 가능해야 한다.
3. 자동 저장과 실시간 동기화가 실패해도 사용자의 로컬 작업을 잃지 않는다.
4. 확정·승인된 버전은 직접 덮어쓰지 않고 새 개정을 만든다.
5. 브라우저 계산은 미리보기이며 물량·금액 확정은 버전이 고정된 결정론적 규칙으로 수행한다.
6. AI는 최종 단계에서 추천 기능으로만 추가하며 자동 승인이나 확정 계산을 맡기지 않는다.

## 5. 기술 구조

### 렌더링

- 대량 객체의 이동·확대·선택은 Canvas/WebGL 계층에서 처리한다.
- 텍스트 입력, 접근성, 컨텍스트 메뉴는 DOM 오버레이로 처리한다.
- PDF.js와 현재 IFC WebGL 뷰어는 원본 근거 렌더러로 재사용한다.
- 편집 도형은 공통 월드 좌표를 사용하고 화면 좌표와 분리한다.

### 데이터 모델

- `drawing_documents`: 프로젝트 내 편집 문서
- `drawing_pages`: 페이지·시트
- `drawing_canvases`: 모델/종이 공간 및 배경 원본
- `drawing_layers`: 순서, 표시, 잠금
- `drawing_objects`: 선, 경로, 도형, 텍스트, 치수, 벽, 개구부
- `drawing_styles`: 선, 채움, 글자 스타일
- `drawing_blocks`, `drawing_block_instances`: 재사용 도형
- `drawing_tables`: 공간·문·마감·물량 스케줄
- `drawing_property_schemas`, `drawing_property_values`: 사용자 속성
- `drawing_operations`: 추가형 변경 이벤트
- `drawing_snapshots`: 빠른 재개를 위한 주기적 스냅샷
- 기존 이슈·댓글·anchor·승인·알림 테이블은 그대로 연결

각 객체는 `version`, `created_by`, `updated_by`, `source_file_id`, `source_anchor`, `quantity_reference`를 가질 수 있다.

### 동시 편집

- Supabase Realtime Presence: 사용자 커서, 선택, 현재 페이지
- Postgres Changes: 확정된 객체 변경·댓글·상태
- 객체별 버전 기반 낙관적 동시성 제어
- 짧은 소프트 잠금으로 동일 객체 동시 편집 충돌을 안내
- 네트워크 단절 시 로컬 outbox에 저장 후 재연결 때 재전송
- 실행 취소는 사용자 작업 단위 operation을 역적용하되 다른 사용자의 작업은 삭제하지 않음

### 권한

- Viewer: 보기
- Commenter: 댓글·이슈
- Editor: 도형·레이어·속성 편집
- Reviewer: 검토 결정
- Approver: 최종 승인
- Admin: 구성원·공유·보존 정책

모든 권한은 화면뿐 아니라 Supabase RLS와 서버 action에서 재검증한다.

## 6. 구현 로드맵

### P0 — 편집기 기반

- 새 Drawing Workspace route와 전체 화면 shell
- PDF 배경 또는 빈 캔버스 생성
- 월드 좌표, 확대·이동, 그리드, 선택 시스템
- 객체·레이어·operation 최소 DB와 RLS
- 자동 저장, 다시 열기, 오류 복구

### P1 — 기본 2D 작성

- 선, 폴리라인, 사각형, 원, 텍스트, 치수
- 선택, 다중 선택, 이동, 복사, 삭제
- 실행 취소·다시 실행
- 단축키와 명령 검색
- 오른쪽 속성 검사기

### P2 — 문서 구조와 재사용

- 페이지, 캔버스, 레이어

### P3 — 실시간 협업

- 실시간 커서·선택·접속자
- 공동 편집과 충돌 안내

- 변경 이력, 활동 피드, 복원

### P4 — 건축 의미 객체

- 벽, 개구부, 공간, 영역, 축, 치수

- 공간·문·마감 스케줄

### P5 — PDF·IFC 통합

- `2D | 3D | 분할` 모드
- PDF 도형 ↔ IFC GlobalId 상호 연결·포커스
- 개정 전후 오버레이와 변경 표시
- 기존 anchor 재연결 검토 흐름 통합

### P6 — 물량·내역 연결

- 벽·영역·IFC 요소를 수량 행에 연결

- 내역·단가·공종 매핑
- 개정에 따른 수량·금액 변화 비교

### P7 — 제품화

- 회사 템플릿·라이브러리
- 데스크톱/태블릿 적응형 UI
- 대형 도면 성능 최적화
- 감사 로그·보존·백업·복구
- 현장 사용자 검증, 요금제, 조직 관리

AI 기반 도면 인식·분류·누락 추천은 P7 이후에 별도 단계로 둔다.

## 7. 첫 개발 단위의 완료 조건

P0+P1 첫 수직 기능은 다음을 모두 만족해야 한다.

1. 프로젝트에서 빈 도면 또는 PDF 배경 도면을 연다.
2. 확대·이동 후 선, 폴리라인, 사각형, 원, 텍스트, 치수를 작성한다.
3. 객체를 선택·이동·복사·삭제하고 실행 취소·다시 실행한다.
4. 두 개 이상의 레이어를 만들고 표시·잠금을 바꾼다.
5. 검사기에서 객체 이름, 레이어, 색, 선 굵기, 채움, 텍스트를 바꾼다.
6. 새로고침·재로그인 후 동일한 상태가 복원된다.
7. 댓글 또는 기존 이슈를 객체에 연결한다.
8. 두 브라우저에서 상대방 커서와 객체 생성·이동이 보인다.
9. PDF·IFC 원본 파일의 SHA-256은 작업 전후 동일하다.
10. Viewer는 편집할 수 없고 Editor만 객체를 변경할 수 있다.

## 8. 품질·출시 게이트

- 일반 도면 10,000개 객체에서 데스크톱 조작 60fps 목표
- 대표 도면의 첫 사용 가능 화면 2.5초 이내 목표
- 공동 편집 반영 지연 p95 500ms 이내 목표
- 네트워크 단절·재연결 후 유실 0건
- 조직 간 프로젝트·도면·댓글 접근 RLS 반례 통과
- 승인된 개정에 대한 직접 update/delete 차단
- 실제 사용자 3명이 `도면 열기 → 작성 → 댓글 → 수정 → 승인 → 내보내기` 수행
- 기존 IFC/PDF 검토, 수량, 승인, Revit 다운로드 흐름 회귀 없음

## 9. 1HK의 차별점

Rayon과 유사한 편집 경험은 진입점일 뿐이다. 1HK의 제품 방어력은 다음 연결에서 만든다.

`원본 도면/RVT/IFC → 도면 객체 → 검토 이슈 → 승인 → 물량 → 내역·금액 → 자재·발주·입고 → 탄소 근거`

도면에 그린 선과 영역이 단순 그래픽이 아니라 실제 요소, 계산식, 변경 사유, 담당자, 승인 기록을 가진 업무 데이터가 되도록 설계한다.
