# 구조 수량 산출 계약 — 꿈푸른유치원 ZG/ZJ

이 계약은 제공된 꿈푸른유치원 구조수량 파일의 **보존·추적·검산** 범위만 정의한다.
표준품셈, 시장단가, 설계 변경의 정당성 또는 다른 공종의 수량을 추정하지 않는다.

## 1. 범위와 소스 역할

같은 공사명이라도 ZG와 ZJ는 서로 다른 구조수량 산출 세트다. 한 세트의 총량을 다른 세트의 부족분으로 자동 보정하거나 합산하면 안 된다.

| 세트 | 원시 ledger | 공식 anchor | 실행/견적 연결 | 역할 |
|---|---|---|---|---|
| ZG240507 | `ZG240507_04A(산출근거_모델).xlsx` | `ZG240507_02(동별층별재료별).xlsx`, `ZG240507_03(재료별규격별).xlsx` | `ZG240507_01(실행집계).xlsx` | `04A`는 부재별 signed ledger, `02/03`은 공식 집계 anchor, `01`은 실행 품목·할증 연결이다. |
| ZJ240507 | `ZJ240507_02(산출근거).xls` | `ZJ240507_01(실행집계).xls`의 `동별 집계`, `동별 규격별 집계` | 같은 파일의 `실행집계` 시트 | 레거시 파일명은 다르지만 역할은 같다. `ZJ 02`는 ledger, `ZJ 01`의 집계 시트는 anchor, `실행집계`는 실행 품목 연결이다. |

ZG의 `04(산출근거)`와 `04A`는 산출식·결과가 같은 인쇄/모델 표현이다. 자동 입력에는 도형·부호 열이 있는 `04A`를 쓴다. `04A`의 산출식 열은 사람이 읽는 식 문자열이고, Excel 재계산식이 아니다. 반면 ZG `02/03`의 소계는 실제 Excel `SUM`, `SUMIF`, `TRUNC` 수식으로 저장되어 있다.

## 2. 공식 anchor

### ZG240507

공식 결과는 모두 “할증후 수량”이다.

| 버킷 | 공식 셀 | 세부 합계 | 공식 총량 |
|---|---|---|---:|
| 콘크리트 계열 | `ZG 02!동별 층별 재료별 집계!C4`, `ZG 03!재료별 규격별 집계!E8` | 막자갈 48.248 + 25-180-8 16.401 + 25-270-15 344.572 m³ | **409.221 m³** |
| 형틀·부대재료 계열 | `ZG 02!...!G4`, `ZG 03!...!E18` | 317.563 + 351.366 + 55.625 + 348.344 + 1,292.697 + 51.211 + 364.510 m² | **2,781.316 m²** |
| 철근 계열 | `ZG 02!...!O4`, `ZG 03!...!E25` | H10 7,037.439 + H13 11,421.371 + H16 10,945.209 + H19 1,482.356 kg | **30,886.375 kg** |

`ZG 02!C4`는 `SUM(D4:F4)`, `G4`는 `SUM(H4:N4)`, `O4`는 `SUM(P4:S4)`이다. 층별 총량은 FT/01/P1 순서로 콘크리트 235.374/161.316/12.531 m³, 형틀·부대 747.940/1,869.489/163.887 m², 철근 10,715.613/19,412.617/758.145 kg다.

### ZJ240507

공식 결과도 “할증후 수량”이다. `ZJ 01!동별 집계!D3:E3:F3`과 `D6:E6:F6`은 같은 총량을 보이며, 규격별 소계는 `동별 규격별 집계!C7/C17/C24`에 있다.

| 버킷 | 세부 합계 | 공식 총량 |
|---|---|---:|
| 콘크리트 계열 | 막자갈 48.717 + 25-180-8 41.376 + 25-270-15 360.688 m³ | **450.781 m³** |
| 형틀·부대재료 계열 | 319.360 + 319.360 + 34.650 + 347.670 + 1,280.958 + 96.477 + 318.730 m² | **2,717.205 m²** |
| 철근 계열 | H10 7,091.257 + H13 11,090.443 + H16 12,227.231 + H19 1,499.886 kg | **31,908.817 kg** |

ZJ의 `어린이집 층별 부재별` 시트에는 층면적이 0인 행의 `#DIV/0!` 비율식이 있다. 이 비율은 수량 공식 anchor가 아니며 `NOT_EVALUATED`다. 동일 시트의 부재별 수량은 provenance 용도만 갖는다.

## 3. 버킷 정의

“형틀”이라는 표시는 두 버킷을 섞어 표현한다. 자동화는 아래를 분리해 보관·표시한다.

| 버킷 | 포함 규격 | 출력 단위 | 주의 |
|---|---|---|---|
| `pure_formwork` | 합판(보측면), 합판(슬라브), 내부옹벽/기둥, 기초 | m² | 실제 거푸집·형틀 수량이다. |
| `formwork_accessories` | 0.03*2 PE필름, 비드 T125, PF T140 | m² | 형틀과 같은 집계 그룹에 있지만 거푸집 자체가 아니다. |
| `formwork_family` | 위 두 버킷의 합 | m² | 원본 공식 anchor의 2,781.316(ZG) 또는 2,717.205(ZJ)과만 비교한다. |
| `concrete_family` | 막자갈깔기, 25-180-8, 25-270-15 | m³ | 막자갈은 구조 콘크리트 강도가 아니지만 원본 콘크리트 집계에 포함된다. |
| `rebar_family` | H10, H13, H16, H19 | kg | ledger의 길이(m)와 공식 anchor의 질량(kg)을 혼동하지 않는다. |

## 4. Canonical signed-row schema

ledger에서 한 행도 삭제하거나 절댓값으로 바꾸지 않는다. 최소 저장 스키마는 아래와 같다.

| 열 | 의미 |
|---|---|
| `source_sha256` | 원본 파일 바이트 SHA-256 |
| `source_ref` | 파일 역할·시트·행. 예: `ZG04A/01/141` |
| `level` | FT, B1, 01, P1 등 원본 층 |
| `member_type` | 보, 슬라브, 옹벽, 기초, 파라펫 등 원본 부재 종류 |
| `member_code` | 원본 부호/유형. 없으면 빈 값으로 보존 |
| `operation` | `normal`, `deduction`, `reinforcement` 중 하나 |
| `material` | 원본 재료 설명 |
| `spec` | 25-270-15, H13 등 원본 규격 |
| `native_unit` | 원본 단위(m³, m², m, kg 등) |
| `expression_text` | 원본 산출식 문자열. 해석·수정하지 않는다. |
| `raw_quantity` | 원본 결과 셀의 signed 수치 |

숫자만 맞는 임의 행이 PASS하지 않도록 각 anchor는 승인된 `expected_ledger_ids` 집합을 갖는다. 실제 child 행의 ID 집합과 다르거나 `source_sha256 + sheet + cell/row`가 중복되면 FAIL이다. registry 기반 최종 PASS에서는 anchor ID·bucket·unit·공식값·원본 셀과 정렬된 expected ID 집합의 canonical SHA-256도 독립 승인 규칙으로 고정한다. `concrete_family`는 막자갈·무근·철근콘크리트 child의 합, `formwork_family`는 `pure_formwork + formwork_accessories`의 합만 허용하며 임의 parent ledger 행은 금지한다. 합계가 같아도 선택된 child의 SQ001 산식·operation 중 하나라도 PASS가 아니면 SQ002는 PASS하지 않는다.

소스·규칙 객체에 자기 선언한 SHA-256만으로는 공식 PASS가 아니다. 배포·승인 흐름에서 독립적으로 고정한 `StructuralEvidenceRegistry`의 source/rule ID→SHA 매핑과 일치해야 최종 PASS다. registry가 없거나 해시가 다르면 숫자가 일치해도 REVIEW다.

`operation=deduction`은 음수 결과 또는 명시적 공제 재료명에서 결정한다. 예를 들어 ZG `04A`의 기초 보강 공제와 `01` 시트의 개구부 콘크리트·형틀·철근 공제는 모두 signed 행으로 유지한다. 보강근은 양수여도 `reinforcement`로 구분한다.

## 5. raw → official 변환 경계

원시 ledger를 공식 anchor로 재산출하는 규칙은 아직 확정되지 않았다. 따라서 다음은 **승인된 MDB/ACCDB 규칙 또는 버전·해시가 고정된 승인 규칙표가 제공되기 전까지 REVIEW**다.

- 규격별 할증률 적용 대상과 공제행 적용 방식
- 행별 절사·반올림 순서
- 철근 길이(m)에서 질량(kg)으로의 변환
- 실행 품목의 ton 환산 및 절사

ZG `04A` 원시 합계가 콘크리트 405.540 m³, 형틀·부대 2,716.239 m², 철근 길이 H10 12,059.030 m/H13 10,933.050 m/H16 6,811.840 m/H19 639.640 m인 반면 공식 anchor는 위의 할증후 값이다. ZJ도 `실행집계`의 값·할증·결과 열과 `동별 규격별 집계`의 anchor를 구분한다. 단순히 총량에 1%, 2%, 3%, 10%를 곱해 동일 결과가 나온다고 가정하면 안 된다.

### 철근 질량 source gate

`native_unit=m`인 철근 ledger 행이 kg 공식값을 만들려면 다음 둘 중 하나가 반드시 필요하다.

1. 해당 MDB/ACCDB에서 추출한 단위질량·적용조건·절사 규칙과 그 DB SHA-256
2. 적산 담당자가 승인한 규격별 변환 규칙표의 버전, SHA-256, 적용일

이 증거 없이 일반 단위중량표나 임의 상수를 적용한 철근 kg은 공식값이 아니다. anchor를 읽어 보이는 것은 가능하지만, raw→kg 변환 검증은 REVIEW로 남긴다.

보고 kg와 승인 배근중량표는 각기 다른 소스 셀을 가리켜야 한다. 길이×단위중량×할증 basis에서도 보고값·길이·단위중량·할증률 네 근거 셀은 서로 달라야 한다. 같은 셀의 값을 여러 입력에 복사한 순환 자기검증은 REVIEW다. `RebarMass` anchor는 ledger 합계로 PASS할 수 없고 반드시 독립 근거를 가진 SQ003을 거친다.

0보다 큰 허용오차는 bucket·단위·단계별 승인 규칙 ID와 SHA-256이 있을 때만 PASS에 쓴다. 산식에 절사·반올림이 필요하면 mode, 0~6 자릿수, 규칙 근거를 명시한다. 그렇지 않은 근접한 차이는 PASS가 아니라 REVIEW다.

## 6. Provenance와 증거

모든 결과에는 다음 증거를 함께 기록한다.

- 입력 파일 역할과 SHA-256
- ledger 행의 `source_ref`, 원본 산출식 문자열, signed 결과값
- anchor 셀 주소, 저장된 수식, 저장된 결과값
- 적용한 MDB/승인 규칙표의 SHA-256 및 규칙 버전
- 평가 시각, 허용오차, 평가 상태와 사유

원본의 수식 문자열·셀 값·시트명은 정규화하여 덮어쓰지 않는다. 공식 anchor의 제한된 `SUM(범위)`·직접 셀 참조는 leaf까지 재귀 평가해 중간 저장 캐시와 모두 일치해야 한다. 현재 고정 raw 스키마의 결과·개소는 수식이 없는 저장 OOXML 숫자 셀만 허용하며 문자열처럼 보이는 숫자나 숨은 수식 셀은 거부한다. Unknown 버킷도 산식 자체의 결과 불일치는 FAIL로 남긴다. 파일 형식이 `.xls`여도 실제 OOXML 컨테이너인 ZJ 파일은 확장자만으로 파서 분기를 결정하지 말고 내용 형식을 확인한다.

## 7. 결정론적 상태

| 상태 | 조건 |
|---|---|
| `PASS` | 해시·스키마가 유효하고, 승인 규칙이 있는 계산 또는 공식 anchor 수식·값이 정확히 일치한다. |
| `FAIL` | 파일 해시 불일치, 필수 anchor/셀 누락, signed 행 누락, 승인 규칙으로 계산한 값과 anchor의 허용오차 초과 불일치가 있다. |
| `REVIEW` | raw→official 규칙, 철근 질량 근거, 공제/할증 적용 순서가 승인되지 않았거나 사람이 판단해야 한다. |
| `NOT_EVALUATED` | 비교 대상이 적용되지 않거나 원본이 계산 불능이다. 예: ZJ 0층면적 행의 `#DIV/0!` 비율. |

`REVIEW`와 `NOT_EVALUATED`는 PASS로 집계하지 않는다. FAIL이 없더라도 REVIEW가 남은 결과는 공식 재산출 완료가 아니다.

## 8. 구현 단계와 수용 기준

1. **입력·증거 보존** — ZG `04A`, ZJ `02` ledger를 signed-row schema로 읽고 파일 해시·셀 좌표를 보존한다.
2. **Anchor 검사** — ZG `02/03`, ZJ `동별 집계/동별 규격별 집계`에서 규격별 소계와 위 6개 총량을 읽어 상호 대조한다.
3. **버킷 분리** — `pure_formwork`와 `formwork_accessories`를 별도 결과로 내고, 그 합만 `formwork_family` anchor와 대조한다.
4. **MDB 규칙 승인** — DB 또는 승인 규칙표의 단위중량·할증·절사 규칙을 해시로 고정한다.
5. **재산출 검증** — 승인 규칙으로 ledger를 재산출해 공식 anchor와 비교한다. 이 단계 전에는 raw→official을 PASS로 만들 수 없다.

최소 수용 테스트는 다음과 같다.

- ZG anchor가 409.221 m³, 2,781.316 m², 30,886.375 kg으로 각각 PASS한다.
- ZJ anchor가 450.781 m³, 2,717.205 m², 31,908.817 kg으로 각각 PASS한다.
- ZG/ZJ 중 어느 한 세트의 해시·셀·총량을 바꾸면 FAIL한다.
- 공제행을 제거하거나 부호를 양수로 바꾸면 ledger completeness FAIL한다.
- 순수 형틀과 부대재료를 섞어 “거푸집”으로만 출력하면 bucket contract FAIL한다.
- 철근 질량 규칙의 DB/승인 규칙표 증거가 없으면 raw→kg은 REVIEW다.
- ZJ 0층면적 비율의 `#DIV/0!`는 수량 총량을 FAIL로 바꾸지 않고 NOT_EVALUATED다.
