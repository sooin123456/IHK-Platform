# L1 CSV 입출력 계약

내역 입력은 UTF-8 CSV 또는 `.xlsx`다. CSV는 쉼표, 큰따옴표, 따옴표 안의 줄바꿈을 지원한다. 일반 XLSX는 첫 번째 워크시트의 문자열·숫자·저장된 수식 결과를 읽는다. 수량·단가·금액 셀은 OOXML 숫자 타입과 저장값을 모두 가져야 하며, 저장값 없는 일반·공유수식이나 문자열 숫자는 입력 오류다. EMS XLSX에 `공종별내역서` 시트가 있으면 해당 시트를 우선 읽는다. 병합셀과 수식 재계산은 하지 않으며, 저장된 값만 사용한다.

숫자는 지역설정과 무관하게 `1200.5` 또는 `1,200.5` 형식만 허용한다. 소수점 쉼표(`1,5`)나 통화 기호는 허용하지 않는다.
모든 헤더는 한 파일 안에서 중복될 수 없다.

## QTO CSV

필수 열: `검산키, 분류, 패밀리, 타입, 레벨, 수량, 체적_m3, 면적_m2, 길이_m, 요소ID`

`검산키`는 Revit이 `분류\u001F패밀리\u001F타입\u001F레벨` UTF-8 바이트에서 계산한 대문자 64자리 SHA-256 식별자다. 네 메타데이터는 비어 있을 수 없고, 입력 시 같은 방식으로 다시 계산한 값과 일치해야 하며 같은 검산키의 집계행은 한 번만 존재해야 한다. 파서는 소문자 SHA 입력도 대문자로 정규화한 뒤 중복을 판정한다. 매핑 CSV에는 QTO CSV의 값을 그대로 복사한다. `요소ID`는 `|`로 연결한 양의 정수 Revit ElementId다. `1`과 `01`은 같은 ID로 정규화하며 한 행 안과 QTO 전체에서 중복될 수 없다. `수량`은 1 이상의 정수이고 해당 행의 요소ID 개수와 정확히 같아야 한다. 하나라도 위반하면 입력을 거부하며 BIM 대조에 사용하지 않는다. 모델에 요소가 없는 경우에는 가짜 0행을 만들지 않고 헤더만 있는 QTO CSV를 사용한다.

## 내역 CSV

필수 열: `내역ID, 품명, 단위, 수량, 단가, 금액`

단위는 `EA`, `m`, `m2`, `m3`만 사용한다. KRW는 산술 검산의 단가·금액에 사용한다.
내역 파일에는 데이터 항목이 1개 이상 있어야 한다. `내역ID`는 기계적 연결 키이므로 Excel 수식 문자 `=`, `+`, `-`, `@`로 시작할 수 없다.

## EMS 공종별내역서 XLSX

실제 EMS 내역서의 `공종별내역서`를 인식한다. `N`열 품목 ID, `C`열 단위, `D`열 수량, `E/G/I`열 재료·노무·경비 단가, `K/L`열 총단가·금액을 읽는다. N열 값은 중복될 수 있으므로 L1의 `내역ID`는 `N열값:원본행번호`로 만든다. 금액은 EMS 표시식에 맞춰 다음처럼 검산한다.

`TRUNC(수량×재료단가, 0) + TRUNC(수량×노무단가, 0) + TRUNC(수량×경비단가, 0)`

`E`~`L` 금액 영역이 모두 실제 빈 셀인 행만 금액 계산 대상이 아닌 참고 행으로 제외한다. 금액 입력 일부가 있는데 총금액 또는 수량이 비어 있는 행은 삭제하거나 0으로 추정하지 않고 R011 NOT_EVALUATED로 남긴다. D~L의 비어 있지 않은 계산 셀은 OOXML 숫자 타입이고 저장값이 있어야 한다. 문자열 숫자, Excel 오류, 저장값 없는 수식은 입력 오류로 중단하며 행을 누락시키지 않는다. F/H/J에 저장된 재료·노무·경비 구성금액은 별도 원본값으로 보존하며, 값이 있으면 각 Q×구성단가 절사값과도 대조하고 R012 소계에도 사용한다. Excel이 `280.9`를 `280.89999999999998`처럼 직렬화한 값은 Excel의 15자리 유효 정밀도로 정규화하여 1원 단위의 가짜 불일치를 방지한다. 이 정규화가 서로 다른 정수를 합치지 않도록 절댓값 `9,007,199,254,740,991`을 넘는 저장 숫자는 안전하지 않은 입력으로 거부한다.

지원하지 않는 단위도 항목에서 삭제하지 않는다. 산술 검산은 계속하되 BIM 수량 대조는 `R021 NOT_EVALUATED`로 남긴다. 해당 항목에 BIM 매핑을 추가하려면 별도 단위·계산식 규칙을 먼저 승인해야 한다.

EMS에서 수량과 금액이 모두 음수인 행은 공제·환입 조정으로 해석한다. R010·R011 계산은 그대로 검산하지만 양수 BIM 물량과 직접 비교하지 않고 `R021 NOT_EVALUATED`로 남긴다. 일반 CSV의 음수값은 자동 조정으로 추정하지 않는다.

동일 XLSX에 `원가계산서`가 있으면 필수 비목 코드 `AS, B2, BS, C4, C5, C6, C7, CA, CB, CG, CH, CS, S1, D1, D2, D9, DB, DH, S2`와 선택 비목 `D3`~`D8`, `DK, DL, DM`의 저장값을 읽어 R012 총액 체인을 검산한다. 같은 비목 코드가 두 번 나오면 입력 오류로 중단한다. 관급·별도 금액이 있는 파일에서 품목 구성금액과 AS·BS·CS 중 일치하는 소계는 PASS, 배분 근거 없이 차이가 있는 소계만 NOT_EVALUATED로 남긴다. 요율이 법적으로 맞는지는 판단하지 않고 저장된 비목 간 산술만 확인한다.

## 매핑 CSV/XLSX

필수 열: `내역ID, 검산키, 단위, 계수`

매핑은 사람이 검토·승인한 값만 입력한다. 명칭 유사도만으로 자동 매핑하지 않는다. `승인` 열이 있으면 값이 `Y`인 행만 검산에 사용한다.
승인 행이 0개인 매핑 파일은 EMS/내역 산술만 수행하는 입력으로 허용하며, 각 BIM 대조는 R020·R021 NOT_EVALUATED로 남긴다. 검산 대상 내역 자체가 0개인 실행은 허용하지 않는다.
XLSX 매핑의 내역ID·검산키는 수식이나 숫자 셀이 아닌 명시적 텍스트 셀이어야 한다. 이는 표시형식만 `001`로 보이는 숫자 `1`을 다른 기계 ID로 오인하지 않기 위한 조건이다.

## 매핑 템플릿

```sh
dotnet run --project src/THEKIE.Qto.Preflight -- --sources samples/source-manifest.csv --mapping-template samples/qto.csv samples/estimate.csv mapping-template.xlsx qto-index.xlsx
```

템플릿에서 검산키를 `qto-index.xlsx`에서 복사하고 `승인`을 `Y`로 바꾸면 그대로 매핑 XLSX로 사용할 수 있다. 템플릿과 인덱스는 모든 셀을 OOXML 텍스트 타입으로 저장하므로 `001` 같은 기계 ID가 스프레드시트에서 `1`로 바뀌지 않는다. CSV 템플릿 출력은 자동 형변환 위험 때문에 제공하지 않는다.

## 실행

```sh
dotnet run --project src/THEKIE.Qto.Preflight -- --sources samples/source-manifest.csv samples/qto.csv samples/estimate.csv samples/mapping.csv samples/report.csv
dotnet run --project tests/THEKIE.Qto.Core.SelfTest
```

종료 코드 0은 소스 게이트를 통과한 실행에 FAIL 없음, 1은 FAIL 있음, 2는 입력 또는 실행 오류, 3은 결과는 만들었지만 소스 게이트를 건너뛴 진단 실행이다. 따라서 자동화는 코드 3을 승인 결과로 취급하면 안 된다.

검산 실행 시 결과 CSV 외에 `결과파일.html`과 `결과파일.manifest.csv`가 생성된다. HTML은 공유용 요약 보고서이고, 실행 manifest에는 규칙 버전, 코어·CLI 어셈블리 SHA-256, 수량·KRW 허용오차, 생성시각, 세 입력 파일과 소스 매니페스트의 SHA-256, 선택된 범위·소스 ID, 게이트 결과가 기록된다. 결과·HTML·manifest 경로는 입력 경로와 같을 수 없고 기존 파일도 덮어쓰지 않으므로, 실행마다 새 결과 경로를 지정한다. 모든 입력 해시는 판정 전후에 대조하며 실행 중 바뀌면 결과를 쓰지 않고 중단한다.

Excel에서 여는 결과 CSV와 실행 manifest의 텍스트 필드는 앞 공백 뒤 첫 문자가 `=`, `+`, `-`, `@`이면 작은따옴표를 붙여 수식 실행을 막는다. 매핑 템플릿은 모든 셀을 XLSX 텍스트 타입으로 저장한다. 기대값·실제값·차이 같은 숫자 필드는 원래 decimal 값을 고정소수점으로 보존한다.

소스 매니페스트의 정확한 열·상태·S001~S005 규칙은 [SOURCE_MANIFEST.md](SOURCE_MANIFEST.md)를 따른다. 매니페스트가 준비되지 않은 진단 실행은 `--unsafe-no-source-gate`를 명시해야 하며 결과에 `S000 REVIEW`가 남는다.
