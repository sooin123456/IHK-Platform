# Drawing review screen refresh implementation plan

**Goal:** 기존 로컬 작업실에서 작성/검토 전환, 변경 핀, 위치별 대화 화면을 연결한다.
**Spec:** ../evidence/2026-09-09-workspace-replan/README.md — 사용자가 화면 우선 구현 승인.
**Architecture:** 기존 DrawingPdfScreenPreview 도면을 유지하고 변경 목록/핀 표시를 작은 컴포넌트로 분리한다. 운영 화면·백엔드·CAD·실시간 협업·승인 전송은 변경하지 않는다.
**Tech Stack:** 기존 React/TypeScript/CSS/Lucide, Node SSR tests, in-app browser.

## Constraints

- 기존 사용자 변경을 보존한다. 별도 작업실 route나 신규 의존성을 만들지 않는다.
- 사무실 템플릿에서만 명시적인 샘플 변경 3개를 제공한다. PDF/빈 도면에 임의 변경을 만들지 않는다.
- 모드 전환으로 page/zoom/fitKey/viewMode/선택/대화 초안을 초기화하지 않는다.
- 화면 대화·요청 구성은 실제 전송/승인과 구별한다. 기존 검토 흐름은 보조 진입점에서 유지한다.
- Viewer 편집 금지, 키보드 핀 선택 및 좁은 화면 패널 유지.

## Tasks (같은 상태 인터페이스를 수정하므로 이번 구현은 직접 순차 진행)

- [ ] 1. `tests/drawing-change-preview.test.mjs`: 실제 SSR 렌더에서 작성/검토 모드와 변경 목록 존재, PDF에 샘플 없음, 실제 도형 선택 식별이 동일함을 검사한다. `node --test tests/drawing-change-preview.test.mjs`로 실패 확인.
- [ ] 2. `drawing-change-preview.tsx/.css`: `drawingChangeItems(shapes,officeSample)`와 `DrawingChangePins`, `DrawingChangePanel`을 구현한다. 단일 selected ID를 소비하며 상세/대화/비교는 화면 예시로 표현한다. 최초 임의 변경은 officeSample일 때만 반환한다.
- [ ] 3. `drawing-pdf-screen-preview.tsx`: mode state와 selectedChangeId를 소유한다. 작성/검토 버튼은 UI mode만 전환하며 도면 renderer를 재마운트하지 않는다. 기존 도구는 작성 모드, 변경 강조와 탐색은 검토 모드로 바꾼다. 기존 검토·개인 메모는 명시적 보조 패널로 유지한다.
- [ ] 4. SSR 기존 PDF/검토/도형 관련 테스트, 타입 포함 build 수행. 로컬 런타임 복사는 파일별 diff 확인 후 해당 파일만 반영한다. 브라우저에서 모드/핀/목록/대화 보존/Viewer/좁은 화면 확인.

## 후속 완성도 개선 — 변경 위치 노출

- 실제 브라우저에서 3D 상태의 변경 선택 시 상세만 열리고 2D는 가려져 있는 실패를 재현했다.
- 변경을 직접 선택하면 3D 전용 보기를 2D로 복귀한다. 이미 2D가 보이는 분할 보기와 일반 작성/검토 모드 전환의 보기 상태는 보존한다.
- 도형의 레이어가 숨겨져 있으면 해당 레이어만 표시한다. 잠금과 다른 레이어 설정은 변경하지 않는다. 활성 작성 도구도 종료하여 위치 확인 중 우발적인 도형 추가를 피한다.
- 레이어 표시의 불변성·잠금 보존·미존재/이미 표시된 레이어 테스트를 실패 확인 후 구현했다. 관련 테스트 60/60, 타입 검사, 빌드 통과.
- 브라우저에서 3D→변경 선택→2D와 상세 동일 ID 확인, 분할→변경 선택→분할 유지 확인. 콘솔 error 없음. 숨긴 레이어 로직은 단위 테스트 검증이며 전체 브라우저 도형 생성 시나리오는 아직 미검증.

## 후속 완성도 개선 — 기존 수정·승인 흐름 회귀

- 기존 drawing-screen-object-browser 테스트 두 개를 재실행해 새 개정 시작 후 검토 모드가 남아 편집 검사기로 가지 못하는 회귀를 발견했다.
- 화면 검토 reducer가 resolve/new-revision을 유효하게 수락했을 때만 작성 모드로 전환한다. Viewer는 이 전환에서 제외한다. 검토 중/승인된 대상의 수정 차단은 기존 규칙을 유지한다.
- 기존 테스트의 ‘검토 도형 클릭=바로 속성’ 기대는 새 승인된 UI(변경 대화가 먼저 열림)에 맞춰 속성 탭을 명시적으로 열어 읽기 전용을 검증하도록 조정했다. 작성 모드에서도 작성 도구 비활성 확인을 유지했다.
- 작성→수정 요청→새 개정→실제 화면 속성 수정→재검토→승인→새로고침 후 읽기 전용 복원까지 통과했다. 이는 화면 시나리오이며 서버 승인 검증은 아니다.
- 기존 객체 동선 2개 + 신규 검토 동선 7개 = 브라우저 9/9, 관련 단위/SSR 60/60, 타입 검사·빌드 통과. 로컬 4181 반영, 운영 미배포. 전체 목표 진행 중.

## 후속 완성도 개선 — 원본 복구·검토 재개

- 기존 PDF 복구 테스트를 현재 검토 기록/더보기 메뉴 경로로 갱신하고 실행했다. 재열기 시 기록은 복원되지만 작성 시작 화면이 표시되어 검토 대기 문맥을 놓치는 문제 재현.
- 저장된 requested/changes/reviewed/approved 상태를 재열면 검토 모드와 기록 탭을 표시한다. 명시적 다른 업무 패널/물량 진입은 덮어쓰지 않는다.
- 승인 후 속성 읽기 전용 검증은 새 검토 모드에 맞게 속성 탭을 명시적으로 열어 확인한다.
- 동일 PDF를 다른 이름으로 재선택해도 페이지/검토 유지, 다른 원본 선택 취소 시 유지, 교체 확인 시 새 화면 초기화 및 이전 기록 보존, 원본 재열기, 자재 지정 근거의 원본 불일치 거부까지 통과.
- 실제 PDF 포함 브라우저 10/10, 관련 SSR/단위 60/60, 타입 검사·빌드 통과. 로컬 반영, 운영 미배포. 전체 목표 진행 중.

## 후속 완성도 개선 — 다른 원본 교체 후 작성

## 후속 완성도 개선 — 검토에서 선택 도형 수정

## 후속 검증 — PDF 복구 간헐 실패 추적

- 동일 병렬 조건으로 복구 실패를 재현했다. 진단 출력상 요청/페이지 오류는 없고, 저장된 검토 상태는 복원됐지만 원본 미선택 화면이었다. 실패 위치는 두 번째 reload 직후 파일 입력 단계였다.
- 테스트가 서버 렌더 HTML을 대상으로 클라이언트 복원 전에 파일 입력을 넣는 경쟁 가능성을 확인했다. 두 reload 후 저장된 ‘검토 모드’가 실제 aria-pressed=true가 될 때까지 기다리는 조건을 추가했다. 임의 sleep/timeout 증가/강제 성공 처리는 하지 않았다.
- 이후 같은 병렬 조건을 3회 연속 실행해 매회 11/11(총 33회 검증) 통과. 제품 코드 변경은 없으며, 재현 실패의 모든 가능한 환경 원인을 증명한 것은 아니다.
- 테스트 실패 시 URL, 페이지 오류, 실패 요청, 화면 텍스트 진단이 남도록 보강했다. 추가 운영 배포 없음. 전체 목표 진행 중.
