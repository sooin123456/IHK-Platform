## 다음 구현 순서

### 후속 연결: 검토 후 다음 행동

요청 화면에 항목 검토→승인 확인→납품 기록 첨부 단계와 상태별 다음 행동을 표시한다. 미확인은 검토자 보기, 수정 요청은 첫 해당 위치, 전체 확인 및 현재 표시 일치 시 승인자 보기로 이동한다. 도면이 달라지면 재구성을 안내하며 자동 승인하지 않는다. 고정 요청과 실제 도면 개정 승인은 여전히 별개다.

승인 확인 진입 버튼 부재 RED 후 구현. 브라우저 20/20, 단위/SSR 14/14, 타입 검사·빌드 통과. 스크린샷에서 제목 자동 스크롤이 단계 표시를 가리는 것을 발견해 요청 요약 아래로 재배치했다. 최종 배치의 초기 가시성·승인 확인 흐름을 별도 브라우저로 재검증한다. 전체 A–G+V2 수용표 완료 판정은 아직 하지 않았다.

### 후속 연결: 미제출 검토 요청 초안

기존 대화 스키마에 optional requestDraft를 추가하여 이전 저장값과 호환하면서 요청 메시지·직접 선택 ID·범위 모드를 탭에 보관한다. 복원 후 기존 미리보기는 폐기하여 현재 범위를 다시 확인하게 한다. 현재 페이지 모드는 재개한 페이지 기준이며 이를 안내한다. 찾을 수 없는 선택은 경고한다. 저장 실패는 대화 초안과 같은 보호/재시도 경로를 사용한다.

초안 유실 및 잘못된 스키마 수용 RED 후 구현. 복원값이 textarea의 부모 라벨 텍스트에 포함되는 문제를 DOM 진단으로 확인해 명시적 aria-label을 추가했다. 브라우저 20/20(skipped 0), 단위/SSR 14/14, 타입 검사·빌드 통과. 로컬 4181 반영, 운영 미배포. 전체 화면 목표는 미완료다.

### 후속 연결: 위치별 대화·입력 초안 복원

문서 ID가 있고 원본 교체/고정 회차가 아닌 작업은 위치별 의견, 작성 중 초안, 대화 유형, 확인 표시를 별도 버전 스키마로 탭 저장한다. 새로고침 후 같은 객체 ID로 복원한다. 손상된 기록은 덮어쓰지 않고 작성 차단·다시 읽기를 제공한다. 저장 실패는 기존 이탈/원본 교체 보호 상태로 전달하고 대화 보관 재시도를 제공한다. Viewer는 저장하지 않는다.

초안 reload 유실 RED 확인 후 구현. 브라우저 19/19(skipped 0: 초안/의견 복원, 쓰기 실패, 이동 차단, 재시도, 손상 기록 보호 포함), 단위/SSR 14/14, 타입 검사·빌드 통과. 로컬 4181 반영. 서버 동기화가 아니며 임시/교체 원본 화면은 여전히 메모리 범위다. 미요청 요청 메시지 초안·모든 프로그램 방식 이동 보호는 별도 잔여 항목이다.

### 후속 연결: 납품 요청 기록의 가시성

승인 확인 요청의 고정 기록을 현재 납품 화면뿐 아니라 이전 구성 이력과 프로젝트 납품 목록에서도 같은 읽기 전용 컴포넌트로 표시한다. 요청 메시지·항목별 페이지·검토 의견·승인 확인 의견/시각을 보이며 긴 항목은 details로 접는다. 현재 도면 승인/과거 PDF 복원과 구분한다. 새 라이브러리·서버 기능 없음.

이력에서 기록 내용이 누락되는 SSR RED 후 구현. 납품 단위/SSR 12/12, 브라우저 19/19(skipped 0: 요청 첨부 후 reload·의견 펼치기, 기존 납품/프로젝트 왕복 포함), 타입 검사·빌드 통과. 로컬 4181 반영, 운영 미배포. 요청과 도면 개정의 완전한 연결·구성 전 임시 선택 보존·전체 화면 수용표는 여전히 남아 있다.

### 화면 우선 후속: 번호 기반 변경 확인

도면 핀과 목록의 번호를 일치시켰다. 확인 전 필터에서도 원래 번호를 유지한다. 검토 모드에는 확인 진행 막대와 다음 확인 전 항목 버튼을 추가하여, 목록과 상세 대화 사이에서도 같은 도면의 미확인 항목으로 이동한다. 화면 확인 표시이며 승인과 별개임을 명시한다. 서버 기능 추가 없음.

진행 UI 부재로 실패하는 브라우저 테스트 확인 후 구현. 새 진행/번호 검사와 기존 PDF·대화·검토 요청 회귀 18/18 통과(skipped 0), 관련 단위/SSR 13/13, 빌드 통과. 데스크톱 스크린샷 확인. 로컬 4181 반영, 운영 미배포. 전체 제품 화면 목표 완료를 뜻하지 않는다.

### 후속 연결: 키보드 도형 이동

선택 도형에 초점이 있을 때 방향키 1칸/Shift+방향키 10칸의 정규화 화면 이동을 지원한다. 입력란의 화살표는 가로채지 않으며 Ctrl/Meta/Alt 조합과 드래그 중 이동은 처리하지 않는다. Inspector에 사용 방법을 표시했다. Viewer는 이동 콜백이 없어 키보드로도 변경되지 않는다.

방향키 위치 변화 RED 후 구현. 브라우저 6/6(방향키/Shift·삭제 복원 좌표·Viewer 불변 포함), 관련 단위/SSR 25/25, 타입 검사·빌드 통과. 로컬 반영, 운영 미배포. 전체 목표는 미완료이며 다중 선택·연속 취소·승인/납품 연결 등 기존 핵심 공백은 유지한다.

### 후속 연결: 선택 도형 드래그

선택된 화면 도형의 드래그를 연결했다. 이동 중에는 오버레이 위치만 미리 보여 주고 pointerup에서 한 번 반영한다. Esc·pointercancel·포인터 캡처 상실은 원래 위치를 유지한다. 실제 표시 크기로 정규화 좌표 이동량을 계산하며 Viewer·잠금·검토 상태에서는 이동 콜백을 제공하지 않는다.

드래그가 위치를 변경하지 못하는 브라우저 RED 후 구현했다. 이동 반영→다음 드래그 Esc 취소→위치 입력→삭제/복원→재열기·Viewer 검사, 기존 객체 검토/복구 포함 브라우저 6/6, 단위/SSR 65/65, 타입 검사·빌드 통과. 로컬 4181 반영. 터치 제스처/다중 선택/연속 undo-redo/확대 배율별 좌표 정밀 검증은 남아 있다.

### 후속 연결: 선택 도형 편집

검사기에 정규화 화면 X/Y 위치 입력, 새 ID 복사, 삭제와 직전 삭제 취소를 연결했다. 원본 바이트/요청 이력은 변경하지 않는다. 기존 개정 대상은 삭제를 차단하고 사유를 표시한다. 원본 교체 시 삭제 취소 대상도 초기화한다. 좌표는 실제 CAD/실측 좌표가 아닌 화면 예시임을 표시한다.

브라우저: 복사본 ID 분리→위치 변경→삭제 후 원본 유지→삭제 취소 후 좌표 복원→새로고침 보관, 기존 PDF 복구·검토 도형 회귀 포함 6/6 통과. Viewer 새 편집 명령 비활성도 추가 검사했다. 관련 단위/SSR 65/65, 타입 검사·빌드 통과. 로컬 반영, 운영 미배포.

전체 이동/편집 완료는 아니다. 드래그 이동·다중 선택·연속 undo/redo는 아직 없고 삭제 취소는 현재 세션의 직전 삭제 한 건만 복원한다. 키보드/모바일 위치 편집과 승인 요청 이후 변경된 표시의 재요청 시나리오를 추가 검증해야 한다.

### 후속 연결: 프로젝트 승인 확인 목록

요청 approval 기록이 있는 경우 프로젝트 목록에서 ‘승인 확인’으로 분류한다. 항목별 checked만 있는 ‘확인 완료’와 분리했으며 승인 확인 필터를 도면 왕복 시 유지한다. 같은 요청 번호의 고정 승인 의견을 읽고 Viewer가 변경할 수 없음을 브라우저로 검증했다. 도면 개정 승인·납품 완료가 아니라는 설명을 목록에도 표시한다.

관련 단위/SSR 82/82, 타입 검사·빌드 통과. 로컬 4181 반영, 운영 미배포. 개정 승인·납품 인계는 여전히 미완료이며 목록 연결을 전체 인계 완료로 취급하지 않는다.

### 후속 구현: 요청 묶음 승인 확인 화면

요청 묶음 안에 승인자 체험 역할과 승인 대상 확인을 추가했다. 모든 항목이 checked이고 현재 항목 내용이 고정 요청과 일치할 때만 승인 확인 가능하다. 실제 화면 도형은 전체 스타일/좌표를 sourceState로 함께 기록하여 색상 등 변경도 비교한다. 승인된 묶음은 검토 의견을 수정할 수 없고 새 요청을 구성해야 한다. 승인 의견/시각은 해당 요청에 보관한다. 기존 기록은 승인 필드 없이 복원 가능하며 미확인 항목이 있는 승인 기록·잘못된 시각은 복원을 거부한다.

검증: 판정 함수 부재 RED 후 구현. 브라우저 17/17(검토 전 승인 차단→검토자 전체 확인→승인자 확인→읽기 전용→reload 포함), 관련 단위/SSR 65/65, 타입 검사·빌드 통과. 실제 구조 PDF 포함. 로컬 4181 반영, 운영 미배포.

이 구현은 **요청 묶음의 승인 확인 화면**이며 기존 도면 개정 승인이나 납품 상태를 변경하지 않는다. 따라서 위 우선순위 1의 도면 개정 인계와 3의 납품 대상 연결은 아직 미완료다. 승인 의견 저장 실패·Viewer·변경된 실제 도형의 승인 차단을 조합한 추가 브라우저 검증도 필요하다.

1. 요청 묶음→개정 승인 연결의 현재 데이터 경계를 조사하고 기존 승인 패널로의 명시적인 인계 화면을 구성한다. 승인 결과를 임의 복사하거나 자동 확정하지 않는다.
2. 선택 객체의 화면 편집 동선을 완성한다.
3. 승인 결과→납품의 대상 동일성을 연결한다.
4. 초안 보호와 전체 역할별 수용 검증을 완료한다.
