1. **E1 연결 물량의 예외 흐름.** 선택 객체 ID 전달·미산출 행·공종 보존·동일 객체 복귀는 구현 및 검증됐다. 남은 것은 삭제/원본 교체 시 누락 안내, 다중 페이지/모바일 목록과 승인 근거 연결의 수용 검증이다. 설명용 A01 수치를 실제 측정값으로 취급하지 않는다.
2. **D1/D2 기존 개정 루프와 요청의 인계.** 새 요청 approval과 `reviewLoop`는 별개다. 요청 snapshot은 존재하지만 그것이 기존 도면 승인 상태를 바꾸지 않는다. 자동 승인 복사 대신, 동일 요청·원본·페이지의 승인 대상 확인 화면과 읽기 전용 결과 소비자를 일관되게 연결한다.
3. **F1 납품 범위 정합성.** `deliverySource`는 `reviewLoop`와 `approvedRequest`를 나란히 보관한다. 현재 구성의 페이지/개정과 첨부 요청 배치가 일치하는지 사용자에게 명확히 확인시키고, 과거 구성은 현재 편집본으로 교체하지 않는다.
4. **C2 및 전체 역할 수용.** 블록/스타일/표의 독립 예시를 실제 선택 대상으로 연결하고, 이후 A–G/T1–T6의 남은 형식·역할·반응형 조합을 검증한다. 검토 창의 소규모 개선만 반복해 이 공백을 대체하지 않는다.

### C1 후속 실행 결과

다중 선택 후속: Shift+클릭/Shift+Enter로 같은 페이지의 표시 도형을 추가·해제한다. 선택 외곽선·검사기 개수/목록·일괄 복사/삭제를 동일 ID 배열로 연결했다. 복사는 공통 오프셋으로 상대 위치를 유지하고 새 ID를 부여하며, 일괄 작업은 하나의 undo 항목이다. 삭제 undo는 여러 도형의 선택도 복원한다. 잠긴 레이어가 포함된 일괄 편집과 검토 대상이 포함된 삭제는 차단한다. 일반 클릭은 단일 선택으로 돌아간다.

선택 수 화면 부재 RED 후 구현. 브라우저 30/30, 단위/SSR 16/16, 타입 검사·빌드 통과. 실제 스크린샷에서 일괄 작업 버튼 구분이 부족해 기존 버튼 스타일과 간격을 적용하고 최종 일괄 작업을 재검증했다. 로컬 반영. 다중 드래그 이동·공통 속성 일괄 편집·모바일 선택 진입·선택 상자는 남아 있으며 다중 선택 전체 완료로 판정하지 않는다.

입력 단위 후속: 같은 입력란에 초점이 머무는 동안의 도형 속성 변경을 동일 group으로 묶는다. 다른 입력란/도형/명령은 새 작업이며 undo/redo 후 새 입력은 이전 group과 합치지 않는다. 연속 이름 입력 RED 후 구현. 브라우저에서 숫자 필드를 비우면 기존 숫자가 즉시 복원되어 새 숫자가 뒤에 붙는 문제도 발견해, 좌표 필드의 입력 문자열을 적용된 좌표와 분리했다. 범위를 벗어나거나 빈 값은 도형에 적용하지 않으며 포커스를 나가면 마지막 적용값을 표시한다.

브라우저 9/9(연속 이름·좌표 입력의 작업 분리, 기존 이력/단축키/검토/복구), 타입 검사·빌드 통과. 로컬 반영. 다중 선택·작성 메뉴 통합과 전체 수용표의 다른 미완료 범위는 유지한다.

검토 대상 후속: edit-target의 현재 도형도 캔버스 이력에 반영한다. undo/redo는 동일 ID·페이지·종류의 현재 도형만 edit-target으로 전달하며 검토 의견·과거 개정·승인 상태를 복원하지 않는다. 이력 초기화 기준을 모든 phase 변경에서 편집 가능/잠금 경계·개정 번호·대상 ID·보관값 복원으로 조정하여 draft→changed 첫 편집이 소실되지 않게 했다. 검토 대상의 삭제/페이지·종류 교체는 계속 차단한다.

검토 도형 이름 변경 후 undo 버튼 disabled RED 확인 후 구현. 수정 요청→새 개정→이름 변경→undo/redo→재검토→최종 승인·reload 브라우저를 포함한 28/28, 관련 단위/SSR 47/47, 타입 검사·빌드 통과. 로컬 4181 반영, 운영 미배포. C1 잔여는 입력 단위 병합·다중 선택·작성 메뉴의 독립 옵션과 연결이며, D의 새 요청 묶음/도면 개정 일원화는 이 변경으로 완료되지 않는다.

키보드 후속: Ctrl/Meta Z, Ctrl/Meta Shift Z, Ctrl Y를 실제 도형 이력에 연결했다. 제거 후 작업실 루트에 초점을 유지하여 바로 redo 가능하다. input/textarea/select/contenteditable/role=textbox, IME 조합, 열린 업무 패널, 드래그 중에는 캔버스 이력을 가로채지 않는다. 반복 키 입력은 이력을 연속 소모하지 않는다. 단축키 부재 RED 후 구현, 객체/복구 브라우저 8/8, 단위/SSR 41/41, 타입 검사·빌드 통과. 드래그 중 Ctrl Z 보호도 별도 브라우저 재검증한다. 검토 대상 edit-target 이력·입력 단위 병합·다중 선택 등 나머지 C1 범위는 유지한다.

일반 캔버스 화면 도형의 생성/복사/이동/속성/삭제를 동일한 최대 100단계 세션 이력으로 연결했다. 도구막대의 도형 실행 취소/다시 실행이 실제 표시 객체를 복원하고 새 편집은 redo를 비운다. 잠긴/사라진 레이어나 현재 검토 대상에 영향을 주는 복원은 차단한다. 원본 교체·보관값 복원·검토 대상/개정 단계 변경에서는 이력을 초기화한다. 기존 단일 삭제 취소도 이력에 기록한다.

브라우저 생성/복사/좌표/삭제의 undo-redo·분기 검사와 객체/복구 회귀 7/7, 변경·대화 회귀 20/20, 단위/SSR 15/15, 타입 검사·빌드 통과. 로컬 4181 반영. **C1 전체 완료 아님:** 검토 대상으로 지정된 객체의 edit-target 이력, 키보드 단축키, 입력 단위 병합, 작성 메뉴의 독립 예시와 통합, 다중 선택은 남는다. 새로고침 후 현재 도형은 기존 방식으로 복원되지만 undo 스택 자체는 복원하지 않는다.

1. **C1 실제 화면 객체의 연속 실행 취소/다시 실행.** 현재 `drawing-authoring-preview.tsx`의 `advanceAuthoringHistory`는 문자열 label 기록만 되돌린다. 캔버스는 단일 삭제 취소만 존재한다. 실제 화면 객체의 생성/이동/속성/복사/삭제를 동일 이력에 연결하되 승인·잠금·Viewer·원본 교체 경계를 유지한다. 서버 operation 구현으로 확대하지 않는다.
2. D1/D2: 새 요청 묶음과 도면 버전의 명시적인 연결 및 고정 화면 다시 열기. 요청 승인만으로 파일 전체 승인 처리하지 않는다.
3. B1–B3/C3/G3: 시작 종류별·모드별·좁은 화면 수용 시나리오를 보강한다.

작은 문구 수정이나 기존 녹색 테스트의 반복만으로 이 우선순위를 대체하지 않는다. 전체 목표는 유지한다.
