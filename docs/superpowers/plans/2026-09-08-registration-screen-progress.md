# 도면 등록 방식 화면 — 진행 기록

## 구현한 범위

DWG·IFC 준비 조건 다음에 등록 방식 확인을 연결했다.

- 별도 새 도면 / 기존 도면의 새 개정 준비 선택.
- 대상은 현재 프로젝트의 도면 목록에서 전달한다. 다른 프로젝트 후보나 임의 예시 대상을 추가하지 않는다.
- 대상이 없으면 개정 선택 불가. 대상 미선택·빈 변경 사유·300자 초과는 진행 불가.
- 같은 이름 안내는 제목과 파일 이름의 확장자를 제외한 정규화 비교이며 실제 동일 파일 분석이 아님을 명시한다.
- 준비 화면에 선택 대상과 변경 사유를 표시한다. 취소하면 등록 방식 입력으로 복귀한다.
- 기존 승인본·원본·검토 상태를 변경하지 않는다. 화면 준비일 뿐 실제 도면 등록이나 개정 발급이 아니다.

## 검증

- 새로운 등록 컴포넌트·검증 함수의 부재로 테스트 실패를 먼저 확인했다.
- registration/native-start/dashboard 47개 통과. 이후 대상·길이 검사를 보강한 registration 2개도 통과.
- 타입 검사 exit 0, 로컬 빌드 exit 0(기존 경고 유지).
- 브라우저: 성수동 사무실 → DWG 예시 → 준비 조건 → 새 개정 선택. 대상 미선택 시 진행 비활성화 확인.
- 1층 평면도 / 문 위치 변경 검토 입력 → 준비 화면에 두 값 표시 → 준비 취소 → 두 값 그대로 복원 확인.
- 로컬 서버 4181, PID 1571, session 92348.

## 남은 작업 — 전체 완료 아님

- PDF 가져오기에도 동일한 등록 방식 흐름 연결.
- 현재 개정 준비 의도는 작업실 제목에만 반영된다. 작업실의 출처 카드·준비 기록 및 프로젝트 목록으로 복귀하는 문맥을 연결해야 한다. 실제 대상 도면의 개정을 변경하면 안 된다.
- 같은 이름 안내의 실제 파일 선택 브라우저 검증, IFC·빈 프로젝트·좁은 화면 검증.
- 준비 조건으로 돌아간 뒤 다시 진입하는 미완성 입력 복원 검증.
- 원래 A–G 전체 화면 목표와 별도로 본 항목을 전체 완료로 취급하지 않는다.

## 후속: 작업실 준비 기록 및 PDF 연결

- DWG·IFC의 등록 방식·파일 이름·대상 도면 제목·변경 사유를 React Router 탐색 상태로 인계한다. 변경 사유나 파일 이름을 URL에 추가하지 않는다.
- 작업실 상단에 접을 수 있는 ‘등록 준비 기록 · 미등록’을 추가했다. 실제 개정·승인·검토 예시와 별개임을 표시한다. 다른 원본을 열면 이전 준비 기록을 숨긴다.
- 화면 경로의 전달값을 길이·형식 검증하고, hydration 후 표시한다. 기존 검토 저장 ID에는 연결하지 않는다.
- PDF 선택 후에도 같은 등록 방식 컴포넌트를 거치도록 연결했다. 준비 조건으로 돌아갈 때 선택 입력을 보관하고, 새 파일을 선택하면 초기화한다.
- registration/native-start/review-loop/pdf-screen/dashboard 총 71개 통과. 타입·빌드 exit 0, 기존 경고 유지. React 점검에서 다른 경로로 이동할 때 이전 record가 잠깐 남는 파생 상태를 제거했다.
- 브라우저 DWG: 1층 평면도 / 출입문 위치 변경 → 준비 → 작업실 → 기록 펼치기에서 파일·대상·사유 일치 확인. 새로고침 후 hydration을 마치면 기록이 다시 표시된다. 오류 로그 조회 0개.
- 런타임: 4181 PID 2228 / session 34524.

아직 미검증: PDF 실제 파일 선택부터 준비·열기 전체 경로, 다른 원본 선택 시 기록 숨김, 모바일 긴 기록, 공유 URL에서 기록이 없는 화면. 프로젝트 목록의 영구 등록·실제 개정 생성은 구현하지 않았다. 위의 예전 ‘PDF 연결’ 및 ‘제목만 반영’ 항목은 이번 코드 변경으로 보완됐지만 해당 브라우저 검증 전체가 완료된 것은 아니다.
