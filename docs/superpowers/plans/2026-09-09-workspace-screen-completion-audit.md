# 작업실 화면 완성도 — 현재 증거와 다음 구현

## 범위

사용자의 최신 지시인 화면 우선 구현을 유지한다. 기존 A–G 및 V2 범위를 삭제하지 않는다. 서버 협업/실제 승인/정밀 CAD/운영 배포는 이번 화면 개발의 완료 주장에 포함하지 않는다.

근거: `2026-09-08-full-product-screen-oneflow.md`, `2026-09-09-v2-screen-integration.md`, `../evidence/2026-09-09-workspace-replan/README.md`, 최신 작업 기록 `2026-09-09-drawing-review-screen-refresh.md`.

## 다음 구현 순서

1. 겹친 변경 핀을 묶고 펼쳐서 선택할 수 있게 한다. 원래 도면 위치는 이동하지 않는다. 목록과 같은 ID·번호를 사용하고 키보드/터치에서도 선택 가능해야 한다. 밀집 상태에서 선택 항목을 놓치지 않는 브라우저 테스트를 먼저 작성한다.
2. 화면 검토 요청의 범위를 현재 페이지/선택 항목으로 구분하고 명시한다. 기존 단일 대상 승인과 여러 항목의 확인을 혼동하지 않으며 실제 승인 완료로 표시하지 않는다.
3. 변경 찾기 이전의 페이지/보기 위치로 돌아가는 행동을 제공한다. 모드 전환은 위치를 바꾸지 않고 명시적인 탐색만 이력을 만든다.
4. 위 동선의 긴 대화/좁은 화면/원본 누락/Viewer를 검증한 뒤 A–G 프로젝트·납품·관리의 전체 여정으로 검증 범위를 넓힌다.

## 최신 검증의 한계

최근 브라우저 13개와 관련 단위/SSR 60개는 위 메인 작업실 일부 동선의 근거다. 이 숫자로 전체 A–G/V2, 다중 사용자, 10,000개 객체 성능, 전체 15페이지 구조 PDF 품질, 실제 사용자의 직관성을 증명하지 않는다.

현재 전체 목표는 미완료다. 기존 기록의 많은 성공 문장을 전체 완료로 합산하지 않는다. 이번 감사는 다음 구현의 순서를 메인 화면 미구현 요구로 되돌리는 기준이다.

## 추가 구현: 요청 범위 선택

- 요청 구성 안에서 현재 페이지 전체 또는 변경 직접 선택. 직접 선택은 다른 페이지의 변경도 포함하며 각 페이지를 표시한다.
- 선택하지 않은 항목 제외, 빈 선택은 미리보기 비활성, 범위 변경 시 기존 결과 숨김. 선택·요청 메시지는 화면을 나갔다 돌아와도 유지한다.
- 미전송/실제 승인 아님 안내 유지. 도면의 선택·대화 상태와 요청 대상 선택은 별개다.
- 신규 브라우저 테스트가 선택 라디오 미구현으로 실패한 뒤 구현 후 통과. 관련 단위/SSR 61개, 브라우저 회귀 15개, 타입 검사·빌드 통과.
- 추가 2페이지 PDF 테스트로 `1, 2쪽 · 2개 변경`과 각 항목의 페이지 표기를 검증했다. `/tmp/1hk-request-scope.png` 시각 확인.
- 로컬 4181에 반영. 프로덕션 배포 없음. 다음 우선순위는 이전 위치 복귀와 좁은 화면·긴 요청 결과의 접근성 검증이며, 전체 A–G 범위는 여전히 미완료다.

## 추가 구현: 탐색 전 위치 복귀

- 변경 탐색 첫 진입의 페이지·배율·스크롤·보기 모드·선택 ID를 기억한다. 다음 변경을 여러 번 보더라도 출발점을 덮어쓰지 않는 단일 복귀 지점이다.
- 상단 `탐색 전 위치 · N쪽`에서 복귀한다. PDF 렌더가 준비된 뒤 스크롤을 복원하여 페이지 전환 초기화와 경합하지 않게 했다.
- 다른 원본을 열 때 복귀 기록을 초기화한다. 모드 전환만으로는 기록을 만들지 않는다. 저장·협업 기능은 추가하지 않았다.
- 신규 실제 브라우저 검사가 버튼 미구현으로 실패한 뒤 통과: 2페이지 PDF, 200% 배율, 가로·세로 스크롤 → 다른 페이지 변경 → 복귀 후 배율과 정확한 스크롤 좌표 일치.
- 관련 단위/SSR 61개, 브라우저 16개, 타입 검사·빌드 통과. `/tmp/1hk-return-location.png`로 상단 버튼 배치 확인. 로컬 4181 반영, 배포 없음.
- 다음 검증: 작은 화면/분할 보기 복귀, 긴 요청 결과의 확인 위치. 이 좁은 테스트 결과로 전체 A–G 구현이나 전체 목표 완료를 주장하지 않는다.

## 추가 구현: 모바일 긴 요청 결과

- 요청 결과를 제목으로 구분하고 미리보기 후 초점·스크롤을 결과로 이동한다. `요청 내용 수정`은 메시지를 보존하며 입력란으로 복귀한다.
- 실제 390×844 브라우저로 긴 메시지 미리보기→수정→재확인을 검증했다. 초기 테스트는 결과 제목/초점 미구현으로 실패했다.
- 첫 구현의 viewport 검사만으로는 고정 탭에 가려진 제목을 잡지 못했다. 캡처에서 문제를 발견하고 제목과 탭의 경계 좌표를 비교하는 실패 테스트를 추가했다. 스크롤 여백 조정 후 통과 및 캡처 재확인.
- 타입 검사·빌드, 단위/SSR 61개 및 최종 브라우저 회귀 17개 통과. `/tmp/1hk-mobile-request.png`에 현재 결과. 로컬 4181 반영, 서버 기능/배포 변경 없음.
- 전체 화면 감사의 다음 범위는 프로젝트→도면→검토→납품→원래 프로젝트 복귀와 역할별 경로다. 현재의 메인 작업실 테스트 개수는 이 전체 여정을 증명하지 않는다.

## 전체 연결 회귀 감사 — 신규 요청과 기존 결정의 단절

이번 회차는 제품 코드 수정이 아니라 현재 화면 경로에 맞춘 회귀 테스트 보완 및 실제 연결 검증이다. 실행 중인 로컬 4181에서 검증했으며 재빌드/배포하지 않았다.

- 프로젝트·변경 회차·물량/자재·납품 6개: 최초 3개 실패. 내보내기/물량은 더보기 안으로, 기존 개정 검토는 검토 기록 탭으로 이동했으나 테스트가 이를 생략했다. 해당 사용자 조작만 추가하고 기존 결과/동일성/권한/저장 실패 판정은 유지했다. 재실행 6/6 통과.
- 공유·자료·관리 8개: 최초 2개 실패도 검토 기록 진입 누락이었다. 경로 보완 후 8/8 통과. PDF 원본 불일치 거부/고정 페이지, 외부 요청 동일 ID 왕복, 만료/취소된 공유 제한, 자료·관리 초안 보존을 포함한다.
- 변경 테스트: drawing-delivery-browser, project-review-navigation-browser, project-change-flow-browser, project-sharing-browser. 모두 화면 예시 검증이며 서버 권한이나 실제 전송 검증 아님.

### 다음 우선순위를 바꾸는 발견

새 DrawingChangePanel의 요청은 `requestPreviewScope`와 메시지로 결과만 표시하며, 결과 다음 행동은 `요청 내용 수정`뿐이다. 기존 검토 결정 reducer/프로젝트 검토 목록에 같은 선택 범위를 전달하지 않는다. 따라서 기존 경로의 14개 통과로 신규 메인 화면의 요청→검토자→수정→재검토가 연결됐다고 판단할 수 없다.

다음 구현은 새 선택 범위의 **고정된 화면 요청 묶음 → 검토자 보기 → 항목별 수정 요청/확인 → 작성자 복귀**다. 같은 ID·페이지·요청 시점 제목을 유지해야 한다. 기존 단일 대상 승인에 여러 항목을 억지로 합치거나 일부 항목을 버리지 않는다. 실제 서버 전송·승인 완료로 표시하지 않는다. 이후 프로젝트 검토/납품과의 연결도 같은 요청 식별자로 검증해야 한다.

분할/모바일 복귀의 나머지 조합 검증은 유지하되, 이 메인 플로우 단절을 우선한다. 전체 목표는 미완료다.

## 신규 요청 묶음의 화면 검토 루프

- DrawingChangeRequestPreview를 추가하고 요청 미리보기에서 `이 구성으로 검토 흐름 체험`으로 진입한다. 당시 항목 ID/페이지/제목/설명과 메시지를 복사한 요청 묶음이다.
- 작성자/검토자 보기는 역할 체험이며 인증 변경이 아니다. 항목별 확인 또는 의견 필수 수정 요청, 현재 도면의 같은 ID 찾기, 작성자로 돌아가 수정, 같은 항목 재검토 구성을 연결했다.
- 새 요청은 별도 회차로 추가한다. 이전 회차는 읽기 전용이며 현재 객체를 수정해도 과거 제목/의견을 바꾸지 않는다. 삭제된 항목의 위치 찾기/같은 항목 재검토는 비활성화한다.
- 요청 1의 두 사각형→확인 1건/수정 요청 1건→두 번째 도형 이름 수정→요청 2→요청 1 다시 읽기 검증. 신규 테스트는 흐름 진입 버튼 미구현으로 실패한 뒤 구현 후 통과했다.
- 최종 브라우저 회귀 18개, 단위/SSR 61개, 타입 검사·빌드 통과. `/tmp/1hk-request-batch.png` 시각 확인. 로컬 4181 반영, 배포 없음.
- **남은 연결**: 묶음은 현재 마운트된 화면의 메모리 상태다. 새로고침/프로젝트 이탈 시 보존되지 않으며 프로젝트 검토 목록·알림·납품에는 아직 연결하지 않았다. 기존 단일 대상 승인 reducer와 합치지 않았다. 실제 승인/전송 주장은 하지 않는다.
- 다음 작업은 요청 묶음의 문서별 식별/복원 경계와 프로젝트 검토 목록 재진입 연결이며, 여러 페이지·Viewer·원본 교체·모바일의 묶음 검토도 보강해야 한다. 전체 목표는 미완료다.

## 문서별 요청 기록 보존

- 등록 문서의 기본 원본에서만 `1hk:preview:change-requests:<documentId>`에 버전 1 요청 기록을 sessionStorage로 보관한다. sourceVersion이 바뀐 작업/과거 changeRound/문서 없는 임시 화면에는 기존 문서 저장 키를 넘기지 않는다.
- 새로고침 복원, 항목별 확인/의견 보존, Viewer 무쓰기, 저장 실패 시 메모리 유지·재시도, 읽기 실패 시 변경 차단·다시 읽기를 연결했다. 원본 바이트/서버 데이터는 수정하지 않는다.
- 파서는 요청 회차·범위·페이지·좌표·문구와 결정의 대상 ID를 확인하며, 손상 데이터를 빈 기록으로 처리하지 않는다. 스키마 불일치·중복 ID·범위 밖 결정·빈 수정 요청 의견을 거부하는 단위 검사 포함.
- 신규 브라우저 검사에서 새로고침 뒤 요청 묶음 소실을 먼저 재현했다. 구현 후 복원, 의도적 quota 실패→화면 왕복→재시도, Viewer 무쓰기, `null` 손상 기록 보호·다시 읽기까지 통과했다.
- 타입 검사·빌드, 단위/SSR 62개, 브라우저 회귀 19개 통과. 로컬 4181 반영. 프로덕션 배포 없음.
- **한계**: 요청의 고정 기록은 보존하지만 새 화면 도형 전체/미확정 의견 초안은 이 저장소에 포함하지 않는다. 복원된 요청의 현재 객체가 없으면 위치 찾기를 막는다. 저장 실패 중 프로젝트 이탈 방지 및 프로젝트 검토 목록 연결은 아직 미완료다. sessionStorage이므로 다른 브라우저/로그인 세션의 서버 협업 보존이 아니다.

## 프로젝트 검토 목록 연결

- 프로젝트의 문서 목록 범위에서 새 요청 저장소를 읽어 `변경 요청 묶음` 목록을 표시한다. 기존 개정 승인·외부 요청과 별도의 화면 기록이며 실제 전송/승인으로 표시하지 않는다.
- 링크는 문서 ID와 requestRound를 유지하고 returnPanel=project-reviews로 복귀한다. Viewer 진입 역할도 보존한다. 존재하지 않는 회차는 다른 요청으로 대체하지 않는다.
- 새 브라우저 테스트는 목록 미구현으로 실패한 뒤 프로젝트→도면 요청 생성→프로젝트 검토→요청 1 열기→수정 요청→같은 검토 목록 상태 반영→Viewer 제한까지 통과했다.
- 구현 도중 children 배열이 기본 도면 목록 fallback을 가리는 회귀를 기존 테스트가 발견했다. 검토 분기 안에서만 두 내용을 묶어 수정했고 도면 목록·검색 복귀 테스트도 통과했다.
- 프로젝트/납품 브라우저 7개, 작업실 브라우저 19개, 단위/SSR 62개, 타입 검사·빌드 통과. 로컬 4181 반영, 운영 배포 없음.
- **잔여**: 현재 검증은 기본 템플릿 요청 경로다. 기존 승인된 도면의 초기 검토 탭 복원과 requestRound 직접 진입 우선순위는 추가 점검 필요. 현재 개정 검토의 빈 상태 문구·필터와 새 묶음 목록의 정보 구조도 통합 정리가 필요하다. 새로 그린 객체 전체의 재진입 복원, 저장 실패 이탈 방지, PDF 원본 재선택과 객체 위치 연결도 미완료다.

## 승인 기록과 요청 직접 진입의 표시 충돌 수정

- 승인된 R3 기록과 별도 요청 1을 보관한 문서에서 requestRound=1로 진입하면, 승인 기록 복원 effect가 검토 기록 탭을 선택해 요청 묶음을 가리는 것을 브라우저 테스트로 재현했다.
- 명시적인 requestRound가 있으면 검토 모드·변경 탭을 초기 화면으로 사용하고, 기존 기록 복원이 해당 탭 선택을 덮어쓰지 않게 했다. 승인된 개정 상태 자체는 그대로 복원한다.
- 동일 테스트에서 요청 메시지 노출·검토 모드·승인 저장 문자열 불변을 확인했다. 없는 requestRound=999는 다른 요청을 표시하지 않는 안내를 확인했다.
- 프로젝트/납품 브라우저 8개, 작업실 브라우저 19개, 단위/SSR 62개 및 타입 검사·빌드 통과. 로컬 4181 반영, 배포 없음.
- 다음 주요 미완료는 실제로 새로 그린 화면 객체의 문서별 재진입 복원이다. 요청만 복원되고 객체가 없어 위치 탐색이 막히는 경우를 해결해야 한다. 전체 목표는 여전히 미완료다.

## 문서 화면 도형·레이어 복원

- 문서 기본 원본의 `1hk:preview:screen-draft:<documentId>`에 localShapes와 레이어를 함께 보관한다. 객체 ID/페이지/위치/스타일 및 레이어 표시·잠금 값을 유지한다.
- 기존 검토 target은 기존 reducer에서 계속 관리하며, 과거 changeRound 화면에는 현재 초안 저장소를 연결하지 않는다. 다른 원본으로 변경한 sourceVersion 작업도 기존 문서 초안에 쓰지 않는다.
- 기존 ScreenShape 검증을 재사용하고, source 종류/용지·중복 객체 ID·존재하지 않는 레이어 참조·잘못된 좌표를 거부한다. 읽기 실패는 편집 차단/다시 읽기, 쓰기 실패는 현재 화면 유지/재시도 안내를 제공한다.
- 프로젝트 요청 왕복 테스트를 샘플 대신 실제 UI에서 그린 사각형으로 강화했다. 구현 전 재진입 시 `도면에서 확인` 비활성으로 실패했고, 구현 후 원래 객체 ID의 상세 및 도형으로 연결되는 것을 확인했다.
- 브라우저 회귀 27개, 단위/SSR 63개, 타입 검사·빌드 통과. 로컬 4181 반영, 운영 배포 없음.
- **잔여**: 등록 PDF 원본 재선택 후 여러 페이지의 도형 복원, 도형 저장 실패/손상 기록의 실제 브라우저 복구, 작업실 보조 메뉴의 오류 상태 편집 제한, 저장 실패 이탈 방지는 추가 검증·보완이 필요하다. 임시 작업의 서버 저장/다른 브라우저 협업 기능을 구현했다는 뜻은 아니다.

## 등록 PDF 복원 및 손상 기록의 보조 메뉴 경계

- 신규 브라우저 검사: 2페이지 PDF 등록→각 페이지에 사각형 작성→새로고침→이름만 바꾼 동일 PDF 선택→양쪽 페이지의 객체 ID 복원 통과. 다른 PDF로 교체 시 현재 도형은 비워지고 기존 문서의 저장 문자열은 그대로 유지되는 것도 확인했다.

- 최종 브라우저 회귀 21개, 단위/SSR 63개, 타입 검사·빌드 통과. 로컬 4181 반영, 배포 없음.

# 후속 검증 — 도형 보관 실패 중 이탈

- 로컬 4181 반영, 운영 미배포. 전체 목표는 진행 중이다. 요청 묶음 보관 실패의 이탈 보호, 프로그램 방식의 SPA 이동, 원본 교체 중 미보관 도형 보호는 아직 이 검증으로 입증되지 않았다. beforeunload 이벤트 취소를 검증했으며 모든 브라우저의 강제 종료 복구 보장은 아니다.
# 후속 검증 — 검토 요청 보관 실패 중 이탈

- 검토자의 수정 의견 보관 실패 후 프로젝트 복귀로 화면을 떠나는 실패를 브라우저에서 재현했다. 요청 패널에서 작업실로 실패 상태가 전달되지 않아 도형 실패만 차단하고 있었다.
- 요청 묶음 보관 실패도 작업실 이탈 경고에 합쳤다. 다른 정보 탭에서 이탈을 시도한 경우 ‘요청 보관 상태 보기’로 원래 요청과 재시도 버튼을 다시 보여 준다. 재시도 성공 후 경고 해제와 기존 의견 저장을 확인했다.
- 브라우저 18개 통과, 1개는 STRUCTURE_PDF_PATH 미지정으로 건너뜀. 요청 기록 재열기·Viewer 읽기 전용·손상 기록 보호·도형 실패 복구 포함. 단위/SSR 64개, 타입 검사, 빌드 통과. 로컬 4181 반영, 운영 미배포.
- 전체 목표 진행 중. 원본 교체와 프로그램 방식 SPA 이동, 아직 요청에 포함하지 않은 대화 초안의 이탈 보호는 이번 검증 범위 밖이다.
# 후속 검증 — 미보관 작업과 원본 교체

- 도형 보관 실패 상태에서 다른 PDF 교체를 확인하면 도형이 초기화되는 실패를 브라우저에서 재현했다.
- 동일 원본 여부 확인 후, 다른 원본인 경우 최신 도형/요청 저장 실패 상태를 확인하여 교체를 차단한다. 동일 원본 재선택은 현재 상태를 유지하는 복구이므로 계속 허용한다. 원본 해시 계산 도중 상태가 바뀌어도 최신 실패 여부를 참조한다.
- 도형과 검토 의견 각각에 교체 시도 후 유지 확인을 추가했다. 도형 보관 재시도 성공 후 교체 가능 및 이전 저장 기록 유지도 검증했다.
- 실제 구조 PDF 포함 브라우저 20/20, 단위·SSR 64/64, 타입 검사·빌드 통과. 로컬 4181 반영, 운영 미배포. 전체 화면 목표는 진행 중이며 미요청 대화 초안 보호와 프로그램 방식 SPA 이동 보호는 남아 있다.
# 후속 화면 개선 — 프로젝트 검토 분류

- 프로젝트 검토에서 개정 기록과 항목별 변경 요청을 구분했다. 변경 요청이 존재해도 전체 요청이 없다고 보이던 개정 영역의 빈 상태 문구를 수정했다.
- 요청 묶음에 전체/확인 대기/수정 요청/확인 완료 필터와 상태 배지를 추가했다. 수정 의견이 하나라도 있으면 수정 요청으로 분류하며, 그 외 미확인 항목 유무로 대기/완료를 구분한다. 완료는 실제 승인이 아닌 예시 확인 상태다.
- 도면별 요청을 개정 번호 역순으로 표시하며 이전 묶음은 삭제하지 않는다. 문서 간 생성 시각 정렬은 수행하지 않는다.
- 필터 부재 RED 후 구현, 접근성 이름에 선택지까지 포함되는 문제를 브라우저로 확인하여 명시적 이름 부여. 프로젝트 브라우저 7/7, 프로젝트 단위/SSR 69/69, 타입 검사·빌드 통과. 로컬 4181 반영, 운영 미배포.
- 전체 목표 진행 중. 요청 필터의 도면 왕복 복원과 개정/요청 두 목록의 화면 우선순위는 추가 사용성 점검 대상이다.
# 후속 화면 개선 — 검토 목록 맥락 복원

- 확인 완료 필터→요청 열기→도면에서 프로젝트 복귀 시 전체 요청으로 초기화되는 실패를 브라우저에서 재현했다.

# 후속 화면 개선 — 변경 요청 우선 배치

- 브라우저의 실제 위치 비교로 변경 요청이 개정 검토 기록 아래 묻히는 상태를 확인했다. 검토 현황 제목 아래 변경 요청 묶음, 그 아래 개정 검토 기록 순으로 재배치했다.
- 기존 개정 로딩과 변경 요청 슬롯을 분리하여 요청 목록을 독립적으로 표시한다. 개정 기록 설명에서 기존의 잘못된 ‘아래 요청’ 안내도 제거했다.
- 프로젝트 브라우저 7/7(실제 화면 y 좌표로 순서 확인 포함), 프로젝트 단위/SSR 69/69, 타입 검사·빌드 통과. 1440×1000 빈 상태 화면을 시각 확인했다. 로컬 4181 반영, 운영 미배포.
- 전체 목표 진행 중. 현재 빈 요청 목록에서 도면 선택으로 이어지는 명확한 시작 안내와 긴 이력의 탐색/초점 복원이 추가 점검 대상이다.
# 후속 화면 개선 — 빈 검토 목록의 시작 동선

- 빈 요청 목록에서 다음 행동을 찾을 수 없던 상태를 테스트로 확인했다. 프로젝트의 실제 도면 목록을 펼쳐 선택하는 시작 안내를 추가했다. 임의 도면이나 요청은 생성하지 않는다.
- 선택한 도면은 기존 작업실에서 열리고 검토 목록으로 복귀한다. Viewer는 보기 가능한 범위와 편집자에게 요청할 내용을 안내하며 기존 읽기 전용 권한을 유지한다. 도면이 없는 경우 빈 도면·템플릿·파일 시작 안내를 표시한다.
- 빈 목록→지정 도면→검토 목록 왕복을 편집자·Viewer 각각 검증했다. 프로젝트 단위/SSR 69/69, 타입 검사·빌드 통과. 로컬 4181 반영, 운영 미배포. 전체 목표 진행 중.
