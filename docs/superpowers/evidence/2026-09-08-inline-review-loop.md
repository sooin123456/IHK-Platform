# 편집·검토 화면 흐름 수정

## 범위

사용자가 승인한 기존 PDF 화면 프로토타입의 편집·검토 구간만 수정했다. 실제 CAD 객체 편집, 영구 저장, 권한 서버 검증, 승인 전송, 배포는 포함하지 않는다. 도면 위 D01은 실제 문을 인식한 것이 아닌 별도 예시 도형이다.

## 변경

- 검토 모달과 `1 도면 → 2 검토 → 3 내보내기` 단계 표시를 이 진입 경로에서 제거했다. 내보내기/공유 모달은 기존대로 별도 제공한다.
- 같은 도면 옆 오른쪽 검토 패널과 명시적 작성자/검토자 체험 전환을 제공한다. 760px 이하에서는 도면 위, 검토 아래 배치로 도면을 가리지 않는다.
- 문 위치 변경 → 요청 → 작성자 대기 → 검토자 위치 의견 → 작성자 위치 확인/수정 → R2 재검토 → 승인 흐름을 연결했다.
- 요청 목적이 없거나 변경이 없는 요청을 막고, 작성자의 결정 및 검토자의 도형 변경을 막는다. 비교 확인 전에는 승인할 수 없다.
- 패널 전환 시 요청 문구를 보존하며, 새 파일을 선택할 때만 관련 화면 세션을 초기화한다.
- 승인 후 새 개정에서도 D01의 기존 도형과 페이지를 유지한다.

## 후속 목표: 같은 도면 안의 화면 연속성

사용자의 목표 설정 요청에 따라 기존 화면-only 원플로우 정리 목표를 설정했다.

- D01 객체 속성에 종류, 검토 오버레이 레이어, 고정 페이지와 개정, 읽기 전용 상태를 표시한다.
- I01은 검토와 댓글에서 같은 상태를 소비한다. 댓글에서 의견 위치 버튼을 누르면 기존 검토 패널과 같은 D01로 복귀한다.
- 개인 메모는 검토 요청 의견과 별도임을 명시한다.
- 도면 정보의 별도 편집기 이동 링크를 현재 도면의 편집·검토 체험 버튼으로 교체했다.
- 검토뿐 아니라 댓글·정보·도구 속성도 동일한 고정 패널을 쓴다. 모바일에서만 아래로 배치된다.
- 추가 실패 테스트 2개를 먼저 확인하고 구현했다. 기존 회귀 포함 54/54 통과. 타입 검사 포함 build exit 0.
- 최종 빌드 브라우저에서 D01 속성, 정보→같은 검토 복귀, 수정 요청→댓글의 I01→같은 위치 복귀, 모달 0개 확인. 390×844에서도 도면과 댓글을 동시에 표시하고 가로 넘침 없음(390=390). 캡처된 브라우저 error 로그 없음.
- 사용자의 기존 4181 탭을 작성자 ‘수정 요청’ 상태, ‘의견 반영 · 문 위치 재조정’ 버튼이 활성화된 상태로 남겼다. 임시 모바일 크기는 복원했다.

이 목표의 완료는 예시 객체 한 건을 사용하는 화면 흐름에 한정된다. 임의 객체 편집, 실제 파일 저장, 승인 이력 영구 보존, 실제 협업, 제품 전체 사용성 완성을 뜻하지 않는다.
