# DWG 가져오기 분석 작업 — 구현 및 검증 기록

2026-09-06 · 내부 개발 검증 · 운영 배포 아님

이번 단위의 구현·독립 검토·최종 검증을 마쳤다. 아래 구현 범위는 DWG 분석까지이며, 편집·재저장·납품 완료를 뜻하지 않는다.

## 구현 범위

검증된 DWG 업로드를 재시도 가능한 분석 작업으로 등록하고, 실제 읽기 엔진을 격리 실행한 결과를 PostgreSQL에 보존한다. 기존 ACadSharp 3.7.1, 격리 읽기 실행기, Supabase RPC와 PostgreSQL을 재사용했다. 새 npm/NuGet 의존성, 별도 큐 제품, 협업 서버, 유료 서비스는 추가하지 않았다.

성공 상태는 `analyzed`이며 모든 결과는 `qualification: experimental-unqualified`, `persistenceAuthority: not-issued`를 유지한다. 원본 바이트와 기존 도면 객체·변경 기록·원본 근거 연결·승인 행을 수정하지 않는다. 미완성 가져오기 버튼도 추가하지 않았다.

- 사용자·프로젝트·초안 도면·검증된 원본에 묶인 멱등 요청, 현재 편집 권한 재검사.
- RLS 및 명시적 권한, 서비스 DB 역할과 서비스 클레임의 동시 확인, 일반 사용자의 내부 테이블 직접 접근 차단.
- 프로젝트별 활성 작업 최대 5개, 작업별 시도 최대 3회, 고유 임대 토큰, 최초 처리 이미지 고정, 기한 만료·재시도·오래된 완료 요청 차단.
- 원본 200MiB, 분석 결과 32MiB 제한. 정확한 바이트 수·헤더·SHA-256·보고서 구조를 검사한 후 한 번 직렬화한 보고서의 해시로 저장한다.
- CLI 실행부터 실제 Supabase SDK 요청, 원본 다운로드, 격리 읽기, 결과 발행까지 연결. RPC와 원본 다운로드 모두 지정한 출처만 사용하고 리다이렉트를 거부한다.
- 전송 응답을 잃었을 때 성공 여부를 임의로 판단하거나 다른 결과로 재발행하지 않는다. 결과 재조회에서도 현재 권한과 저장된 해시를 검사한다.

최종 검증은 2026-09-06 09:48–09:49 KST에 코드 변경을 멈춘 상태에서 실행했다.

실제 Docker 통합 5개는 Node 합계에 포함되며 별도 중복 합산하지 않았다. 모든 명령의 표준 오류 출력이 비어 있고, 최종 검증 전후 계획 범위 코드 해시가 일치했다. [명령·코드·로그 해시와 파이프라인 증거](2026-09-06-native-dwg-import-jobs/verification.json), [Node 실행 로그](2026-09-06-native-dwg-import-jobs/node.stdout.log), [실제 DB 실행 로그](2026-09-06-native-dwg-import-jobs/real-postgres.stdout.log)를 보존했다.

두 처리자의 경쟁에서 하나만 작업을 획득했고, 정상 발행 후 새 사용자 요청으로 정확한 결과를 다시 읽었다. 잘못된 보고서 해시의 발행은 거부되어 결과 행이 남지 않았다. 원본 파일 및 기존 작업실 행은 변하지 않았고, 실행기의 컨테이너·설정 폴더·임시 검증 DB가 남지 않았음을 성공한 조회로 확인했다. 마지막으로 이 작업에서만 만든 PostgreSQL 컨테이너와 빈 설정 폴더를 제거했다. 이는 복원이 필요 없는 합성 검증 데이터이며 사용자 데이터는 제거하지 않았다.

개별 구현 검토, 지적 수정 재검토, 전체 단위 검토가 모두 통과했고 미해결 Critical/Important/Minor 지적은 없다. 필요한 검증 환경이 없을 때 필수 검사가 건너뛰지 않고 실패하는 경우도 별도로 확인했다.

실제 파이프라인 검사는 독립된 로컬 PostgreSQL과 실제 Linux 읽기 컨테이너를 사용한다. HTTP 부분은 실제 CLI·Supabase SDK를 실제 SQL RPC에 연결하는 **로컬 테스트 브리지**다. 실 PostgREST의 JWT 인증, Supabase Storage, 로그인한 브라우저 경로를 검증했다고 해석하면 안 된다.

고정 합성 DWG 원본: 10,987바이트, `AC1024`, SHA-256 `5c287281fafa07f76a0158d5374dd7577910c107dcb55817688acf9fd8656c71`.

기대 보고서: UTF-8 1,446바이트, SHA-256 `c01a5e9ebae2460de8781e90dda68a47dc8e3bf3a869d8be188d34adebc783cf`. LINE·CIRCLE·ARC·LWPOLYLINE·TEXT의 값과 핸들 `4A`–`4E`, 레이어 `3C`·`48`·`49`를 고정 기대값과 비교한다. 미지원 INSERT는 미지원으로 남긴다.

고정 읽기 이미지: `sha256:c67ff75cdacccad6cd77b275ad2557f889943bd29c98767c8f0e399d5e9b394f`.

검토 중 CLI 구성값을 엄격한 어댑터에 전달하는 조합 오류를 발견해 수정했고, 실제 자식 CLI를 실행하는 회귀 검사를 추가했다. 테스트 도구의 특수문자 경로 처리와 실패 시 정리도 보완했다. 사용자 변경이 포함된 기존 DB 검사 파일에 포맷 변경을 되돌리는 과정의 실수가 있었으나 즉시 중단하고, 작업 전 보존 사본과 해시가 일치하도록 복구한 뒤 최소 연결 부분만 다시 적용했다. 최종 검증은 모두 복구 및 수정 이후의 코드로 실행했다.

## 설계 판단

분석 증거부터 연결하고 도면 객체로 저장할 권한은 아직 발급하지 않는다. 이로 인해 다음 통합 단계가 남지만, 읽기 성공을 편집·납품 성공으로 오인하지 않게 한다. 기존 원본 없는 도면의 DWG 내보내기 조건을 넓히거나 DXF 근거로 대체하지 않았다.

권한이 철회된 완료 요청은 `PNI03`으로 거부하며 결과를 남기지 않는다. 이후 일치하는 실패 요청 또는 다음 작업 획득 시 종료 상태로 정리하므로 잠시 처리 중 상태가 남을 수 있다. 모든 권한 변경의 동시 실행 순서를 선형화했다고 주장하지 않는다.

Content-Length가 없는 정상 분할 전송도 허용하되, 실제 수신 길이와 독립적으로 검증된 원본의 길이·해시·헤더가 모두 일치해야 한다. 헤더가 있으면 엄격히 검사한다.

기존 미커밋 변경을 보존하기 위해 캡처한 작업 파일을 기준으로 검토했다. 이 선택은 로컬 검증 자료가 더 남는 비용이 있지만, 커밋·배포 권한을 임의로 확대하지 않는다. 독립 파일 소유권과 고정 RPC 계약 아래 DB와 작업 실행기 구현을 병렬 진행하고, 통합 검사는 양쪽 검토 후 실행했다.

## 남은 필수 개발

1. 분석 결과에서 서비스가 발급하는 네이티브 객체 근거와 `dwg_import` 저장 권한을 만들고, 실제 도면 객체·변경 이력·실행 취소·협업·복원과 연결한다.
2. 로그인한 사용자의 검증된 업로드 → 가져오기 → 편집 가능한 도면 흐름을 실제 인증·Storage·브라우저에서 검사한다.
3. 승인된 변경을 원본의 별도 복사본으로 DWG 재저장하고, 외부 CAD 및 수신자 기준으로 납품 적합성을 검증한다.
4. 실무 템플릿과 납품 패키지에 연결한다.

전체 Universal Workspace 목표는 활성 상태이며, 이번 단위만으로 DWG 편집·재저장·납품을 완료 처리하지 않는다. 운영 배포와 원격 데이터베이스 변경은 하지 않았다.
