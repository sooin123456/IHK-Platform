# Native DWG 5종 형상 재저장 — 개발·검증 기록

전체 Universal Workspace 목표는 **진행 중**이다. 이 단위는 가져온 DWG의 형상을 수정하고 기존 네이티브 writer로 다시 저장하는 필수 내부 경로를 확장한다. 승인된 재저장 작업·다운로드 UI 연결 또는 DWG 납품 자격 완료를 의미하지 않는다.

현재 상태: **이 개발 단위의 구현·독립 검토·로컬 검증 완료**. 최종 전체 검토의 중요 문제 2건을 한 번에 수정하고 별도의 범위 한정 재검토에서 승인받았다. 전체 목표·DWG 납품 자격·운영 배포 완료는 아니다.

## 실제 구현

- 기존 `buildNativeDrawingDwgSelectedEdits`와 ACadSharp 3.7.1 writer를 재사용했다. 새 엔진·의존성·협업 경로를 추가하지 않았다.
- LINE, LWPOLYLINE, CIRCLE, ARC, TEXT의 좌표·형상 변경을 `1hk-dwg-edits/2`로 컴파일하고 실제 DWG에 반영한다. 이전 v1 LINE/TEXT 요청은 계속 읽는다.
- 단위 변환 후에도 변경하지 않은 원래 좌표·반지름·텍스트 높이는 그대로 보존한다. 호의 360도 경계 통과와 완전한 한 바퀴를 0도로 축소하지 않는다.
- 동일 객체 집합·식별정보, 엄격한 JSON·Unicode·형상 범위·요청 크기·정점 수를 검증한다. 모든 대상과 결과를 검사한 뒤 한 번에 변경한다.
- 원본과 작업 사본의 SHA를 확인하고 새 출력 경로에 저장한다. 기존 handle·owner·layer를 유지하며, 알려진 미지원 데이터 손실은 저장 전에 차단한다.
- 실제 앱 명령 → 실제 가져오기 projector → 컴파일러 → CLI writer → DWG 재읽기를 연결한 통합 테스트를 추가했다. 별도 가짜 writer를 사용하지 않는다.

## 검토에서 보완한 사항

1. 밀리미터 좌표가 원본 단위로 변환되면서 서로 다른 두 정점이 같은 값으로 축소되는 경계값을 차단했다. RED 40통과/1실패 → GREEN 41/41, 독립 재검토 승인.
2. 루트 사전·블록만 검사하면 놓치는 일반 객체의 확장 사전까지 검사한다. 엔진의 전체 보존 객체 레지스트리와 순환 참조를 안전하게 순회한다.
3. 폴리라인 수정 시 기존 정점을 전부 새로 만들어 식별정보를 지우던 경로를 고쳤다. 대응하는 인덱스의 정점 인스턴스는 유지하고, 추가·삭제된 정점만 해당 형상 변경으로 처리한다.
4. 실제 pinned writer가 0이 아닌 정점 ID를 파일에 보존하지 못함을 확인했다. 메모리에서만 유지하는 것을 납품 보존으로 주장하지 않는다. 해당 ID가 원본의 대상/비대상 객체에 있으면 v2 재저장을 차단한다. 이를 처리할 writer 검증은 전체 R4의 남은 필수 항목이다.
5. 최종 검토에서 300도 시작의 완전한 한 바퀴가 부동소수점 덧셈으로 엄격한 2π 상한을 넘는 것을 재현했다. 상한을 넘게 반올림된 끝값만 바로 이전 표현 가능 값으로 보정하고, 양의 한 바퀴 이하·오차 1e-9 이내를 확인한다. loader/reader 규칙은 완화하지 않았다. 실제 CLI 거절 RED → DWG 저장·재읽기·실제 projector의 300도/360도 복원 GREEN을 확인했다.
6. TEXT 내용·높이가 바뀌면 기존 표시 너비로는 저장 후 범위를 판단할 수 없었다. 최종 native geometry를 기존 projector로 미리 검증한다. 이 내부 임시 보고서는 반환하거나 원본 근거로 저장하지 않는다. mm/cm·명시 단위 선택에서 내용/높이 증가, 앞선 정상 편집이 있는 일괄 실패, 입력 불변 회귀를 추가했다.

## 증거와 지원 범위의 한계

- 합성 파일의 **실제 로컬 동일 엔진** 저장·재읽기 증거다. 실제 로그인·DB·Storage·worker·브라우저 납품 통합, 독립 CAD 수신자의 열기/재저장/출력 또는 고객 도면 호환성 검증은 아니다.
- unknown/proxy는 pinned writer가 payload를 보존하지 못한다. 실제 ACadSharp 메모리 그래프의 사전/확장 사전/연결 객체 차단을 시험하며, writer가 이미 제거한 파일을 unknown 원본 증거로 사용하지 않는다.
- 정점 ID 손실은 실제 writer/readback으로 특성을 확인한다. 차단은 실제 source read 후 구성한 메모리 그래프에서 검사한다. 정점 ID를 가진 외부 DWG 입력 코퍼스 검증은 아직 없다.
- 일부 알려진 비대상 엔티티·블록·레이어 등의 목록을 비교하지만 모든 폰트·배치·Xref·XData·사전·헤더·출력 품질의 완전 보존을 입증하지 않는다.
- pinned 엔진은 전체 객체 열거용 공개 API가 없다. 검증한 private registry 필드에 단일 .NET8 accessor를 사용한다. 접근 계약이 깨지면 부분 검사로 대체하지 않고 저장을 실패시킨다. 엔진 업그레이드 시 재검증이 필요하다. [ACadSharp 3.7.1 소스](https://github.com/DomCR/ACadSharp/blob/v3.7.1/src/ACadSharp/CadDocument.cs), [.NET accessor 문서](https://learn.microsoft.com/en-us/dotnet/api/system.runtime.compilerservices.unsafeaccessorattribute).
- 요청 결과는 `experimental-unqualified`, `not-issued`; 산출물은 `not-qualified`, 독립 CAD 검증은 `not-performed`를 유지한다. 기존 승인된 source-free 내보내기 제한을 완화하지 않았다.

## 사용자 작업 보존

HEAD `9f5f56d93db325ff935772252f9d4fb64d69f98c`와 빈 index를 유지했다. 이 단위의 10개 구현·시험·README 파일 밖에서 기존 dirty 기준 759개 파일의 변화 및 예상 밖 새 파일이 없음을 확인했다. 앞선 작업실 가져오기 24개 파일도 모두 해시가 일치한다.

기존 검증 원본 `2026-09-06-native-dwg-import-projection/accepted-code/synthetic-source.dwg` SHA-256은 `5c287281fafa07f76a0158d5374dd7577910c107dcb55817688acf9fd8656c71`로 동일하다. 이번 새 생성 파일과 세 재저장 파일의 해시는 실제 바이트에서 다시 확인했으며, 별도의 통합 요약에 기록했다. `git diff --check`도 통과했다.

새 dependency, SQL, 원격 DB·Storage 변경, stage/commit/push/배포는 없다. 사용자의 4173 미리보기는 조작하지 않았다. 시험용 일회성 Vite/Chromium과 생성 파일을 실제 서비스 또는 고객 데이터로 취급하지 않는다.

## 대신 내린 판단과 비용 — Rulings I made

1. 기존 승인을 유지하고 추가 승인·커밋·배포를 묻지 않았다. 이번 권한은 개발까지다. 잘못 판단했다면 다음 개발 범위 조정 비용이 있다.
2. v2 계약과 파일 소유권을 먼저 고정하고 TS/C# 구현을 병렬 수행했다. 잘못 분리했다면 통합 재작업 비용이 있다.
3. v1은 유지하고 확장 요청은 v2로 분리했다. 미지원·unknown 손실은 차단하되 전체 R4 성공 조건을 줄이지 않았다. 일부 파일은 보존 가능한 엔진 검증 전까지 사용할 수 없는 비용이 있다.
4. 커밋되지 않은 사용자 변경의 복구를 위해 기존 작업공간·private 기준/차이/바이너리를 보존했다. 제한된 로컬 기록이 남는다.
5. 요청 자체뿐 아니라 비대상 정점을 포함한 최종 문서의 정점 한도를 검사했다. 큰 도면은 더 넓은 reader/writer 검증 전까지 거절되는 비용이 있다.
6. 에이전트 수 제한으로 원래 엔진 작성자를 재개하지 못해 해당 검토자를 수정 담당으로 전환했다. 편향 위험은 별도의 독립 재검토로 확인했고 승인받았다.
7. 전체 보존 객체 검사를 위해 pinned private registry 접근을 제한적으로 허용하고, writer가 잃는 비영(非零) 정점 ID는 차단했다. 엔진 버전 변경이나 해당 데이터가 있는 도면에는 추가 어댑터·writer 검증 비용이 있다.

Superpowers의 테스트 우선·원인 추적·독립 검토를 적용했다. Ponytail은 기존 컴파일러·reader·writer·명령 경로와 고정된 오픈소스 재사용에 반영했다. 원본 보존과 납품 검증은 단순화 대상이 아니다.

## 다음 필수 개발

1. 가져온 DWG의 승인 개정·원본 SHA·단위·객체 매핑을 재저장 요청 권한과 결합한다.
2. 격리된 writer 실행 → 변경 불가능한 산출물 영수증 → 권한 재검증 다운로드 → UI 상태/재시도까지 연결한다.
3. 실제 인증 브라우저의 가져오기·저장·새로고침·재로그인·그룹 실행 취소·역할 권한을 검증한다.
4. unknown/proxy·정점 ID 등 손실이 있는 엔진 범위를 해결하고 실제 고객/독립 CAD 수신 코퍼스로 납품 자격을 확인한다.
5. 기존 데이터 업그레이드 리허설, 실무 템플릿·같은 승인 개정의 DWG/PDF/견적 납품 패키지(R5), 실제 사용자 흐름·성능·복구 검증을 완료한다.

이 항목들이 남아 있으므로 전체 목표·DWG 납품·운영 적용 완료로 표시하지 않는다.
