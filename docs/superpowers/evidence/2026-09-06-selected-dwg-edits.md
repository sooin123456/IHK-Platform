# 기존 DWG의 명시적 객체 편집 기반

2026-09-06 · 로컬 개발/검증 · 운영 배포 아님

## 구현

기존 ACadSharp 3.7.1/.NET 변환기의 `qualify` 흐름을 확장했다. 새 엔진·패키지·협업 서버는 추가하지 않았다.

- 편집 요청이 없으면 무편집 왕복만 실행한다. 첫 번째 선·텍스트를 임의로 바꾸던 동작을 제거했다.
- 원본 SHA-256, 명시적 DWG handle, 원본 단위의 WCS 좌표로 모델 공간 LINE 끝점과 일반 TEXT 값을 지정한다. 대상 전체를 검사한 후 적용하므로 잘못된 뒤쪽 대상 때문에 앞 객체만 바뀌지 않는다.
- 요청 크기·개수·좌표·문자 제한, 중복/미지원 필드와 대상·잘못된 해시·Unicode를 검증한다. 요청 바이트와 해시를 보존하고 원본 파일은 수정하지 않는다.
- 재저장 후 현재 검사 가능한 모든 필드를 요청 적용 상태와 비교한다. 선택한 객체라는 이유로 geometry 전체를 검사에서 제외하지 않는다.
- 추가로 LINE 방향값과 TEXT 스타일·INSERT 블록 참조를 검사한다. 숫자가 포함된 이름을 좌표처럼 비교해 다른 참조를 같은 것으로 판단하던 문제를 재현·수정했다.

## 확인한 결과

- 자체 검사 15개 통과. 원치 않은 자동 편집, 첫 번째가 아닌 대상 선택, 요청 거부, 전체 대상 사전 검증, 방향·참조 변경 검출을 포함한다.
- 기존 네이티브 DWG 생성 회귀 검사 13개 통과.
- Release 빌드 성공, 경고·오류 0.
- 독립 검토의 참조 비교 지적을 실패 검사로 재현한 뒤 수정했고 재검토에서 승인받았다.
- 실제 생성한 AC1024 시험 파일에서 지정한 선·한글 문자를 변경하고 다시 읽었다. 현재 inventory의 나머지 필드는 그대로였고 원본·작업 복사본·요청 바이트 보존을 별도 검사했다.

## 완료로 보지 않는 범위

이 결과는 **같은 엔진으로 만든 시험 도면의 내부 검증**이다. 일반 스타일, 속성, 레이아웃/뷰포트, XData 등 보존 범위가 아직 불완전하며 결과는 `passed-with-inventory-gaps`, 납품 자격은 `not-qualified`다. 독립 CAD 검증이나 실제 고객/납품처 수용 확인은 수행하지 않았다.

앱의 DWG는 아직 기타 파일 보관 경로다. 다음 필수 작업은 원본·handle·공간·좌표 변환을 보존하는 DWG 가져오기/mapping, 기존 operation·권한·승인 개정 연결, 원본 기반 재저장 작업과 납품 묶음이다. 기존 DXF 변환이나 새 네이티브 도면 출력으로 이를 대체하지 않는다. 전체 목표는 진행 상태이며 운영 DB·배포는 변경하지 않았다.
