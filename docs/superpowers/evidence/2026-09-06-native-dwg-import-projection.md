# DWG 읽기 → 작업실 객체 수정 → 네이티브 재저장 연결

2026-09-06 · 내부 개발 검증 · 운영 배포 아님

## 현재 범위

기존 ACadSharp 3.7.1을 재사용하여 실제 DWG를 읽고, 원본 SHA·네이티브 핸들을 유지한 작업실 객체로 변환한다. 그 객체의 선 끝점·텍스트 변경을 원래 DWG 핸들에 적용할 요청으로 다시 만들고, 기존 복사본 재저장 기능으로 연결한다. DXF 중간 파일이나 `dxf_entity` 근거를 사용하지 않는다.

이 결과는 **브라우저에서 고객 DWG를 가져와 승인·납품하는 기능의 완료가 아니다.** 새 경로는 공개 화면에 연결하지 않았고 DB 저장 권한도 발급하지 않는다. `experimental-unqualified`, `persistenceAuthority: not-issued`를 유지한다.

## 실제 연결 결과

독립 검토에서 찾은 문제를 수정한 뒤 실제 연결을 다시 실행해 성공했다. 최종 수정의 독립 재검토도 통과했다. 이전 실행 파일은 그대로 보존하고, 아래 최종 검증 파일은 `accepted-code/`에 별도로 기록했다.

- 실제 합성 DWG 10,987바이트, AC1024.
- 모델 공간 6개 중 LINE·CIRCLE·ARC·LWPOLYLINE·TEXT 5개를 작업실 스키마로 변환. INSERT 1개는 미지원으로, 블록 내부·도면 공간 객체 3개는 별도로 집계.
- 작업실 선 수정 → 원본 핸들 `4A`, 시작 `[10,-5,0]`, 끝 `[137.5,25,0]`.
- 작업실 텍스트 수정 → 원본 핸들 `4E`, `현장수정 A-101`.
- 네이티브 복사본 재저장 후 같은 핸들·변경값을 다시 읽어 확인. 원본 파일 SHA 불변.
- 변경되지 않은 원본 좌표는 표시용 반올림값으로 덮어쓰지 않는다. 미지원 객체 변경·새 객체·삭제·지원하지 않는 속성 변경은 일부만 적용하지 않고 요청 전체를 거부한다.
- 재저장 비교 결과는 `passed-with-inventory-gaps`다. 같은 엔진의 내부 검사이므로 독립 CAD 판독·출력·수신자 승인을 대신하지 않는다.

산출물: [최종 연결 증거](2026-09-06-native-dwg-import-projection/accepted-code/evidence.json), [읽기 보고서](2026-09-06-native-dwg-import-projection/accepted-code/native-import.json), [명시적 수정 요청](2026-09-06-native-dwg-import-projection/accepted-code/edit-request.json), [테스트 결과와 코드 해시](2026-09-06-native-dwg-import-projection/verification.json). 합성 원본과 재저장 DWG도 같은 폴더에 보존했다. 고객 파일·인증정보는 포함하지 않는다.

최종 합성 원본 SHA-256은 `5c287281fafa07f76a0158d5374dd7577910c107dcb55817688acf9fd8656c71`, 재저장 복사본은 `aca81c01c8d9de5490cb41433ebca5e7370870ecf7f101f47cc3852d7c26aebd`다. 원본은 변경되지 않았다.

## 검증

확인된 검사:

| 검사 | 결과 |
| --- | --- |
| 새 읽기·변환·수정 요청 + 기존 내보내기 관련 Node 테스트 | 138 통과, 실패·건너뜀 0 |
| 새 읽기 포함 네이티브 self-test | 24 통과, 실패 0 |
| 기존 네이티브 생성기 self-test | 13 통과, 실패 0 |
| 실제 DWG → Node 읽기 → 작업실 객체 → 수정 요청 → 복사본 재저장 → 다시 읽기 | exit 0 |
| 애플리케이션 타입 검사 | exit 0 |

실제 .NET 읽기 테스트는 실행 때마다 합성 DWG를 직접 생성한다. 실행 파일이나 빌드가 없으면 건너뛰지 않고 실패한다. 네이티브 Release 빌드는 경고·오류 0건이다. 기존 의도적 거부 테스트는 예상 오류 문구를 출력한다. 오류 없는 로그로 포장하지 않는다.

재현 명령(저장소 루트, 기존 로컬 의존성과 Release 빌드 필요):

```sh
NODE_OPTIONS=--no-experimental-webstorage node .superpowers/sdd/2026-09-06-native-dwg-import-projection/verify-final-node.mjs
NODE_OPTIONS=--no-experimental-webstorage node .superpowers/sdd/2026-09-06-native-dwg-import-projection/verify-regressions.mjs
NODE_OPTIONS=--no-experimental-webstorage node .superpowers/sdd/2026-09-06-native-dwg-import-projection/verify-native-continuity.mjs <새로운-증거-폴더명>
```

세 명령 모두 exit 0을 확인했다. 마지막 명령의 폴더명은 영문 소문자·숫자·하이픈 1~40자이며, 기존 결과를 덮어쓰지 않는다.

## 검토로 보완한 오류

- 불완전 UTF-16 텍스트, 비ASCII DWG 헤더 바이트, 일치하지 않는 미지원 표본 수를 거부한다.
- 360도 ARC와 표시용 PLINEGEN 플래그를 보존하고, 한 바퀴를 넘는 원호 보고서는 조용히 축약하지 않고 거부한다. 구형 폴리라인도 전체 정점 수 제한에 포함한다.
- 동일 출력 경로의 동시 실행에서 패배한 작업이 성공한 보고서를 삭제하지 않는다. Node 정리 경로의 디렉터리 교체도 식별한다. 이는 동일 OS 사용자 공격까지 막는 보안 격리 주장은 아니다.
- 읽기 오류를 복구하며 진행하는 엔진 기본값을 끄고, 엔진이 지원하는 미지 객체 보존 옵션을 명시했다. [고정 버전의 공식 구성 소스](https://raw.githubusercontent.com/DomCR/ACadSharp/v3.7.1/src/ACadSharp/IO/CadReaderConfiguration.cs)가 기본 복구 동작의 객체 누락 가능성을 명시한다. 집계는 엔진이 실제로 구성한 객체 범위이며, 모든 바이너리 객체·프록시의 보존을 증명하지 않는다.
- 실제 CLI 분기, 손상 DWG 거부, 동시 출력, 실제 읽기·수정·재저장을 회귀 테스트로 확인한다.
- ATTDEF 속성 정의를 일반 TEXT로 잘못 분류하지 않는다. 실제 DWG에 ATTDEF와 TEXT를 함께 넣어 각각 미지원·지원으로 구분하는 검사를 추가했다.
- 읽기 보고서의 텍스트 제한을 네이티브 읽기·수정과 일치시켰다. 제어문자·줄/문단 구분자·CAD 표현식과 UTF-16 10,000단위 초과 입력을 거부한다. 화면 너비 추정에는 별도로 Unicode 문자 수를 사용한다.

개별 사양·품질 검토와 전체 연결 검토 후, 최종 두 지적(ATTDEF 분류·텍스트 정책)을 수정했다. 독립 재검토에서 모두 해결됨을 확인했고 새 지적은 없었다. 이 승인은 위 내부 개발 범위에 한정하며 제품 출시·운영 보안·전체 DWG 호환성 승인이 아니다.

## 남은 필수 연결

1. 고객 입력을 처리할 작업자의 파일·네트워크 격리와 CPU·메모리 제한. 현재 시간·출력 제한과 최소 환경 변수는 OS 보안 샌드박스가 아니다.
2. DWG 전용 가져오기 작업/완료 기록, 서비스가 발급하는 `dwg_entity` 근거, 저장·실행 취소·협업·복원 경로.
3. 기존 파일/작업실 화면의 가져오기·미지원 항목 안내와 실제 로그인 후 편집·새로고침 검증.
4. 승인된 변경만 원본 DWG 복사본에 적용하는 서버 경로. 다른 객체·블록·레이아웃·스타일 보존과 지원 범위 확대.
5. 외부 CAD·실제 도면·수신자 기준 납품 검증, 의존 파일을 포함한 최종 납품 패키지.

기존 원본 업로드, DXF 검증과 원본 없는 승인 도면의 DWG 내보내기 권한 조건은 변경하지 않았다. 새 패키지·유료 계약·원격 DB 변경·배포는 없다. 전체 목표는 활성 상태다.
