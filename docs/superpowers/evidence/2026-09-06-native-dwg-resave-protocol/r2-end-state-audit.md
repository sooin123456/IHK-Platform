## Smallest missing genuine end-to-end proof

1. **Extend the existing estimator restoration scenario to exercise real logout.** After the current online save, capture the created document/revision identity, exact active line/area/count objects and their classified properties, calibration/units used by those objects, and the actual estimate binding/result rows. Navigate through the visible logout control, verify the canonical workspace requires authentication, then authenticate the same user through the existing app-confirmation helper and enter through the workspace/recent drawing UI. Assert the same identity and complete saved work/binding, including **all three W-001/F-001/D-001 rows after login**. Retain the fresh-context check because it separately proves restoration from the server. No password/email delivery infrastructure or expanded product feature is needed.

2. **Strengthen the existing offline scenario's oracle and client observations.** Before going offline, capture exact selected-object geometry/version and relevant operation IDs. Record an independently known expected geometry for the keyboard move and verify the local offline UI reflects that change. Reconnect without reloading first, assert Owner and Editor each render that expected geometry, assert the authoritative object/operation forward payload equals that expected change, and retain the existing one-operation/acked metadata checks. Reload both connected pages and repeat exact geometry/identity equality and no duplicate operation checks. Assert stable connected state through this phase, with phase-scoped browser request failures and server closure evidence. Perform this after the already assigned honest bootstrap replay fix; existing protected-state rejection guards remain required.

These are two extensions to existing authenticated scenarios, not a new broad test framework. A narrowly controlled reconnect retry or pending-outbox recovery variant may be valuable if the active fix specifically changes that lifecycle, but universal offline shell navigation, every primitive combination, and a new browser persistence product are not prerequisites invented by this audit. Likewise, the requirement says same request ID; preserving creation intent across a fresh start-page visit is not silently added here.

## Concrete defects and limitations found

- **Test coverage defect: the offline geometry oracle is not independent.** At `platform/e2e/drawing-workspace-m1-estimator.spec.ts:8423`, the test reads the resulting server geometry and uses that very geometry as the Editor expectation at `:8436`; there is no expected pre-offline-plus-move comparison. A wrong-but-consistent geometric result can therefore pass the current geometry assertion. This is an acceptance-test defect, not proof of a second production data-loss bug.
- **Test coverage defect: explicit logout is unexecuted.** Fresh-context replacement at `platform/e2e/drawing-workspace-m1-estimator.spec.ts:4158` bypasses `platform/app/features/auth/screens/logout.tsx:7`. The test title's “relogin” describes new authentication, but cannot certify the full logout/restoration transition.
- **No additional production defect is confirmed by this bounded inspection.** Current outbox entries are filtered by owner and revision (`platform/app/lukas/lib/drawing-outbox.ts:293`), Yjs database names include both (`platform/app/lukas/lib/drawing-yjs-persistence.client.ts:16`), and local command ordering persists the outbox before Yjs/provider mutation (`platform/app/lukas/lib/drawing-collaboration-client.ts:476`). These are relevant implementation supports, not end-to-end zero-loss proof. The pre-existing replay defect remains a separate confirmed production issue.
- Quick-start request IDs are regenerated on loader visits (`platform/app/lukas/screens/workspace.tsx:326`), while action failures return the submitted identity (`:397`) and the form reuses that failure identity (`platform/app/lukas/components/workspace-quick-start.tsx:70`). This supports exact retry on the retained form; no stronger reload-stable creation contract is assumed.

Do not promote the 23/23 report to “R2 complete” until the actual logout/restoration assertions and independently checked reconnect state pass in the authenticated disposable runtime, with the known replay defect resolved and unexplained runtime failures accounted for. This audit itself supplies source evidence only; it does not claim those new checks passed.
