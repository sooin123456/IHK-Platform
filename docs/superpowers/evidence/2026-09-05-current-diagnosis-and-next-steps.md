## 확인된 오류와 수정

1. 대시보드 날짜의 기본 시간대 차이로 발생했던 React hydration 오류는 앞선 운영 배포에서 `Asia/Seoul` 고정으로 수정되었다.
2. 견적 연결 폼의 `useState(() => crypto.randomUUID())`는 같은 입력에도 서로 다른 초기 HTML을 만들었다. 반복 렌더 비교로 재현한 뒤, 빈 hidden input을 렌더하고 제출 순간에만 UUID를 채우도록 수정했다. 같은 폼의 재시도에는 기존 UUID가 유지되며, 서버의 역할·개정·BOQ 검증은 그대로다. 이 항목은 초기 HTML 불일치 보완이며 단독으로 운영 오류 화면의 원인이라고 주장하지 않는다.
3. 일부 M1 브라우저 증거 수집이 인증 페이지 이동 뒤에 시작되어 첫 로딩 오류를 놓쳤다. 기존 context 수집기를 인증 전에 연결하고 재로그인·Viewer context에도 적용했다. 의도적으로 끊는 업로드/검증 요청의 필터와 기존 검증 조건은 유지했다.

앞선 배포에서 DXF 마이그레이션 `20260905014005`와 `20260905014006`은 운영에 적용하고 테이블·함수·실행 권한·트리거를 확인했다. 기존 계획의 미체크 항목만으로 미배포라고 판단하면 안 된다. 다만 운영에서 실제 DXF를 새로 가져오고 우회 요청 거부와 재시도를 검증하는 항목은 여전히 별도 미실행이다.

1. 운영 전용 검증 프로젝트에서 로그인 → 프로젝트 생성 → PDF/DXF 업로드 → 작업실 연결 → 저장 → 재로그인, 그리고 Viewer 거부를 끝까지 검증한다.

4. 사용 허가가 확인된 실제 도면과 회사 템플릿으로 정확한 도형·단위·원본 SHA·물량/금액·현장 업무를 검증한다. 현재 OSS 예제 검증은 고객 수용 검증과 구분한다.
5. 격리된 관리형 백업 복구를 실행하고 공급자가 선택 백업과 복구 대상의 관계를 증명하도록 연결한다. 운영 성능 변동과 UI 사용성도 이 출시 게이트에서 확인한다.
