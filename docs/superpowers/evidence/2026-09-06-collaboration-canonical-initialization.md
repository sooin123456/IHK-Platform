# 최초 협업 상태 저장·재접속 수정 — 검증 기록

빈 도면을 아무 편집 없이 열었다 닫아도 최초 협업 상태가 저장되도록 수정했다. 여러 접속이 동시에 초기 상태를 만들면 DB가 하나만 저장하고 모두 그 저장본을 사용한다. 브라우저 접속, 검토 처리, 작업 결과 수신의 세 경로에 동일한 절차를 적용했다.

Viewer는 신뢰된 초기 저장본을 만들고 읽을 수 있지만 일반 편집은 계속 차단된다. 승인 상태와 기존 검토 잠금은 덮어쓰지 않는다. 검토 잠금 중 아직 저장되지 않은 상태는 첫 접속에 전달하지 않으며, 재시도 구분값 `drawing-reconciling`을 실제 WebSocket으로 전달한다. 실패한 문서·연결도 정리한다.

## 검증 결과

| 확인 | 최종 결과 |
| --- | --- |
| 협업·권한·검토·캐시 프로토콜 회귀 | 157/157 통과 |
| 기존 도면·이슈·앵커 검사 | 17/17 통과 |
| 실제 PostgreSQL·서버·WebSocket 통합 | 1/1 통과 |
| 협업 TypeScript | 오류 없음 |
| 로컬 Supabase 보안 advisors | 결과 없음 (`results: []`) |
| 작업별·최종 독립 검토 | 승인, 남은 지적 없음 |

서로 다른 검사는 **175개**이며 반복 실행을 중복 합산하지 않았다. 의도된 접속 거부 진단과 기존 PostgreSQL 긴 식별자 NOTICE는 로그에 보존했다.

실제 통합 검사는 수정 전 코드에서 ‘Viewer 동기화 후 저장본 없음’을 재현했다. 수정 후에는 편집 없이 버전 1·366바이트가 저장됐고, 새 서버에서 캐시를 재전송해도 저장 바이트·해시·버전이 동일했다. 유효한 Viewer 편집은 `P3A02`로 거부되고 보호된 메타데이터 위조도 차단됐다. 검토 잠금 해제 후 명시적 토큰 재전송과 동기화 재개도 별도로 검증했다.

이 통합 검사의 신원 확인은 고정된 로컬 테스트 토큰을 사용한다. 실제 Supabase 로그인/JWKS와 브라우저 IndexedDB 전체 검증을 통과했다는 뜻은 아니다.

## 변경과 남은 범위

프로덕션 3개·테스트 4개 파일을 수정했다. 새 의존성이나 원본 도면 변경은 없고, 기존 DWG 검증 대상 17개 파일의 해시도 유지했다. 미리보기는 기존 4173/PID80284·HTTP200을 유지했다. **운영 배포와 미리보기 재빌드는 하지 않았다.** 적용 시 DB 마이그레이션을 협업 서버보다 먼저 배포해야 한다.

R2에는 화면의 자동 재시도 처리, 이미 어긋난 과거 캐시의 안전한 복구, 접속 중 상태 전환의 저장 보장, 실제 로그아웃·두 사용자 오프라인 복원이 남아 있다. DWG 재저장 작업·취소·결과 다운로드·수신 CAD 검증(R4), 승인본 기반 DWG/PDF/BOQ 납품 패키지(R5)도 전체 목표에서 계속 진행한다. [다음 DWG 작업의 코드 조사](2026-09-06-native-dwg-resave-job-followup.md)는 준비 자료이며 구현 완료가 아니다.
