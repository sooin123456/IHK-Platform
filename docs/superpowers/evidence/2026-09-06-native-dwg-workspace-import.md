# Native DWG 작업실 가져오기 — 개발·검증 기록

전체 Universal Workspace 목표는 **진행 중**이다. 이번 단위는 DWG 분석/편집 가져오기를 실제 프로젝트 진입, 작업실 UI, 기존 복구 전송 경로에 연결한다. DWG 재저장·납품 완료 또는 운영 배포를 의미하지 않는다.

현재 상태: **이번 개발 단위 구현·검토·로컬 검증 완료**. 최종 검토의 중요 문제 1건을 수정한 뒤 독립 재검토에서 승인받았다. 운영 배포나 전체 목표 완료는 아니다.

## 구현 범위

- 검증된 프로젝트 DWG를 선택해 빈 작업실로 진입하거나 기존 작업실에서 가져오기. DWG를 DXF로 위장하거나 PDF/IFC 배경으로 취급하지 않는다.
- 단위 선택 → 분석 요청 → 대기/처리/실패/분석 완료 표시 → 사용자가 명시적으로 편집 객체 가져오기.
- 요청 전에 작은 분석 식별정보만 로컬에 보관한다. 응답 유실/새로고침 후 같은 요청·작업을 재개하며, 저장소 오류가 있으면 복구 가능하다고 표시하지 않는다.
- 오프라인/권한 변경/다른 개정·캔버스로 이동 시 진행 중 조회를 중단하고 늦게 도착한 응답은 적용하지 않는다.
- 기존 명령 큐, Yjs, durable outbox를 사용한다. 별도 도면 상태 저장소나 협업 전송 경로를 만들지 않았다.
- 공통 CAD 클라이언트로 DXF 구현을 재사용한다. DWG 원본·작업·보고서 식별정보와 순서가 정확한 서버 준비 연산을 검증하고, 복구 전송도 서버 재확인을 거친다.
- 서버는 인증된 사용자와 현재 프로젝트/문서/개정/캔버스, 검증된 원본 SHA를 사용한다. 브라우저가 보낸 보고서나 영수증을 권한 증거로 받지 않는다.
- 지원 범위와 DWG 재저장·납품 호환성 미검증을 UI에 명시한다. 기존 내보내기 차단 조건은 완화하지 않았다.

## 검토에서 고친 문제

1. HTTP 응답을 스키마로 변환하면서 예상 밖 필드를 제거하면 준비 연산 변조를 놓칠 수 있었다. 원래 입력과 파싱 결과를 정확히 비교하고 원본 연산을 보존하도록 수정했다.
2. DXF 검증기와 DWG 검증기를 연속 호출하면 다른 형식의 정상 가져오기까지 거절했다. 자기 형식만 검증하고, 서로 섞였거나 한쪽 메타데이터만 있는 연산은 계속 거절한다. 실제 조합 회귀 테스트를 추가했다.
3. 최종 검토: DWG 요청 URL이 선택한 개정을 누락하여 최신 개정이 아닌 편집 가능한 초안에서 충돌할 수 있었다. 활성 개정을 URL에 보존하는 한 줄 수정과 실제 JSX 생산자/route action/파서 실행 회귀를 추가했다. 세 요청 모두 RED 0/3 → GREEN 3/3이며, URL/폼 개정이 다를 때 409 차단도 유지한다. 인증·DB·worker는 경계 대역이므로 실서비스 통합 테스트로 분류하지 않는다.

최종 세 검사에서 실행 중 코드 해시 변화는 없었다. [검증 요약 JSON](2026-09-06-native-dwg-workspace-import/verification.json), [최종 코드 24개 해시](2026-09-06-native-dwg-workspace-import/accepted-files.json), `checks/*/result.json`에 정확한 명령·종료 코드·시각·해시를 기록했다. 원본 코드 스냅샷은 동반 폴더의 `accepted-code/`에 있다. 아래 한계와 남은 게이트를 유지한다.

### 증거의 범위

- 브라우저 테스트는 **실제 React 컨트롤 + 제어된 HTTP 응답**이다. `onPrepared`는 호출을 기록하는 테스트 경계이므로, 실제 로그인부터 전체 편집기 영속화까지의 통합 증거가 아니다.
- Node 테스트는 실제 준비/명령/클라이언트/복구 로직과 경계 대역을 구분해 사용한다. 이전 실제 reader/PostgreSQL 증거는 [이전 canonical import 기록](2026-09-06-native-dwg-canonical-import.md)에 있으며, 이번 브라우저 증거로 재분류하지 않는다.
- 전체 앱 미리보기는 합성 데이터로 데스크톱 1440px·모바일 390px·홈을 확인했다. HTTP 200, 캔버스 표시, 오류 오버레이/가로 넘침/페이지·콘솔 오류 없음. 화면의 협업 연결 문구는 실제 운영 연결 증거가 아니다.
- 첫 cold Vite 확인은 의존성 최적화 중 준비 상태를 기다리다가 시간 초과했다. 코드 수정 없이 진단 및 후속 확인은 통과했지만, 최초 실패를 삭제하거나 정확한 원인이 확정됐다고 주장하지 않는다.
- 앱 미리보기 캡처는 최종 개정 URL 수정 **이전**이다. 변경 후 타입/빌드/회귀 테스트와 구분한다.
- 빌드의 기존 경고: 비어 있는 서버 전용 route chunk, 500KB 초과 bundle, 동일 서버 모듈의 static/dynamic 혼용, 비민감 theme cookie 서명 경고. 마지막 경고를 새 인증 세션 취약점으로 해석하지 않는다. 앞선 브라우저 실행의 NO_COLOR/FORCE_COLOR 경고는 검사 실행 환경에서 해소했다.

## 대신 내린 판단과 비용 — Rulings I made

1. 기존 구현 승인을 유지하고 추가 승인·커밋 선택을 묻지 않았다. 커밋/배포는 하지 않는다. 잘못 판단했다면 다음 개발 범위를 좁히는 재조정 비용이 있다.
2. 파일 소유권과 인터페이스를 고정해 독립 작업을 병렬 수행했다. 잘못 나눴다면 통합 재작업 비용이 있다.
3. 분석 식별정보만 localStorage에 보관하고 도면 변경은 기존 outbox를 쓴다. 저장소가 차단된 브라우저에서는 분석 요청 복구를 제공하지 못하고 오류를 표시한다.
4. 커밋되지 않은 변경의 기준·복구 기록을 남기기 위해 이번 private ledger를 보존했다. 제한된 로컬 기록 파일이 남는 비용이 있다.
5. 추가 에이전트 수 제한으로 완료된 에이전트 자리를 새 UI 작업에 재사용했다. 이전 문맥을 잘못 적용할 위험을 별도 검토로 확인했다.
6. 실제 생성 폼을 담당하는 `drawing-workspace-start.tsx`를 최소 변경 범위에 포함했다. 인접 진입 흐름의 회귀 위험을 진입 테스트로 확인했다.

Superpowers의 테스트 우선·분리 검토 절차를 적용했다. Ponytail은 기존 CAD 커널, 명령 큐, 협업 및 outbox 재사용에 반영했다. 원본 보존·권한·납품 검증 조건은 단순화를 이유로 생략하지 않았다.

## 전체 목표에서 남은 필수 작업

- 실제 인증된 브라우저에서 Auth/PostgREST/Storage/worker를 거쳐 요청 → 가져오기 → canonical 저장 → 새로고침/재로그인 → 그룹 실행 취소와 역할 권한 확인.
- 가져온 DWG의 편집 결과를 DWG로 다시 쓰고 수신 CAD에서 검증하는 납품 자격 확인. 현재 reader의 5종 지원을 writer 전체 지원으로 해석하지 않는다.
- 기존 데이터가 쌓인 clone/restore ledger의 업그레이드 리허설.
- 실무 템플릿·납품 패키지(R5), 실제 고객 파일·역할별 업무 흐름과 운영 성능/복구 검증.

위 항목을 완료하기 전에는 전체 목표, DWG 재저장·납품 또는 운영 적용을 완료로 표시하지 않는다.
