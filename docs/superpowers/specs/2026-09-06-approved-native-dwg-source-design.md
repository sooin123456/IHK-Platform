# Approved native DWG source authority

Date: 2026-09-06. Implementation slice of the approved Universal Workspace/DWG roadmap, not R4/R5 completion. The user authorized continued development without repeated approvals. No commit, paid license, remote mutation, or deployment is authorized here.

## Decision and alternatives

Build the authoritative source connection before exposing the native writer as an export feature. Reuse the existing immutable revision snapshots, approval records, project authorization and native CAD projection. A small read-only RPC retrieves one exact approved source; a server adapter verifies its original JSONB-text hash and returns the current native manifest together with a separate approval/lineage envelope.

Browser-submitted geometry cannot establish approval authority. Reusing the browser PDF/PNG/SVG export audit would accept bytes generated by a different trust boundary. Creating a generic conversion framework or duplicating the share-view hydration logic is unnecessary: extract the existing strict graph hydration once, then consume it from both share resolution and approved CAD production.

This slice deliberately performs no long-running conversion inside a web request and adds no job table. The next worker slice will consume this authority contract behind on-demand, idempotent jobs, leases and staged immutable output receipts. That queue, storage/purge closure and authorized download are still required before a production export action is enabled.

## Trust contract

- Request scope is exactly projectId, documentId, revisionId, revisionVersion, canvasId and snapshotSha256. IDs are UUIDs; versions/sequences are safe integers. No canonical JSON, actor ID, binary path, writer version or output profile supplied by a browser.
- RPC requires a verified, non-anonymous authenticated actor and existing project read access. Viewer may read an approved export source; this does not grant edit rights. Anonymous sessions, outsiders and revoked members fail. Do not substitute quantity-write's estimator-only permission.
- Resolve the exact project/document/revision, snapshot revision version and approved decision's subject version/hash. Status must be approved or superseded, snapshot schema 2. Use PostgreSQL's SHA-256 of the exact UTF-8 canonical_json::text; return that text as the preimage, not a JavaScript reserialization.
- Reject null/malformed scope, foreign document/canvas, version/hash mismatch, draft/reviewed-only revisions, missing approval, corrupt snapshot digest and a purge_storage_ready project. Return one bounded unavailable error; never expose raw SQL, storage paths or canonical data in errors/logs.
- Source lookup is read-only: no source bytes, snapshots, operation logs, approvals or document rows change. Existing approved immutability/RLS remains intact. Explicit function grants; no new table grants or service-role exposure to the browser.
- The server adapter checks the returned scope against the request, hashes canonicalJsonText before parsing/normalization, and checks canonical revision identity, sequence, version, operationSequence, page/type/object/issue references. The SHA of PostgreSQL snapshot text and native structureSha256 are distinct values and must not be substituted for one another.

## Shared graph hydration

Extract the existing share authority hydration/lineage checks into a small server-only helper. Its input is revision identity/status plus snapshot metadata and parsed canonical graph, without share token/project name/expiry. It returns hydrated document state and the validated canonical graph. The share wrapper still maps errors to the same unavailable response and performs its existing token/expiry/source access checks.

Do not weaken strict geometry, duplicate ID, cross-revision, layer→canvas→page, object geometry.type, issue→object or duplicate issue-pair checks. Do not silently discard canonical object lineageId when building DWG authority evidence: preserve canonical layers' pageId, objects' lineageId/pageId/type and issues in a separate, deterministic envelope alongside the manifest. Block instance lineage remains in the existing canonical structure.

## Native-only boundary and output

The selected canvas must have an explicit persisted outputProfile. Never invent a default scale/paper profile for an approved revision. The current native CAD source schema still requires a single page/canvas, no source anchors/backgrounds and supported primitives/assigned blocks. Enforce that schema unchanged; an unsupported source fails closed instead of dropping a background, extra canvas, hidden object or unsupported entity.

Database native eligibility also checks provenance omitted from schema-2 graph serialization: document source ID/hash both null; no page/canvas background file, hash, PDF page or calibration; no object source row even if marked deleted; no revision IFC derivative binding. Historical source provenance is not silently relabeled as wholly native. Downstream BOQ/material links do not make native geometry imported and are not live-joined into the approved source.

Return `{manifest, authority}`. Authority includes project/document/revision IDs, revisionSequence, revisionVersion, operationSequence, canvasId, snapshotSha256, schemaVersion=2, approvalDecision=approved, revisionStatus and deterministic canonical object/layer/issue lineage. The native manifest remains version 1, unchanged writer/schema. This envelope is an input binding, not a signed proof or a published export receipt. The eventual worker must reload/revalidate DB authority and bind deployed writer build + output hash before publication.

Limits reuse the current CAD JSON budget (20 MiB source text maximum before parsing; current object/block/entity/point/depth checks during projection). No dependency or UI changes. Do not make unsupported DWG/customer file roundtrip claims.

## Verification and completion for this slice

1. Shared helper preserves existing public share results and bounded errors, with focused existing share tests plus direct strict-graph tests.
2. Real native template graphs become manifests through the approved adapter; literal scope/profile/geometry and retained canonical lineage are asserted. Canonical text is hashed before transform. Revision version differs deliberately from operation sequence in tests.
3. Negative cases cover every trust/native boundary above; source inputs remain byte-identical on success/failure. Adapter RPC failure is bounded and performs no fallback to client state.
4. Disposable PostgreSQL applies the new CLI-named migration and exercises authenticated owner/editor/viewer, anonymous/outsider/revoked access, exact real review→approval, digest/canvas/revision mismatch and read-only behavior. Existing M1 DB/browser regression remains root-owned.
5. At least one DB-approved native source runs through the unchanged pinned ACadSharp writer, with actual DWG bytes, source/authority/manifest hashes and reader report preserved as local evidence. Same-engine verification is not independent recipient CAD qualification.
