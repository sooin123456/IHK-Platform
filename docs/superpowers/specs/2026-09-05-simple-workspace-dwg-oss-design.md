# 1HK 단순한 작업공간·DWG 납품·오픈소스 활용 재기획

작성일: 2026-09-05. 상태: 조사 기반 제안, 구현·구매·배포 전.

## 1. 결론과 확정 요구

제품의 중심을 `파일 보관·관리 메뉴`에서 `도면을 만들고, 함께 수정하고, 납품하는 일`로 옮긴다. 기능을 없애는 것이 아니라, 시작 화면에서는 적게 보여주고 선택한 작업에 맞춰 필요한 기능을 연다.

- 업로드 없이 빈 도면 또는 템플릿으로 시작한다.
- 사용자는 DWG 가져오기뿐 아니라 **편집한 DWG의 재저장·납품까지 필수**라고 확인했다. 읽기 전용 DWG 뷰어나 DXF 변환 안내만으로 완료하지 않는다.
- 원본 파일은 수정하지 않는다. 편집은 1HK 객체·operation·개정에 저장하고, 납품 DWG는 별도 파생 파일로 생성한다.
- 기존 편집·협업·권한·승인·수량 계보는 유지한다. 다른 편집기 전체를 도입해 이 기반을 다시 만들지 않는다.
- 최대한 오픈소스를 활용하되, 오픈소스만으로 DWG 납품 품질을 입증하지 못하면 유료 CAD 엔진 비용을 공개하고 판단한다. 비용이 발생하는 계약·구매는 이번 조사에 포함하지 않는다.

이번 작업은 캡처·코드 점검과 공식 자료 조사다. 앱 코드, 운영 데이터, 패키지, 배포는 변경하지 않았다. DWG 엔진 실행 시험과 고객 도면 호환성 검증도 아직 수행하지 않았다.

## 3. 새 정보 구조

### 3.1 작업공간 홈

| 위치 | 기본 표시 | 안쪽으로 이동할 기능 |
|---|---|---|
| 사이드바 상단 | `내 공간 ▾` 또는 선택한 팀 이름 | 공간 전환·팀 참여·팀 생성 |
| 주요 탐색 | `도면`, `프로젝트`, `라이브러리` | 진행 중·검토 필요는 목록 필터 |
| 최근 항목 | 최근 프로젝트 최대 5개, 접기 가능 | 전체 목록은 프로젝트 화면 |
| 하단 | 알림, 설정, 내 계정 각 1개 | 구성원·회사 관리·보존 정책은 설정 내부 |
| 홈 상단 | 검색, `새 도면` | 새 도면 메뉴에 빈 도면·템플릿·파일 가져오기 |
| 홈 본문 | 최근 도면, 이어서 작업하기 | 도면/프로젝트 목록에서 정렬·필터 |

`라이브러리` 안에 템플릿·블록·스타일 탭을 둔다. 템플릿과 라이브러리를 별도 최상위 메뉴로 중복 노출하지 않는다. 개인 공간에서는 `회사 관리`라는 표현을 쓰지 않는다. 역할에 따라 설정 내 관리 탭을 노출한다.

조직에 가입하지 않고 프로젝트만 공유받는 경우도 보존한다. 공간 선택기에 `공유받은 항목` 범위를 제공하고, 여기서는 관련 프로젝트만 보여주며 조직 관리 메뉴를 표시하지 않는다. 플랫폼 운영자의 전체 조직 조회는 일반 작업공간이 아닌 별도 관리 영역으로 분리한다.

공간 선택은 서버가 요청마다 권한을 검증한다. URL 또는 서버가 읽는 선택 쿠키로 초기 화면을 일치시키며, 권한 철회·조직 삭제 시 접근 가능한 공간으로 복귀한다. 다른 공간으로 전환해도 로컬 outbox의 원래 문서·프로젝트·개정 ID를 바꾸지 않는다.

### 3.2 도면을 먼저 시작하기

진입 방법은 세 가지로 통일한다.

1. **빈 도면**: 즉시 편집기. 이름·단위는 캔버스에서 바꿀 수 있다.
2. **템플릿**: 미리보기 → 내 도면으로 복제 → 편집기.
3. **파일 가져오기**: DWG·DXF·PDF·IFC를 같은 진입점에서 판별. 파일별 호환성 검사 후 같은 문서 UX로 연결한다.

새 프로젝트를 먼저 만들거나 연락처를 입력해야 도면을 그릴 수 있는 흐름을 제거한다. 다만 내부의 프로젝트 소속·권한·수량 계보 규칙을 없애지 않는다. 프로젝트를 고르지 않은 경우 개인 공간의 자동 기본 프로젝트에 저장한다. 초기 생성은 재시도해도 중복 프로젝트/도면이 생기지 않아야 한다. 처음부터 팀 프로젝트를 선택하는 옵션은 유지한다.

기존 도면의 프로젝트 간 이동, 특히 조직 간 이동은 단순 드래그 기능으로 추가하지 않는다. 승인·댓글·물량 연결의 이관 규칙이 없는 상태에서 자동 이동하면 안 된다. 초기 단순화는 생성 경로에 집중한다.

업로드와 변환 상태를 구분한다: `업로드 중 → 파일 검사 → 도면 준비 중 → 열기 가능`. 실패하면 해당 파일 카드에서 재시도·원본 다운로드·진단 코드 확인이 가능해야 한다. 파일 처리 실패가 대시보드 전체의 빈 오류 화면으로 번지지 않게 한다.

### 3.3 편집기

- 상단: 도면 이름, 저장/오프라인/충돌 상태, 실행 취소/다시 실행, 참여자, 공유, 내보내기.
- 왼쪽: 페이지/레이어 두 탭을 기본으로 표시. 블록·스타일은 라이브러리 패널에서 연다.
- 중앙: 하나의 캔버스. PDF·DWG 원본 배경과 편집 객체를 구분한다.
- 도구 막대: 선택·선·도형·텍스트·치수·댓글의 기본 그룹. 호·폴리라인·벽·개구부·오프셋·자르기 등은 그룹 메뉴와 명령 검색에서 접근한다.
- 오른쪽: 선택 객체에 해당하는 속성만 표시. 선택이 없으면 문서/페이지 설정을 보여준다.
- 업무 전환: `작성 / 검토 / 수량·금액`. 각각 별도 문서가 아니라 같은 객체·선택·개정을 다른 패널로 보여준다.
- `2D / 3D / 분할`은 IFC가 연결됐을 때 노출한다. 빈 2D 문서에 작동하지 않는 3D 전환을 상시 배치하지 않는다.
- 객체의 연결 근거 수·검토 상태는 요약으로 보이고, 원본·IFC·수량·승인 상세는 펼쳐서 확인한다.

단순화를 위해 숨기면 안 되는 정보: 저장 실패, 미전송 작업, 권한 제한, 미지원 CAD 객체, 현재 개정, 승인 상태. 업무 탭 전환은 권한을 바꾸지 않으며, 작성자도 서버 검증 없이 승인할 수 없다.

## 4. 경쟁 제품을 참고해 보강할 지점

Rayon 공식 자료에는 빈 모델·템플릿·가져오기로 시작하는 흐름과 DWG/DXF/PDF 출력이 안내되어 있다. 1HK도 메뉴 수보다 이 작업의 완결성이 우선이다. [시작 흐름](https://docs.rayon.design/documentation/rayons-basics/creating-a-new-project), [출력](https://docs.rayon.design/documentation/import-export/exporting-and-printing).

| 축 | 현재 1HK에서 확인한 상태 | 이번 재기획의 보강 |
|---|---|---|
| 첫 사용 | 빈 도면·템플릿 시작은 이미 구현, 프로젝트·원본 중심의 기존 문구도 남음 | 도면 생성부터 보이는 단일 진입 경로 |
| CAD 업무 왕복 | 제한된 DXF 가져오기, DWG는 원본 보관/사용자 변환 경로 | 실제 DWG 편집·재저장·CAD 재열기 |
| 납품 | 기존 내보내기·승인 계보 기반 존재 | DWG 버전·레이아웃·글꼴·외부참조·출력 스타일 검증 |
| 재사용 | 블록·스타일·회사 라이브러리 기반 존재 | 실무용 템플릿과 검색 가능한 검증된 심볼 |
| 발견 가능성 | 여러 기능과 조직 관리가 같은 탐색 깊이에 노출 | 공간 → 도면 → 선택 객체 순서로 단계적 노출 |
| 1HK 고유 가치 | 원본·객체·수량·금액·승인 연결 기반 존재 | 선택 객체에서 연결 근거와 변경 영향을 쉽게 확인 |

경쟁사 미지원 기능을 단정하지 않는다. 예를 들어 Rayon의 DWG 가져오기 안내와 2025년 8월 제품 업데이트는 레이아웃 지원 설명이 서로 다르다. 문서만으로 현재 호환성을 판정하지 않고 실제 파일로 비교해야 한다. [가져오기 안내](https://docs.rayon.design/documentation/import-export/dwg-dxf-import), [2025년 8월 업데이트](https://docs.rayon.design/other-resources/product-updates/august-25-product-updates).

Figma류 도구에서는 선택·정렬·컴포넌트 재사용·상황별 검사기 원칙을 참고한다. UI 디자인용 오브젝트 모델을 건축 도면의 단위·치수·레이아웃·납품 모델과 동일하게 취급하지 않는다. 경쟁사 화면·문구·아이콘·템플릿을 복제하지 않는다.

현재 설치 내역은 [package.json](/Users/h/Documents/GoAgent/.worktrees/universal-workspace-m1/platform/package.json)에서 확인했다. Yjs·Hocuspocus·IndexedDB 연동은 미래 도입 예정이 아니라 현재 기반이다. 추가 상태관리 라이브러리나 UI 프레임워크는 이번 변경에 필요하지 않다.

추가 조사했지만 초기 채택에서 제외한 후보: [libdxfrw](https://github.com/LibreCAD/libdxfrw)는 GPL-2.0-or-later이며 DWG 쓰기 해결책이 아니다. [dxf-viewer](https://github.com/vagran/dxf-viewer)는 MPL-2.0의 읽기 전용 DXF 뷰어로 문자·선종류·레이아웃 한계가 있다. [SVG-Edit](https://github.com/SVG-Edit/svgedit/blob/master/LICENSE-MIT.txt)은 MIT지만 별도 편집기 전체를 넣으면 기존 캔버스·선택·이력을 중복시킨다.

라이선스 출시는 이름만 확인하는 것으로 끝내지 않는다. 선택한 릴리스와 lockfile/SBOM에 정확한 SPDX·전이 의존성·NOTICE·에셋 조건을 기록한다. 기존 코어 전체에 대한 신규 법적 적합성 감사까지 이번에 마쳤다는 의미는 아니다.

### 템플릿과 심볼

첫 묶음은 1HK 네이티브 템플릿 4종을 권한다: 실측 평면, 사무실 배치, 리모델링 전/철거/신설, 마감·물량 산출. 각 템플릿은 미리보기뿐 아니라 단위·레이어·스타일·치수·예제 수량 연결과 출력 설정을 포함한다. 법규 적합성이나 설계 안전을 보장하는 도면으로 표시하지 않는다.

외부 재사용은 다음 범위로 시작한다.

- [Excalidraw Libraries](https://github.com/excalidraw/excalidraw-libraries): MIT로 안내되는 라이브러리에서 일반 심볼을 선별. 변환 후 실제 치수·단위·형상 품질을 검증하고 상표·로고는 별도 검토한다. 건축 CAD 심볼 전체를 확보했다는 뜻은 아니다.
- [Penpot Files](https://github.com/penpot/penpot-files): 기본 CC BY 4.0 안내와 개별 대체 라이선스를 확인한 파일만 사용. 코드 라이선스와 에셋 라이선스를 구분한다.
- 건축용 문·창·벽·가구 심볼은 기존 1HK 의미 객체를 활용해 초기 20~40종의 검증된 정의로 제작한다. 단순 그림이 아니라 크기·삽입 기준점·레이어·분류를 갖게 한다.

각 자산에 원문 URL, 제작자, 정확한 라이선스, 출처 표기, 버전/해시를 기록한다. 무료 다운로드 사이트, 경쟁사 샘플, 저장소의 테스트용 DWG가 곧 상업 재배포 허가를 의미하지 않는다. 팀 내부 템플릿을 공개 라이브러리로 자동 전환하지 않는다.

## 6. DWG 재저장·납품 설계

### 6.1 엔진 선택지

| 선택지 | 장점 | 비용·위험 | 판단 |
|---|---|---|---|
| 기존 편집기 + ACadSharp | 허용적인 OSS 라이선스, 기존 모델 유지 | 실제 도면 왕복 보존을 직접 증명해야 함 | 우선 타당성 시험. 합격한 버전/객체 범위만 제품 지원으로 공개 |
| 기존 편집기 + ODA Drawings SDK | DWG 읽기·수정·저장을 전문 엔진에 맡김 | 유료 SaaS 라이선스·worker 운영비, 여전히 파일 검증 필요 | 업무용 납품 필수 조건에서 현실적인 품질 우선 대안 |
| Penpot/다른 전체 편집기로 교체 | 완성된 다른 UX를 얻을 수 있음 | 데이터·협업·권한·수량 연결 재구축, DWG 납품 문제도 별도 | 비추천 |

ACadSharp 저장소는 DWG 읽기/쓰기 지원 버전을 명시한다. 다만 2024년 재저장 정보 손실/타 CAD 표시 문제 보고가 있다. 이는 **과거 보고**이며 최신 릴리스에서도 같은 문제가 재현된다고 단정하지 않는다. 현재 고객 도면을 지정 릴리스로 시험해야 한다. [지원 표](https://github.com/DomCR/ACadSharp), [과거 재저장 보고](https://github.com/DomCR/ACadSharp/discussions/479).

최근 이력도 시험에 반영한다. 2026년 7월 동적 블록 writer 정보 보존 요청은 현재 종료되어 후속 변경이 연결되어 있다. 2026년 8월에는 특정 버전의 **DXF writer**에서 3DSOLID/REGION이 누락된다는 보고가 있다. 이를 현재 모든 DWG writer의 결함으로 일반화하지 않고, 선택한 릴리스의 동적 블록 보존과 DXF 중간 변환 손실을 각각 시험한다. [동적 블록 이력](https://github.com/DomCR/ACadSharp/issues/1133), [DXF 변환 보고](https://github.com/DomCR/ACadSharp/issues/1195).

ODA는 읽기·편집·저장을 지원한다고 안내한다. 2026-09-05 공개 표에서 Web/SaaS는 Sustaining 이상에 포함되고, 해당 등급은 첫해 USD 7,500·갱신 USD 4,500으로 표시된다. 세금·추가 제품·배포/스케일 조건을 포함한 최종 견적은 별도 확인한다. [Drawings SDK](https://www.opendesign.com/products/drawings), [공식 등급·가격](https://www.opendesign.com/oda-membership).

무료 ODA File Converter를 그대로 상업 SaaS 변환 서버로 사용할 수 있다고 가정하지 않는다. 비회원 사용과 상업 서비스 제공에는 별도 제한이 있다. [공식 FAQ](https://www.opendesign.com/faq/question/what-are-oda-viewer-and-oda-file-converter), [Community 사용 계약](https://www.opendesign.com/files/2025-09/ODA%20Community%20User%20Agreement%2009-2025.pdf).

추천은 **앱·협업은 기존 OSS 기반, DWG는 합격한 단일 엔진**이다. 납품 품질·계약 조건을 만족하는 OSS 경로가 나오면 그것을 선택한다. 나오지 않으면 ODA를 DWG 부분에 한정해 도입하는 안을 선택할 수 있다. 처음부터 ACadSharp·LibreDWG·ODA를 모두 운영하거나, 읽기와 쓰기에 서로 다른 엔진을 무조건 배치하지 않는다.

### 6.2 저장과 변환 경계

1. 원본 DWG와 사용자가 제공한 의존 파일을 변경 불가능한 원본으로 보관한다. SHA-256과 파일 버전을 기록한다.
2. 격리된 CAD worker가 파일 버전, 객체 종류, 단위, 글꼴, 레이아웃, 외부참조를 검사한다. 브라우저 장시간 작업이나 웹 요청 하나에 전체 변환을 묶지 않는다.
3. 지원 객체를 1HK 객체에 연결하되 원본 SHA·DWG handle·블록/레이아웃·좌표 변환을 보존한다. 지원하지 않는 객체는 경고와 함께 잠긴 원본 표현으로 남긴다.
4. 사용자 편집은 기존 operation/outbox/협업 경로에 저장한다. DWG 엔진을 두 번째 공동 편집 서버로 만들지 않는다.
5. DWG 출력 요청 시 서버에 확정 저장된 개정을 고정한다. 작업 중 출력은 초안, 최종 납품은 승인된 스냅샷을 대상으로 한다. 미전송 변경이 있으면 동기화 완료 전 최신 결과라고 표시하지 않는다.
6. worker가 원본의 작업 복사본을 열어 지원되는 변경만 적용한다. 1HK 도형을 전부 DXF로 납작하게 만든 다음 DWG로 감싸는 방식은 원본 보존 경로로 사용하지 않는다.
7. 다시 읽기·audit·의미 비교·출력 미리보기 검증에 합격한 별도 DWG를 만든다. 실패하면 납품을 차단하고 이유를 표시한다. 원본 다운로드와 1HK 편집 내용은 유지한다.

**편집 전에 납품 가능성을 먼저 검사한다.** 파일별로 `편집·납품 가능 / 의존 파일 보완 필요 / 보기만 가능`을 표시한다. 미지원 객체가 화면에서 잠겨 보인다는 것은 DWG 내부의 네이티브 데이터가 보존된다는 뜻이 아니다. 해당 데이터의 왕복 보존이 입증되지 않으면 납품용 편집을 시작시키지 않고, 검증된 엔진 경로가 있으면 그 경로로 처리하거나 원본 보기만 제공한다. 초기 합격 뒤에도 출력 전 최종 검증은 생략하지 않는다.

원본에 변경이 전혀 없는 `원본 다운로드`는 원본 바이트 그대로 반환한다. 빈 도면/템플릿은 지원되는 CAD 엔티티·레이아웃으로 새 DWG를 생성해야 한다. 파일명을 `.dwg`로 바꾸거나 이미지를 넣은 DWG만 제공하는 것으로 작성·편집 지원을 대신하지 않는다.

선·폴리라인·원·호·문자·치수·레이어·일반 블록은 첫 호환성 시험의 핵심이다. 동적 블록·proxy/AEC 객체·3D 솔리드 등은 편집 지원과 그대로 보존하는 지원을 구분한다. 보존을 입증할 수 없는 파일은 납품 가능으로 표시하지 않는다. 동적 블록을 일반 선으로 해체하는 변환은 사용자에게 알리지 않고 수행하지 않는다.

### 6.3 안전·계보·납품 정보

- 원본 SHA, DWG handle, 1HK 객체 ID, 편집 operation, 승인 개정, 엔진 버전/설정, 출력 SHA를 연결한다. 복사·분할·결합으로 ID가 달라지면 일대다/다대일 관계도 기록한다.
- 외부참조는 사용자가 올린 파일의 명시적인 manifest로만 해결한다. DWG에 적힌 로컬 경로나 외부 URL을 worker가 임의로 읽지 않는다.
- worker CPU·메모리·시간·파일 수·압축 해제 용량을 제한하고, 네트워크 기본 차단·임시 파일 격리·서명된 작업 권한을 적용한다. 기존 IFC job/worker 패턴을 참고하되 CAD 실행 환경은 격리한다.
- 글꼴 누락 시 대체를 표시한다. 한글·SHX/TTF·MTEXT 줄바꿈·문자 폭이 납품 기준을 만족하지 않으면 정식 납품으로 처리하지 않는다. 글꼴 파일의 재배포 권리도 확인한다.
- mm/m/inch·단위 미지정·WCS/UCS·큰 좌표의 변환을 기록한다. 사용자가 단위를 확정하기 전 물량·금액을 확정하지 않는다.
- 납품 묶음은 DWG, 출력 PDF, 필요한 허가된 의존 파일, 변경/호환성 보고서로 구성한다. 토큰·서명 URL·개인정보·내부 비밀 경로를 manifest에 포함하지 않는다.
- 저장 불가와 보기 불가를 구분한다. 미지원 파일도 원본 보관·진단·가능한 미리보기는 제공할 수 있지만, 이것을 DWG 편집·납품 완료로 계산하지 않는다.

### 6.4 DWG 첫 출시 합격 기준

검증용 합성 도면과 사용 허가된 실제 고객 도면을 함께 사용한다. 제안 코퍼스는 최소 30개이며, 개수보다 아래 항목의 커버리지가 우선이다. 제품 지원 입력/출력 버전은 시험 결과와 실제 납품처 요구로 고정하고 공개한다.

- 업로드/무편집 원본 다운로드 전후 SHA 동일.
- 지원 버전별 무편집 round-trip 시험과 편집 후 저장 시험 모두 실행. 원본을 그대로 반환하는 경로만으로 writer 시험을 통과시키지 않는다.
- 선 수정, 문자 변경, 치수 변경, 블록 삽입/이동, 레이어 변경, 삭제/실행 취소 후 재저장 시 의미가 보존됨.
- 모델 공간·종이 공간·뷰포트·단위·선종류·선 굵기·CTB/STB 등 지원하는 납품 조건을 고정하여 비교.
- 한글 글꼴·중첩 블록/속성·외부참조가 있는 도면을 검증. 미지원 객체 보존과 편집 금지 경계도 검증.
- AutoCAD 또는 납품처 지정 CAD에서 복구 경고 없이 다시 열고 출력 확인. 엔진 자체 재열기만으로 충분하다고 판단하지 않는다.
- 납품처별 CAD/버전·표준 도곽·CTB/STB·글꼴·Xref 요구를 기록하고 실제 수령자의 수용 확인을 받는다. 내부 사용자 시험만으로 납품처 호환성을 보장하지 않으며, 미검증 환경은 지원 제한에 공개한다.
- 수정하지 않은 객체/관계/사용자 데이터의 의미 손실 0건. 예상하지 않은 handle 소실·참조 깨짐·자동 복구가 있으면 불합격.
- 그림이 비슷한지만 보지 않고 객체 수·종류·레이어·블록·레이아웃·치수·좌표를 함께 비교. 길이/면적 허용오차는 단위·도면 정밀도에 맞춰 시험 전에 고정한다.
- 동일 원본·개정·설정의 의미 결과가 재현 가능해야 한다. 출력 DWG의 헤더 시각 같은 이유로 파일 해시까지 항상 같아야 한다고 가정하지 않는다.
- Viewer 수정 거부, 조직 간 파일/변환 결과 격리, 만료/철회 권한 거부, 작업 재시도 중복 방지.
- 동시 편집·오프라인 복구 후 고정한 개정의 DWG와 수량/승인 근거가 일치함.

이 기준에 합격하기 전에는 DWG 버튼이 있다는 이유로 `DWG 납품 지원 완료`라고 출시하지 않는다. OSS 후보가 불합격해도 납품 요구를 없애거나 DXF만으로 완료하지 않는다.

## 7. 구현 단위와 순서 제안

다음은 별도 검증 가능한 작업 단위이며, 이번 문서는 전체를 한 번에 구현하는 상세 코드 계획이 아니다.

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| R1 | 조직 선택·중복 메뉴·정확한 역할 조회 | 조직 1/4/20개에서 메뉴 한 묶음, 다른 구성원 순서와 무관한 권한 표시, 100명 초과 구성원도 본인 소속 누락 없음 |
| R2 | 새 도면 진입·기존 화면 정리 | 업로드/프로젝트 입력 없이 시작, 템플릿·파일 가져오기가 같은 편집기로 도착, 기존 링크·공유 프로젝트 보존 |
| R3 | 편집기 단계적 노출 | 작성/검토/수량 패널 전환 시 객체·선택·개정·outbox 유지, 저장/권한 오류는 계속 표시 |
| R4 | DWG 엔진 검증 → 선택 → 가져오기·편집·재저장 | 6.4의 납품 기준 통과. R1과 엔진 검증을 병행해 비용·호환성 판단을 늦추지 않음 |
| R5 | 실무 템플릿·심볼·납품 패키지 | 네이티브 템플릿 4종과 출처 검증 심볼, 실제 사용자 3명의 작성→검토→수정→승인→CAD 납품 및 실제 수령자의 수용 확인 |

R1은 UI만 수정하지 않는다. 본인 membership, 선택 조직 범위, 조직 미가입 공유 프로젝트, 관리 URL 직접 접근/POST 거부, 권한 철회 후 복귀를 함께 검증한다. 같은 이름의 데이터를 자동 정리하지 않는다.

R1~R3 반응형 검증: 1440/1024/768px, 키보드만으로 공간·도면·설정 접근, 초점 복귀, 긴 이름·빈 목록·많은 프로젝트, 계정/알림 접근성. 화면 폭이 좁으면 사이드바를 drawer로 전환한다.

이전 출시 게이트도 유지한다: 실제 운영 업로드/재로그인, 3인 협업, 오프라인 무유실, 원본 해시, 승인 개정 동결, 수량·금액 결정론, 백업 복구. 이번 UX 재기획이 이미 남아 있는 운영·고객 검증을 대체하지 않는다. [기존 진단과 검증 범위](/Users/h/Documents/GoAgent/.worktrees/universal-workspace-m1/docs/superpowers/evidence/2026-09-05-current-diagnosis-and-next-steps.md).

## 8. 이번에 늘리지 않는 것

- 새 편집기 전체 fork, 두 번째 객체 저장 모델, 두 번째 협업 시스템.
- 모든 화면에 회사·보존·수량·승인 메뉴를 동시에 노출하는 구조.
- 고객 파일 시험 없이 모든 DWG 버전·동적 블록·3D/AEC 편집을 약속하는 호환성 표.
- 출처 불명의 대량 CAD 템플릿 수집 또는 경쟁사 자산 복제.
- AI 자동 승인·확정 물량 계산, 불필요한 새 상태관리/UI 라이브러리.

`brainstorming`으로 공간·도면·CAD 납품을 분리해 요구와 선택지를 정리했고, UX 점검으로 캡처의 반복과 코드 원인을 연결했다. `ponytail` 원칙에 따라 기존 코어 유지·메뉴 재배치·단일 CAD 엔진 선택을 우선했다. 이는 DWG 납품·권한·데이터 보존 요구를 축소한다는 뜻이 아니다.
