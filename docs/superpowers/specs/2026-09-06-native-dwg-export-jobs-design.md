# Native DWG export jobs — design

## Product outcome and authority

Continue the approved Universal Workspace goal: a user requests a DWG from the current approved native drawing, sees durable progress after reopening, and downloads the verified result plus its source/lineage report. This is a new asynchronous subsystem, not a replacement for existing PDF/PNG/SVG export or completion of customer DWG import/edit/re-save. Existing DWG preservation, recipient CAD qualification, draft-marked exports and the complete delivery package remain required follow-on work.

The user explicitly asked to implement continuously without repeated approvals. Scoped local implementation and disposable-database tests are authorized. No commit, push, deployment, paid service, license contract, or remote project mutation is authorized. Preserve the dirty worktree and previous evidence.

## Chosen approach

Use existing PostgreSQL RPC/lease patterns, the exact approved-source adapter, and the pinned ACadSharp writer. A web request only queues work; a bounded worker produces and checks files. Synchronous conversion would tie conversion duration to a web request. A separate queue product or generic conversion framework would add operational configuration without a current need. No new package dependencies.

Keep `lukas-qto` private. Reserve `projects/<project UUID>/native-dwg/` and add an AS RESTRICTIVE FOR ALL policy TO authenticated,anon, with both USING and WITH CHECK denying that prefix. Existing permissive project Storage policies therefore cannot reveal, upload, replace, move or delete these files. Service credentials remain server-only and trusted. A separate bucket is unnecessary and would change the existing retention manifest contract.

## Source and actor authority

The browser sends exactly `projectId,documentId,revisionId,revisionVersion,canvasId,snapshotSha256,requestId`. No geometry, output profile, actor, engine path/build, storage path or artifact bytes are accepted. Scope values use current UUID/SHA/safe-integer validation.

The authenticated request derives its actor from auth.uid(), checks the current verified non-anonymous session and project read role before replay, locks the project, invokes exact approved native source authority, then creates an idempotent job. Viewer may export an approved source without receiving edit authority. `(requested_by,request_id)` is unique; exact replay returns the same immutable acceptance `{accepted:true,jobId,requestId}`. Different scope with the same actor/request conflicts. Limit each project to five active jobs; exact replays do not consume another slot. This ceiling protects conversion resources and can be raised with measured throughput, not a new queue abstraction.

Factor the current SQL approved source resolver into a private actor-scoped helper and preserve the existing public authenticated wrapper, its signature, payload and PND01 behavior. The helper receives an explicit persisted actor only from trusted code, verifies a current non-anonymous, nondeleted/nonbanned auth.users row and project owner/member or protected raw_app_meta_data staff role, then applies all existing exact snapshot/approval/native-provenance predicates. No worker JWT impersonation and no broad service execution grant on the public source RPC. Current auth users without an email-confirmation field in the existing verified-session contract are not silently subjected to a new email-verification policy.

The job stores only exact immutable source identity; it does not duplicate the 20 MiB canonical JSON. Claim reloads source through the private helper. Stage and publication recheck live actor access, exact approval scope and purge exclusion. Revoked/anonymous actors cannot gain access through acceptance replay, status or download. Invalid source/actor at claim becomes a bounded terminal failure, not an endlessly selected queue head.

## Durable records and state

Use four focused tables: `lukas_drawing_native_dwg_jobs`, `lukas_drawing_native_dwg_attempts`, `lukas_drawing_native_dwg_artifacts`, `lukas_drawing_native_dwg_exports`. All public tables enable and force RLS; direct privileges are revoked from PUBLIC,anon,authenticated,service_role. Only explicit RPC grants permit operations. Composite project/job and job/attempt foreign keys prevent cross-project attachment. Index request identity, project/scope status lookup, eligible jobs, and artifact/attempt job lookups.

- Job: immutable source scope, requested_by/request_id, created_at; mutable `queued|processing|retry_wait|completed|failed`, attempt_count 0..3, next_attempt_at, current lease token/expiry, pinned writer_build_sha256 and bounded last_error_code. First claim pins the deployed writer hash; later claims require the same hash. A new explicit user request is needed after terminal failure; completed jobs/receipts are not requeued or overwritten.
- Attempt: job/project, attempt_number 1..3, unique lease token, writer hash, expiry, upload_state `not_started|open|closed`. Each claim creates a new row, retaining old attempts. Reclaim never erases an earlier potentially live upload session.
- Artifact: append-only job/project/attempt/kind, exact DB-derived path, SHA, byte size, created_at. Four kinds exactly: `dwg`, `source_manifest`, `authority`, `report`. Duplicate stage replay must match all four tuples. Changed metadata is a conflict. Source manifest <=20 MiB, authority <=20 MiB, report <=32 MiB, DWG <=100 MiB; all nonempty. Paths are `projects/<project>/native-dwg/<job>/<attempt>/<sha256>/<fixed filename>`; filenames are `native.dwg`, `source-manifest.json`, `authority.json`, `native-report.json` respectively.
- Export: append-only one per job, exact successful attempt, structure SHA, completed_at, qualification fixed `experimental-unqualified`. All file/hash/build/scope receipt metadata is derived from job, attempt and registered artifact rows, not arbitrary browser JSON. Publication atomically inserts this immutable receipt and sets the job completed.

Artifact/export updates are forbidden; deletion is allowed only through the existing four-part guarded project-retention cascade (nested delete, exact project marker, table-owner context, absent parent project). Job scope and attempt identity cannot be changed by lifecycle operations. No ordinary delete grants.

## RPC lifecycle

User RPCs: request, status and download descriptor. Authenticate and authorize before finding cached requests or output. Status returns the latest exact-scope job (or the specified exact-scope job), bounded state/error, counts and completed artifact kinds/hash/sizes; no canonical text, storage paths, lease tokens, credentials or fabricated completion percentage. Download descriptor is available only for a completed exact-scope export and one of the four known kinds.

Service-only RPCs: claim, stage, settle upload, publish, fail. Explicit service role check plus EXECUTE service_role only; private helpers have no external grants. Every operation that changes job/publication state locks project first, then relevant jobs, then attempts. Retention locks project → IFC jobs → native jobs in a consistent order. Claims use database time and skip locked candidates; no cross-project head-of-line wait. Lease range 30..900 seconds, normal worker lease 900 seconds. At most three attempts; retry delay 30 * 2^(attempt-1) seconds. Expired last attempt becomes terminal `lease_expired`.

Claim returns job identity, attempt/token/expiry, pinned build and exact source request+payload. Stage registers all four artifact tuples and structure SHA under an active matching lease before the first Storage write, and marks that attempt open. Settle closes only that exact attempt after all its upload/readback work has actually settled; a stale attempt may close its own session but may never stage/publish or alter a newer job lease. Uncertain I/O remains open. Publish requires the current unexpired lease, closed upload session and exact complete registered artifact set. Exact publication replay returns the original receipt even after a lost response, but no other attempt can borrow it. Fail changes only the matching current lease; stale failures cannot overwrite newer/completed work. Error codes are a fixed enum, never raw SQL, canonical JSON, process stderr or storage URLs.

## Worker and file verification

The worker uses a locally published .NET writer, not `dotnet run` inside a web request. Configuration selects absolute deployed paths server-side. Derive writer_build_sha256 from an ordered manifest of the actual published writer/dependency/runtime-config bytes; reject symlinks and changes before/after execution. Reuse the pinned writer's native contract and exact source adapter. Source snapshot SHA, structure SHA, native manifest SHA, report SHA and DWG SHA remain separate.

Use a task-owned mkdtemp directory, exclusive 0600 input writes, shell:false exec, bounded process output and actual process termination timeout. Normal whole-attempt budget is 840 seconds inside a 900-second lease, with at most 120 seconds for the writer and at most 30 seconds per Storage request. Check remaining deadline before and after every step. Do not use a bare Promise.race to pretend an operation stopped. A failed/cancelled upload with uncertain remote completion does not close its upload session.

Validate report qualification/status, exact input identity/hash, reported output hash, AC1024 header, nonempty bounded artifacts and no internal comparison failures. Reject extra/unexpected output file types and path traversal. Reuse upsert:false plus exact byte-size/hash readback after a confirmed success or fully consumed, explicitly coded duplicate response. Matching bytes alone cannot establish that a lost/uncertain upload settled: such an attempt remains open without readback reconciliation, settle or publication. Do not delete registered artifacts in generic failure catches. After every upload/readback actually finishes, settle the attempt then publish; on failure send only a bounded error classification and keep uncertainty visible. Original source bytes and approved records are never modified.

## Retention and late uploader safety

Union every registered native artifact, including failed/unpublished attempts, into `private.lukas_qto_project_retention_storage_files`, preserving `(path,sha256,byte_size)` and current sorting/hash contract. Preparation/finalization include active native jobs and unclosed native upload sessions, and finalization checks the entire native project prefix as well as manifest paths. Add native job/artifact/open-session counts to dependency evidence without treating derived output as permission to delete protected approvals.

Every legitimate current job requires an approved/superseded revision plus approved decision; those existing protected dependencies already refuse purge. Preserve that invariant. Additionally, an uncertain open upload session never expires into presumed safety: it stays retained for explicit operator reconciliation. Lease expiry fences DB publication, not a paused holder of broad service credentials. Prefix absence is a point-in-time check, not a distributed write lock; do not claim arbitrary late-upload resurrection is solved. No automatic deletion/reconciliation operation is added or run in this implementation.

## Route and UX integration

Add scoped resources below `/projects/:projectId/workspaces/:workspaceId/native-dwg`: POST request and GET status; `/.../native-dwg/:jobId/download/:kind` for download. Use existing drawingContext, CSRF/origin policy, bounded request-body parsing and mergeResponseHeaders patterns. Request payload scope must match route project/document. Return no-store bounded 4xx errors for unavailable/unauthorized/unconfigured service; preserve auth cookies on errors.

The download route first obtains a user-authorized descriptor, loads only that exact managed object through a lazily imported server service client, verifies size/hash and rechecks authorization before returning a streamed attachment. A bounded deadline combined with browser-request cancellation reaches actual RPC/Storage transport and remains owned through headers, full body and final reauthorization. Route modules export only framework entrypoints; testable server handlers/parsers stay in .server modules. No signed Storage capability is handed to the browser. Set private no-store, nosniff, no-referrer and an explicit safe fixed filename containing `experimental`; send only allowed MIME types. Never redirect on a user-controlled path.

Extend the existing export dialog with `DWG (시험)` and clear scope/compatibility copy. Use existing React state/fetch, no new global store or collaboration service. Persist the request ID for uncertain POST retries keyed by exact source scope; reload resolves durable status through the server. Poll only while the dialog is open and the job is active; abort polling on close/unmount/source change. Closing the dialog does not claim to cancel a server job. Display queued/processing/retrying/failed/completed honestly, surface a retry action after failure, and expose DWG plus report/source/authority links when complete. Reject unsupported imported/multi-canvas content with an actionable message, not silent fallback. Local preview without real approval/backend may explain that it cannot queue a real export; never forge completion. Existing three image/document export formats retain behavior.

## Verification / acceptance

1. TDD unit checks for strict scope, idempotency transport, each lifecycle failure, stale/expired leases, deadline and abort behavior, artifact/hash/report tamper, cleanup confinement, request retry identity, status rendering and cancellation.
2. Real disposable PostgreSQL proves actual native import→review→approval→request→claim→stage→settle→publish→descriptor; exact request/publication replay; owner/editor/viewer positives; anonymous/outsider/revoked and forged actor/build/path/tuple negatives; current source RPC regression; stage-before-write; attempt retention; active/open-session/protected-approval purge denial; private prefix RLS cannot be bypassed by permissive policies. Concurrent claim and stale completion are tested with actual connections/leases where visibility permits, not by counting source strings.
3. Actual published writer and local Storage through real API produce/download an AC1024 file and four immutable artifact hashes matching the approved source receipt. Storage failures/readback mismatch never produce completed status. No synthetic transport claim substitutes for HTTP integration.
4. Browser tests exercise request→progress→reopen→download, readonly user access and denial, alongside existing upload/start/share/approval regression. Run typecheck/app/worker build and relevant full M1 regression once the vertical path is integrated.
5. Independent task reviews and final integration review; concrete evidence with commands, test counts, hashes, known limits. Production delivery qualification and customer DWG roundtrip remain explicitly unproven until their own acceptance gates pass.
