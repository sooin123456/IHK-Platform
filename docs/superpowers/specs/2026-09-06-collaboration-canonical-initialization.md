# Canonical first collaboration state

This implements the active Universal Workspace goal's R2 persistence requirement. The user's standing approval authorizes local implementation without repeated approval prompts; this is not authorization to deploy, purchase licenses, or mutate remote data.

## Problem and acceptance

An untouched Hocuspocus room currently generates independent Yjs server metadata each time it loads without a stored state. Identical JSON is not identical CRDT history: an honest IndexedDB replay can be rejected by the protected-state guard. A second problem is exposing transient freeze metadata before its identity is durably persisted. The previous accepted freeze-identity unit prevents no-op rewrites, but does not establish first-state durability.

1. Exactly one trusted initial CRDT state is inserted for a revision. Concurrent initializers return the winner's exact bytes, generation, hash and base sequence; losing candidates are never merged into it.
2. Browser, detached freeze/reconciliation, and detached receipt loaders all adopt that winner before any subsequent mutation. Initialization is awaited even when the room is never edited.
3. An authorized Viewer can establish/read a canonical state, including an approved revision with no prior collaboration state. This is trusted serialization, not an editor operation. The service-only bootstrap remains draft-only. Existing state is returned unchanged regardless of revision/freeze state.
4. A pre-existing freeze lease does not prevent insert-only initialization. It does prevent ordinary edits; initialization never changes, releases, or steals a lease and never writes non-active initial metadata.
5. The initializer locks the exact revision, verifies the candidate's canonical snapshot SHA and base sequence against the current graph before first insert, and rejects stale candidates with P3S04. It does not validate opaque Yjs semantics in SQL: the trusted server validates scope and ledger before the call and validates the returned state before admission.
6. No transient reconciliation identity may enter the initial Hocuspocus payload. Reconcile a detached canonical document, reload the durable state after recovery, and compare normalized Yjs encodings before admission. If reconciliation would expose an unpersisted state, fail closed with an explicit retry error, leaving the initial payload empty. An active server-only correction may be persisted through the existing guarded service store, then reloaded; never bypass freeze guards. Retry stale initialization or concurrent durable movement at most three times.
7. Ordinary Viewer edits and client writes to protected server metadata remain rejected. Approved revisions, original files, history and existing ordinary CAS semantics are unchanged.

## SQL interface

Migration: `platform/supabase/migrations/20260906070918_drawing_collaboration_canonical_initialization.sql` (already generated by CLI).

- `private.lukas_drawing_collaboration_initialize_state_core(p_project_id uuid,p_revision_id uuid,p_yjs_state bytea,p_base_operation_sequence bigint,p_base_snapshot_sha256 text,p_allow_readonly boolean)` returns `setof private.lukas_drawing_collaboration_states`.
- `private.lukas_drawing_collaboration_initialize_state(p_user_id uuid,p_project_id uuid,p_revision_id uuid,p_yjs_state bytea,p_base_operation_sequence bigint,p_base_snapshot_sha256 text)` returns the same rows after existing private collaboration authorization. Do not require can_write for trusted initialization.
- `private.lukas_drawing_collaboration_service_initialize_state(p_project_id uuid,p_revision_id uuid,p_yjs_state bytea,p_base_operation_sequence bigint,p_base_snapshot_sha256 text)` returns the same rows after existing realtime entitlement check, with `p_allow_readonly=false`.

Core order: lock revision (P3A01 when unavailable); return existing state unchanged; draft restriction only for absent service state (P3A02); validate byte length 1..8388608, nonnegative sequence and lowercase 64-character SHA (P3S01); calculate `private.lukas_drawing_p2_canonical_snapshot(revision,true)` and SHA using pgcrypto digest of PostgreSQL jsonb text; reject mismatched graph schema/sequence/SHA (P3S04); insert schema 1, generation 1, active/null freeze defaults and computed state SHA/size; return row.

All functions are private SECURITY DEFINER with empty search_path and fully qualified objects. Core has no application-role execute grants. Only `lukas_drawing_collaboration` may execute the two wrappers. Revoke default PUBLIC/anon/authenticated/service_role execution. Existing verified user ID + private authorize is the authority boundary: a collaboration SQL connection has no end-user JWT, so adding an auth.uid null guard would incorrectly deny all legitimate calls. No new public table or Data API exposure.

## TypeScript interface

In existing storage.ts add `DrawingInitializeInput = DrawingStorageScope & { state: Uint8Array; baseOperationSequence: number; baseSnapshotSha256: string }`. Optional database methods `initializeState(input): Promise<DrawingStoredState>` and `initializeServiceState(Omit<DrawingInitializeInput,'userId'>): Promise<DrawingStoredState>` are implemented by the Postgres adapter; storage facade exposes the same methods, validates via existing callback, uses existing transient retry, and seeds correct user/service CAS tokens from the returned winner. No initialization CAS-merge path.

In server.ts reuse one canonical loader for the three absent-state paths. Create candidates in disposable Y.Doc instances, initialize via existing trusted bootstrap, and destroy losing candidates. Apply only returned canonical bytes into a fresh document. Reuse the detached service loader for signed receipts and ensure detached docs are destroyed on failure too.

## Verification and limits

Use actual isolated local PostgreSQL for concurrent winner/loser, stale snapshot/sequence, ACL, Viewer, approved reader, service draft restriction, lease preservation and no-overwrite assertions. Reuse the existing M1 real database fixture and disposable database cleanup. Add production adapter/server and actual WebSocket tests for untouched room unload/reload and honest replay, transient initial admission refusal, Viewer denial and protected-state forgery. Run focused collaboration regressions and TypeScript compilation.

Do not add dependencies, replace Yjs/Hocuspocus, relax protected-state validation, rebuild the live preview, stage/commit/push/deploy, or touch remote data. Live-room freeze projection durability and recovery of already-divergent legacy IndexedDB origins remain explicitly outside this first-admission unit; R2 overall, native DWG delivery R4 and package R5 remain active requirements.
