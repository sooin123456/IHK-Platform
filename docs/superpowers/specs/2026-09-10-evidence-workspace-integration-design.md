## 1. 제품 약속

건축·토목 사용자가 실제 도면 또는 모델에서 수량을 산출하고, 회사 단가로 금액을 만들며, 변경 영향·검토·승인·납품 근거를 같은 작업실에서 관리한다. 시스템은 현재 데이터에서 필요한 다음 작업을 찾아 실제 위치와 함께 안내한다.

핵심 흐름: 원본 → 객체 → 측정·산출식 → 수량 → 단가·내역 → 변경 → 검토·승인 → 납품.

첫 사용자: 적산·견적 담당자. 협업 사용자: 설계 담당자, 현장 공무, 감리·검토자, 승인자. 첫 실증은 한 프로젝트의 바닥 마감 면적 적산과 설계변경으로 제한한다. 건축·토목 전체 자동 적산을 첫 출시 약속으로 삼지 않는다.

실행 전 작업 트리·브랜치·서버·배포 커밋·마이그레이션 적용 상태를 대조한다. 기존 사용자 변경은 보존한다. 미리보기 저장을 운영 저장 성공으로 표시하지 않는다.

## 3. 범위와 비범위

포함: PDF 실측 오버레이, 실제 IFC 3D, 수량·내역 연결, 변경 영향, 권한 기반 검토, 규칙 기반 다음 작업, 근거 기반 AI 추천, DWG 편집·재납품 지원 범위 검증, 건축·토목 위치 체계.

초기 제외: 범용 CAD 전면 대체, PDF 한 장으로 정확한 BIM 자동 복원, AI 최종 계산·승인, 구조 안전 자동 보증, 검증되지 않은 전 공종 자동 적산, 구매·발주 자동 실행.

실사풍 AI 렌더링은 선택적 설계 제안 기능이다. 생성 이미지는 도면 원본·시공 지시·수량 근거와 분리한다.

## 4. 화면 구조

- 진입: 작업이 있는 사용자는 프로젝트 목록/최근 작업, 없는 사용자는 빈 작업실·템플릿·자료 가져오기 안내.
- 상단: 프로젝트/문서, 개정, 저장·연결 상태, `작성 | 검토`, `2D | 3D | 분할`.
- 좌측: 자료·페이지·모델 구조·레이어. 회사 설정·보존 등 관리 메뉴는 한 곳으로 통합.
- 중앙: 실제 도면/모델. 선택·단면·숨김·단독 보기·변경 비교.
- 우측: `속성 | 적산 | 확인할 항목`. 상세 내역은 하단 표 또는 확장 보기로 열고 선택 객체·위치·필터를 유지.
- 추천 선택: 객체 강조 → 위치 이동 → 근거/내역 행 표시 → 허용된 작업 수행 → 결과 재검사.

빈 데이터에는 샘플 값을 채우지 않는다. `미산출`, `검사하지 못함`, `원본 연결 끊김`, `동기화 대기`를 구분한다. 색은 보조 수단이며 아이콘·텍스트·키보드 이동도 제공한다. 객체를 찾지 못하면 근접 객체로 자동 대체하지 않는다.

## 5. 데이터·책임 계약

### 단일 운영 데이터 경로

미리보기는 명시적 데모 경로로 유지한다. 운영 화면은 기존 문서/개정/객체 권위 데이터를 읽고 기존 권한 검증된 mutation을 사용한다. 새 화면을 별도 데이터베이스 제품으로 만들지 않는다.

연결 식별자는 project, document, revision, source file/hash, object ID를 기본으로 한다. IFC GlobalId도 원본·개정 범위와 함께 사용한다. 화면 객체를 전환할 때 PDF 좌표·축척을 검증하고 원본에 연결한다. 변환 불가능한 기존 데모 자료는 확인/다시 작성 대상으로 남기며 자동 실측 자료로 승격하지 않는다.

### 계산

PDF 실제 좌표·회전·페이지별 축척·단위를 분리한다. 원본 IFC 수량 속성, 기하 계산량, 사용자 보정량의 출처를 구분한다. 렌더링 경량 메시를 확정 물량의 자동 근거로 사용하지 않는다.

산출에는 버전 고정 규칙, 입력, 단위, 반올림, 원수량, 보정 사유, 최종수량을 보존한다. 단가는 회사 제공 자료의 버전·기준일·출처를 연결한다. 브라우저 미리보기와 서버 확정 결과를 구분한다. 지원하지 않는 체적·토공 계산을 단순 외곽 상자 체적으로 대체하지 않는다.

### 변경과 승인

객체/축척/규칙/단가 변경으로 영향받은 결과는 재검토 대상으로 표시한다. 기존 승인 수량·금액은 덮어쓰지 않는다. 도면 검토, 수량 검산, 금액 승인을 구분하되 동일 변경 건에서 관련 고정 버전을 보여준다. 승인 후 변경은 새 개정이다. 동시 승인/편집 충돌은 서버에서 검증한다.

설계·계약·발주·기성 수량은 별도 의미로 유지한다. 초기 화면에서 후속 업무 버튼을 만들더라도 실제 연결되지 않은 동작은 완료로 표시하지 않는다.

## 6. 3D 렌더링

기존 IFC 변환 worker, render manifest, 모델 viewer를 우선 재사용한다. 원본 해시·변환 버전·객체 매핑이 일치하는 파생 모델만 로드한다. 변환 대기/진행/완료/부분 지원/실패/재시도를 표시한다.

객체 선택, 속성, 단면, 숨김, 단독 보기, 2D/3D/물량 상호 선택을 제공한다. PDF↔IFC는 좌표 정합이나 검증된 수동 연결이 있어야 하며, 임의 화면 좌표로 일치한다고 표시하지 않는다.

대형 모델은 작업자 분리 처리, 분할 로딩, 가시 영역 처리, 경량 파생 모델, 캐시를 측정에 따라 적용한다. 원본 해석 엔진을 중복 도입하지 않는다. IFC4.3 파일을 읽는 것과 토목 형상·선형·위치를 완전 지원하는 것을 별도 검증한다.

## 7. 업무 안내와 AI

### 규칙 기반 안내를 먼저 제공

초기 규칙: 축척 없음, 필수 속성 없음, 수량 미연결, 단가 미연결, 변경 후 계산 오래됨, 검토 담당/결정 대기, 납품 첨부 누락.

안내 항목에는 rule ID/version, 범위 ID, 근거 revision, 객체/행 연결, 이유, 조치, 상태, 검사 시각을 포함한다. 같은 근거의 동일 문제는 중복 생성하지 않는다. 원본 변경 시 이전 안내는 오래된 것으로 표시하고 재검사한다. 서버 상태 변경 또는 명시적 재검사로 갱신하고 화면 렌더마다 모델/AI 검사를 실행하지 않는다.

규칙 검사는 도메인 서비스로 만들고 운영 상태에서 조회한다. UI는 결과 표시와 허용된 명령 요청만 담당한다. 규칙 검출과 AI 제안을 화면에서 구분한다.

### AI의 역할

첫 AI는 고정된 변경·수량·내역 근거의 요약과 다음 조치 설명으로 제한한다. 이후 회사 품목 후보 추천, 누락/중복 의심, 검토 요청서 초안을 순차 추가한다. 회사 자료 외 시장 단가를 추측해 채우지 않는다.

모든 제안은 evidence IDs, 검토 대상 revision, 제안 이유, 불확실성/자료 부족, 사용자 수락·기각 상태를 가진다. 수락 전 현재 개정을 재확인한다. AI는 금액을 확정하거나 승인하지 않는다. 권한 없는 자료 검색·다른 조직 데이터 참조·원문 속 지시 실행을 차단한다.

외부 AI 전송 정책, 보관/삭제, 지역/계약 조건은 도입 시 확인하고 조직별 허용을 받는다. 필요한 범위만 전송하고 호출 제한·캐시·사용량 계측을 둔다. 실패해도 기본 작업은 계속 가능해야 한다.

AI 평가: 전문가 정답셋으로 근거 정확성, 잘못된 위치 연결, 누락/오탐, 기각률, 검토 시간, 호출 비용을 측정한다. 안전 중요 판단은 전문가 확인 대상으로 남긴다.

## 9. DWG 왕복·토목 출시 게이트

사용자가 제공한 실제 DWG를 포함한 권한 확보 파일로 열기→허용된 편집→새 DWG 저장→독립 CAD 재열기를 검사한다. 원본 바이트는 유지하고 납품용 파일을 새 개정으로 생성한다.

지원 버전, 한글 폰트/SHX, xref, 블록/속성, 치수, 레이어, 선종류, layout/출력, 단위, 프록시·토목 전용 객체를 표로 검증한다. 변환 손실·미지원 객체를 사용자에게 알리고 치명적 손실이면 납품을 차단한다. SDK 비용·SaaS 배포 권한·배포 형태를 계약 확인 후 선정한다. DWG export 성공만으로 호환 완료라고 하지 않는다.

토목은 위치 스키마부터 추가한다. 건축의 동/층/실과 토목의 노선/공구/측점/구조물을 별도 위치 유형으로 관리한다. 기초 공종부터 실증하고 지표면·횡단면·절성토는 별도 알고리즘 검증 후 출시한다. 국가철도공단 협력 가능성을 계약·보안 승인·도입 확정으로 간주하지 않는다.

## 11. 검증·성과 기준

- 단위: 좌표/단위/반올림/개정 무효화/권한 계약의 실패 테스트를 먼저 작성.
- 통합: 실제 저장소에서 수량·내역·승인·원본 근거 일치 검증.
- 종단간: 실제 로그인 계정, 실제 PDF/IFC, 회사 단가, 작성자와 별도 승인자, 재로그인, CSV/XLSX 역검산.
- 실패: 원본 접근 실패, 변환 중단, 세션 만료, 업로드 재시도, 오프라인 outbox, 재접속 충돌, AI 중단.
- 보안: 조직 간 접근, Viewer 변경, 승인 개정 덮어쓰기, 외부 링크·AI 권한 누수 차단.
- 성능: 기존 10,000 객체 60fps/첫 사용 가능 2.5초/협업 p95 500ms를 목표로 유지하되 장비·네트워크·파일·캐시·첫 변환 비용을 별도 명시. 실제 측정 전 달성 주장 금지.
- 실무: 기존 방식과 유사 난이도 사례를 비교하여 최초 적산+변경+검토+납품 총시간을 측정. 교육·중복 입력 시간을 포함하고 추정 ROI를 실측 성과와 구분.

## 12. 실행 순서와 범위 관리

이 문서는 여러 서브시스템의 마스터 기획이다. 실행용 세부 계획은 G0/G1부터 분리하여 실패 테스트, 정확한 파일·인터페이스, 검증 명령, 독립 리뷰 단위로 작성한다. 기능 구현과 배포는 별도 실행 단계다.

진행 상태는 화면 시연/로컬 기능/실제 저장/다중 사용자 검증/출시 확인으로 구분한다. 버튼 이동이나 예시 테스트만 통과한 작업을 실무 완료로 집계하지 않는다.

첫 마일스톤 시나리오: 실제 PDF 등록 → 축척 보정 → 바닥 영역 생성 → 면적 산출 → 회사 단가 연결 → 금액 표시 → 저장 → 다른 세션으로 재로그인 → 동일 근거와 결과 복원. G1 완료 전에 새로운 전사 관리 화면을 추가하지 않는다.

일정은 G0에서 현재 운영 상태와 재사용 가능성을 확인한 뒤 팀 가용량 기준으로 산정한다. 측정 없이 출시일·DWG 완전 호환·AI 정확도를 약속하지 않는다.
