# Lukas QTO 프로젝트 업무 화면 실무 검증안

기준일: 2026-08-15  
대상: 적산·BIM 실무자 3명  
검증 화면: 프로젝트 개요, 파일, 물량, 검토, 자재

## 검증 목적

기능 설명을 먼저 듣지 않은 실무자가 모바일 또는 노트북에서 아래 세 가지 핵심 업무를
스스로 끝낼 수 있는지 확인한다. 이번 검증은 계산 정확도가 아니라 업무 화면의 발견성,
용어, 이동 경로를 확인한다.

## 참가자 구성

| 참가자 | 권장 경력 | 주 사용 기기 | 확인할 관점 |
|---|---:|---|---|
| A | 적산 3년 이상 | Windows 노트북 | 파일과 물량 결과를 빠르게 찾는가 |
| B | BIM/Revit 3년 이상 | Windows 노트북 | IFC·추출 결과 등록 흐름을 이해하는가 |
| C | 현장 또는 검토 책임자 | 모바일 | 승인 대기와 결정 기록을 이해하는가 |

세 참가자에게 같은 설명을 제공한다: “이 프로젝트에서 지금 해야 할 업무를 찾아
완료해 주세요.” 메뉴 위치나 정답은 알려주지 않는다.

## 과제 1 — IFC 추가

시작점: 프로젝트 개요  
완료 조건: `파일` 화면에서 IFC를 선택하고 등록 시도를 완료한다. 운영 자료 대신 제공된
테스트 IFC를 사용한다.

관찰 항목:

- `지금 할 일` 또는 하단 `파일`을 첫 행동으로 선택했는가
- 파일 종류에서 IFC를 찾았는가
- 등록 완료 또는 명확한 오류 안내까지 도달했는가
- 기술 용어 때문에 멈춘 지점이 있는가

## 과제 2 — 산출 결과 확인

시작점: 프로젝트 개요  
완료 조건: `물량` 화면에서 가장 최근 산출 결과 또는 검산 결과의 상태와 상세 진입점을
찾고, 본인이 확인해야 할 결과인지 말할 수 있다.

관찰 항목:

- `물량` 메뉴를 찾는 데 걸린 시간
- 산출 결과와 검산 결과를 구분하는가
- `결정 대기`, `승인`, `기각`, `보류`를 올바르게 해석하는가
- 파일 확인번호 같은 기술 근거가 주 정보보다 먼저 방해하지 않는가

## 과제 3 — 승인 대기 처리

시작점: 프로젝트 개요  
완료 조건: 승인 대기 배지를 보고 `검토` 화면으로 이동하여 지정된 테스트 항목에
`승인` 또는 `보류`와 메모를 기록한다.

관찰 항목:

- 승인 대기 건수를 발견했는가
- `검토` 화면을 선택했는가
- 자동 점검과 사람의 최종 결정을 구분하는가
- 결정 저장 후 상태가 바뀌었음을 인지하는가

## 통과 기준

- 전체 9회 과제 중 8회 이상 성공(성공률 90% 이상)
- 첫 행동까지 걸린 시간 중앙값 10초 이하
- 각 핵심 화면까지 두 번 이하의 메뉴 선택으로 도달
- 치명적 용어 오해 0건: 산출과 승인, 자동 점검과 사람 결정을 반대로 이해하지 않음
- 모바일에서 가로 스크롤 없이 과제 완료

기준을 충족하지 못하면 실패 과제의 첫 이탈 지점만 우선 수정한다. 참가자가 요청하지
않은 기능을 추가하거나 메뉴 수를 늘려 해결하지 않는다.

## 종료 질문

1. 첫 화면에서 무엇을 먼저 해야 한다고 느꼈나요?
2. `파일`, `물량`, `검토`, `자재` 중 의미가 모호한 단어가 있었나요?
3. 승인 버튼을 누르기 전에 어떤 근거가 더 필요했나요?
4. 현장에서 매일 확인한다면 첫 화면에 남겨야 할 숫자는 무엇인가요?
5. 사용하지 않을 메뉴는 무엇인가요?

## 판정 경계

이 문서는 실제 실무자 검증 절차다. 코드·자동 테스트가 통과해도 UX-P3 완료로 처리하지
않는다. 세 명의 측정표와 인터뷰 메모가 채워지고 통과 기준을 만족해야 완료다.
